DeepEP 与 DeepGEMM 的执行过程

一个 MoE 层在多卡上的执行顺序：DeepEP 的 notify 与 dispatch 把 token 送到专家所在的卡，DeepGEMM 的 grouped GEMM 在每张卡上计算专家，combine 把结果送回并求和，两个 micro-batch 让通信与计算重叠。简图、表格和时间线上的数字都由 src/sim 的模拟器算出：notify、dispatchPlan、expandedLayout、combinePlan 按 DeepEP V2.5 的源码给出每份数据的去向和字节数，schedule 与 pipeline 按 DeepGEMM 的 SM90 FP8 内核给出 tile 顺序和一个 SM 上的流水线，overlapSchedule 排出两个 micro-batch 的时间线。

模型的简化：DeepEP 的模拟只给出去向和字节数，不模拟 channel 的时序，所以图中把 RDMA 和 NVLink 两跳分成两步画；DeepGEMM 的流水线只模拟一个 CTA，TMA 发出拷贝不占时间，各阶段的时长是假设值。每一步在文字里说明用到的假设。
