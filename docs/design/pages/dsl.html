vizflow 页面描述文件 第二版

由标准模块组成的页面（例如几层 Transformer）可以不写 JavaScript，只写 YAML 页面描述文件。描述文件的结构对应 PyTorch 的写法：一个模块对应一个真实的类，init 对应 __init__，forward 对应 forward，参数路径与 state_dict 的键相同。dsl 入口把文件编译成计算图、步骤、面板、讲解段落和模块记录，<vizflow-page src="x.yaml"> 再把这些交给已有的挂载流程。编译结果就是普通的 Graph、StepsSpec 与 PanelItem[]，描述文件写不出的需求仍然用 JavaScript 接口。

完整示例：examples/qwen3/qwen3-dsl.yaml 与它引用的 decoder.yaml、attention.yaml、rope.md。测试 test/dsl/qwen3.test.ts 把 transformers 的 Qwen3ForCausalLM 的参数写进这一页，在 float64 下比较 logits、损失和每个参数的梯度；fixture 由 uv run scripts/gen_qwen3_fixture.py 生成。其他模型页面还使用第一版的写法，迁移之前不能编译。

每个 forward 结果都要被某一步讲解展示，否则编译报错。图上的每个节点因此都对应讲解里的一步，内置模块的每一步对应 HF 实现里的一行代码。

文件里有什么

文件分两种。页面文件描述一整页，用 model 指定根模块；模块文件描述一个可以复用的模块，用 module 给出模块名。页面只在 modules 里用到的模块也可以直接写在页面文件里。

页面文件的键作用
title页面标题，元素把它画在场景上方。
camera相机选项，原样传给 mountScene。
import模块名到模块文件的映射。vizflow/nn/名字 是包内的模块，./x.yaml 相对于当前文件。
preamble一个只写 \newcommand 的文件，定义模板和 LaTeX 里可用的宏。
model根模块的名字，在 modules 或 import 里查找。
config本页的配置值。根模块的 args 按同名从这里取值；seed、tokenizer、real 只属于页面。
data根模块的输入值，按名字对应根模块的 inputs。
modules只在本页使用的模块，键是模块名。
panels页面右侧的面板，见「面板」。
sections场景下方的讲解段落，见「讲解段落」。
模块的键作用
module模块名，只在模块文件里写。
import这个模块用到的其他模块。内置的 Linear、Embedding 不需要导入。
args构造参数，对应 __init__ 的参数。
inputs、outputs接口，键是名字，值是 { type, shape, dtype }。
init子模块、weights 和 buffers。
forward计算，一个 名字: 表达式 的列表。
tex数学名称，键是名字或相对路径。
formula模块整体的公式，用 \step{}{} 关联步骤。
fold模块折叠成一步时的讲解。
steps讲解步骤，按顺序排列。
unshown不需要单独展示的 forward 结果。

模块只能读取自己声明的参数、输入，以及 init 和 forward 定义的名字。要用外面的值，通过 args 或输入传进来。同一作用域里一个名字只能定义一次。

字符串写在哪里、怎么读

字符串按所在的位置分三类。这样同一个名字在表达式里直接是引用，在模板里只有包在 \viz{} 或 {{ }} 里才是引用，不会和正文文字混淆。

类别位置读法
表达式args 的取值、count、shape、dtype、forward、show、notes.at、面板和讲解段落里的张量引用按 Python 的表达式读，名字就是引用。
模板label、title、subtitle、text、append、brace、note、hint普通文字；$...$ 与 $$...$$ 是 LaTeX，{{ }} 插入表达式的值。
LaTeXtex 的值、formula整个值就是 LaTeX，不加 $。

表达式支持 + - * / // ** @、一元负号、函数调用和关键字参数、方法调用、成员访问、下标与切片、列表、字符串字面量和 True、False、None。下标从 0 开始，可以是负数，和 Python 一致。dtype 名（bf16、fp32 等）和导入的模块名是表达式里可用的名字。含 [、: 等字符的表达式在 YAML 里加引号。

所有表达式由同一个求值器按 Python 的语义计算，只是结果的去处不同：forward 里的运算建成计算图的节点；buffer 的 value、data 的 expr 在编译时算出值；小图的表达式记录成一段库运算的程序，页面数值变化后重新执行。args、shape、count 等只算数和维度。同一段表达式在这几处的含义相同，例如：

  • 列表就是列表，不自动拼成张量：cat([a, b], dim=-1) 的第一个参数是两个张量的列表；x.permute([1, 0]) 与 x.permute(1, 0)、x.view([T, d]) 与 x.view(T, d) 相同。
  • 数在左边的运算按 Python 的反射运算计算：1 - x 是 rsub，1 / x 是 reciprocal 乘 1，rope_theta ** e 是底数为数的 pow。
  • 下标里的 None 加一个长度为 1 的维度，... 补齐其余维度：x[:, None]、position_ids[..., None]。整数下标是 select，切片是 narrow，覆盖整个维度的切片（x[1, :] 里的 :）不产生节点。
  • 转换到当前 dtype 的 .float()、.to(x.dtype) 不产生节点，与 torch 返回原张量一致。
  • 名字先在当前作用域里找：forward 里定义的 cos 会遮住同名的运算 cos，这时用方法写法 x.cos()。

模块的参数与输入

args

args 声明构造参数，类型是 dim（正整数）、int、float、bool、dtype 或 module。没有额外选项时写成 d_head: dim，有默认值时写成 { type: float, default: 1e-6 }。默认值是表达式，可以引用前面的参数。

使用处的 args 可以写成字典或列表。列表里的裸名字表示用调用者同名的值传入，单键字典表示指定值。名字不是被调模块的参数、参数没给也没有默认值、同一个参数给了两次，都在编译时报错。

init:
  self_attn:
    use: Qwen3Attention
    args: [d_model, d_head, num_heads, num_kv_heads]
  mlp:
    use: GLU
    args: [d_model, d_ff, { act: SiLU }]

inputs、outputs 与形状绑定

输入输出写成 { type: tensor, shape, dtype }，页面根模块的 token 列表写成 { type: list, dtype: str }。shape 和 dtype 里不是参数的名字在调用时从实际输入绑定，已经绑定或声明过的名字只做检查；outputs 里的名字必须已经绑定，用来检查结果。从输入绑定的名字在模块里至少还要再出现一次，否则编译报错 'dd' takes its value from this input but is used nowhere else in M; if it should be an arg, check the spelling：只出现一次的名字多半是参数名拼错了，按绑定处理会让形状检查失效。'...' 可以在 shape 里出现一次，对上任意个维度，例如 RMSNorm 的 ['...', hidden_size] 只要求最后一维。

  • 序列长度 T 是数据的维度，不作为参数传入，同一个实例可以用不同的 T 调用。
  • init 只能使用 args 中的名字。这和 HF 的 __init__ 一致：建参数需要的维度都由调用者传入。
  • 依赖输入形状的常量在 forward 里计算，例如 position_ids: arange(T)、M: causal_mask(T, dtype=e.dtype)，不写成 buffer。
  • 根模块输入的维度（例如 T）是页面的维度，显存与计算量面板的 $T$ 滑块改变它。由它算出的尺寸（arange(T) 的长度、T // chunk 这样的循环次数）记录成算式，滑块改变时重新计算；它们不登记成新的维度名，所以两个碰巧相等的尺寸不会被当成同一个维度。

dtype

参数的 dtype 由页面 config.dtype 统一设定，相当于 model.to(torch.bfloat16)；不写时是 fp32，写了 dtype 以外的值时报错 config.dtype: dtype must be one of ...。根模块声明了 dtype 参数（dtype: dtype）时，config.dtype 同时传给这个参数，模块可以把它继续传给子模块；没有声明时它只设定参数的 dtype。模块的 args 不另外声明参数 dtype，init 也不读它。输入的 dtype 从实际输入绑定，用来检查输出。运算的结果按 torch 的类型提升推导，matmul 两侧的 dtype 必须相同，否则编译报错 expected inputs of the same dtype；有意的转换在 forward 里写出来，例如 z.float()、xh.to(x.dtype)。这样页面上的每个类型转换都是 HF 代码里的一次转换。

init：子模块、权重与 buffer

init:
  q_proj:
    use: Linear
    args: { in_features: d_model, out_features: num_heads * d_head, bias: False }
  layers:
    use: list[Qwen3DecoderLayer]
    count: num_layers
    args: [d_model, d_head, d_ff, num_heads, num_kv_heads]
  log_softmax: LogSoftmax
  weights:
    weight: { shape: [hidden_size], init: ones }
  buffers:
    inv_freq:
      type: tensor
      shape: [d_head // 2]
      dtype: fp32
      value: 1.0 / rope_theta ** (arange(0, d_head, 2, dtype=fp32) / d_head)
  • 子模块写 { use, args }，没有参数时可以只写模块名。use: list[M] 配合 count 建参数独立的层列表，第 $i$ 层的路径是 layers[i]。
  • weights 写成 { shape, init, present }。present 是一个 bool 参数的名字，参数为假时这个权重不创建，forward 里它的名字是 None，例如 Linear 的 bias: { shape: [out_features], present: bias }。这对应 HF 里 self.bias = None 的写法，参数路径和 state_dict 一致。init 是 ones、zeros、normal 或 uniform，默认 uniform。uniform 取 $U(-1,1)$，normal 取标准正态，都保留两位小数，随机数的种子是页面的 config.seed，默认 0。
  • buffers 的 value 是在编译时求值的表达式，可以用数、参数、库里的运算（包括 arange）、四则运算与广播、下标和类型转换，不能读张量；结果的形状和 dtype 必须等于声明的 shape 和 dtype，不做隐式转换。和 HF 一样，需要浮点的整数序列直接写 arange(..., dtype=fp32)。
  • 内置的 Linear 和 Embedding 使用 PyTorch 的参数名：Linear 是 in_features、out_features、bias，Embedding 是 num_embeddings、embedding_dim；两者的权重都叫 weight，形状与 PyTorch 相同。bias 默认是 True，与 nn.Linear 的签名一致，这样照抄 HF 的构造参数就得到同样的参数集合；HF 写了 bias=False 的地方（Qwen3 的投影和 lm_head）页面也写 bias: False。Linear 的 forward 是 linear(x, weight, bias)，与 F.linear 相同。

参数的路径沿 init 树拼接，与 PyTorch state_dict 的键一致，例如 model.layers[0].self_attn.q_proj.weight、lm_head.weight。graph 上参数的节点名就是这个路径，测试据此把 transformers 的参数写进页面。

forward：计算

forward:
  - q_linear: q_proj(x)
  - q: q_linear.view(T, num_heads, d_head)
  - qt: q_norm(q).transpose(0, 1)
  - rotated: apply_rotary_pos_emb(q=qt, k=kt, cos=cos, sin=sin)
  - qr: rotated.q_embed
  - M: causal_mask(T, dtype=e.dtype)
  - h_last: layers(e, mask=M, cos=cos, sin=sin)
  - zf: z.float()
  • 每一项只有一个结果名。表达式里的函数和方法是 autograd 的运算，例如 x @ weight.T、x ** 2、rsqrt(mse)、sq.mean(-1, keepdim=True)、cat([nq2, q1], dim=-1)、repeat_kv(k, n_rep)、q[..., : d_head // 2]。类型转换写成 x.float()、x.double()、x.half()、x.bfloat16() 或 x.to(dtype)。
  • arange(start, end, step, dtype=...) 与 torch.arange 相同，默认 int64，步长为 0 时报错。causal_mask(T, dtype=...) 建一个 $T\times T$ 的常量，$s>t$ 的格子是 torch.finfo(dtype).min，其余是 0，与 HF create_causal_mask 一致。两者都是注册的运算，没有输入，在步骤里占自己的一层；滑动窗口、分块注意力的 mask 也按这种方式加成运算，不在页面里拼。
  • linear(x, weight, bias) 是组合运算，展开成 x @ weight.T，bias 不是 None 时再加上它。
  • 调用子模块写 实例(位置参数, 名字=值)。单输出的模块返回张量；多输出的模块返回具名结果，用 result.名字 取出。
  • 同一个实例可以调用多次，各次共用参数，每次调用的中间结果独立：第 $k$ 次调用（$k\ge2$）的节点路径前缀是 实例路径#k。
  • 调用层列表时依次执行各层，第一个位置参数逐层串联，其余关键字参数原样传给每一层，返回最后一层的输出。
  • 子模块调用是赋值的整个表达式时，模块的输出用调用处的名字命名：n1: input_layernorm(x) 的输出节点名是 layers[0].n1，tex 也取调用处的。多输出的模块按 qr: rotated.q_embed 这样的赋值命名各个输出。
  • 表达式里间接产生的节点（例如 x.float().exp() 里的类型转换）的名字是结果名加 /序号，例如 ex/1，序号按路径计数，模块输出用了调用处的名字时也不会重名。这些节点随结果一起展示，其中的布局运算和类型转换不单独画，画在最近的已画出的源节点上，例如 position_ids[..., None].float() 画在 position_ids 上。

页面：config、data 与 real

model: Qwen3ForCausalLM
config:
  V: 5
  d_model: 4
  num_layers: 2
  rope_theta: 10
  dtype: bf16
  seed: 20261010
  tokenizer:
    vocab: [on, mat, the, sat, cat]
  real:
    qwen3-8b: { name: Qwen3-8B, T: 8192, V: 151936, d_model: 4096, num_layers: 36 }
data:
  tokens: [the, cat, sat, on]
  ids: { expr: 'tokens_to_ids(tokens[:-1])' }
  y: { expr: 'tokens_to_ids(tokens[1:])' }
  • config 和 data 按 YAML 字面值读取，需要计算时写 { expr: ... }。数据表达式可以用名字、下标、切片和 tokens_to_ids。config 里的名字必须是根模块的参数。
  • data 里的 token 列表编译成一个隐藏的标签节点；由 tokens_to_ids 得到的数据编译成标签节点，带上词表。序列面板替换 token 后，这些数据按原来的表达式重新计算。
  • real 是字典，键是规格名，值是 { name, 维度名: 真实值 }，T 是真实规模下的序列长度。第一个规格用于卡片上的真实形状和显存与计算量面板；real 只描述真实规模，不改变示例计算。
  • 根模块的模板可以读 real：{{ real['qwen3-8b'].d_model }} 取规格 qwen3-8b 的 d_model，结果是数或字符串，可以参与四则运算。real 只在根模块的作用域里有定义，子模块要用真实规模时，由根模块的步骤写出。

tex 怎么来

节点的 tex 按以下顺序决定，先找到的生效：

  1. 外层模块 tex 里按相对路径写的名字，例如 decoder 的 mlp.a、attention 的 q_norm.ms，最外层的模块优先。
  2. 调用处的名字的 tex：n1: input_layernorm(x) 的输出用 decoder 里 n1 的 tex。
  3. 模块自己的 tex。
  4. 由名字推出：q 是 $\mathbf{q}$，x0 是 $\mathbf{x}_{0}$，W_q 是 $W_{q}$。

\viz{名字} 在 tex、模板和公式里引用一个张量的 tex，名字按当前模块的作用域查找，只做替换，不调整排版；追加下标或上标时写 {\viz{x}}_t、{\viz{x}}^{\top}。层列表里的模块给自己的 tex 加上标 ^{[i]}，序号从 0 开始，与 layers[i] 一致（第一层是 $^{[0]}$），已有上标时合并成 ^{q,[0]}；含 \viz 的 tex 不加，因为被引用的 tex 已经带了层号。

讲解步骤

steps 按顺序列出讲解，每一步是 { id, show, ... }。步骤的 id 就是要展示的名字时 show 可以省略。

show含义
张量或张量列表一步，展示这些张量。
模块实例插入这次调用的讲解：模块有 steps 时是一个带大括号的模块，没有时是一步，展示它的参数和结果。
几个模块实例一组，组里每个实例一个子模块，title 等写在组上。
{ producer_of: a }同一实例调用多次时，指定产生 a 的那次调用。
{ all: true }总览，展示全图，只能写 label、title、text、notes、backward。
{ inputs: true, parameters: true }输入步骤，展示根模块的输入和全部参数。

步骤的其他键：

  • label、title、text 是这一步的讲解，append 在正文后追加；backward: { label, title, text, append } 改写对应的反向步骤。
  • segment 是步骤条上的分段名，默认取最外层模块的标题。subtitle、fold、folded、formula、inline、steps 只用于展示模块调用的步骤。
  • steps: { 路径: 补丁 } 按步骤 id 改写子模块的步骤，路径用点连接，例如 act_fn.sigmoid.neg；组里的成员可以不写组名。补丁不能改 show。写在模块步骤上的 text、append、notes 放到这个模块的第一步。
  • fold 改写模块折叠后那一步的讲解；模块顶层的 fold 是默认值。
  • inline: true 让模块调用不成为单独的模块，步骤算作外层模块的；配合 brace: { title, subtitle } 在场景里画一个大括号，模块的 formula 显示在大括号上。不是 inline 的模块调用不能写 brace，它已经有自己的大括号。
  • beside: 前一步的 id 把这一步并到那一步里：两个张量步骤合成一步；两个模块调用的步骤逐个合成，步数必须相同，例如 q_norm 和 k_norm。
  • notes 在场景里加注释：at 是张量、张量的一个元素（例如 'mask[0, 2]'）或模块实例，text 是模板，side 是 left、right、above、below 之一。

循环步骤

- id: layers
  loop: layer = layers[i]
  defaults:
    title: Qwen3DecoderLayer
    subtitle: 第 {{ i }} 层
  rules:
    - at: -1
      subtitle: 最后一层

loop 对列表的每一项生成一步，layer 是当前项，i 从 0 开始，可以引用 layers[i + 1]。先合并 defaults 与 at 匹配的规则（at 可以是负数），再求值模板，越界引用报错。show 默认是循环变量。

每个结果都要展示

编译器检查每个被展示的模块调用：forward 的每个结果要么出现在某一步的 show 里，要么是某个被展示的模块调用的输入，要么由一个被展示的子模块调用产生，要么是布局运算（view、reshape、transpose、permute、unsqueeze、contiguous）或类型转换作用在已展示的张量上的结果，这类结果画在输入上。都不满足时报错，指向 forward 里那一项。确实不需要单独展示的结果写进模块的 unshown。没有被任何一步展示的参数和 buffer 放进第一个展示其使用者的步骤。

公式与插值

formula 是模块的公式，\step{步骤 id}{公式片段} 标出由哪一步算出的部分：前向走到这一步之前这部分不显示，走到这一步时用正色标出；反向时整条公式显示，当前步骤对应的部分用负色标出。id 的写法与补丁相同，子实例.* 表示子实例的全部步骤，几个 id 用逗号隔开。编译后 \step 变成 \htmlData{vf-step=s序号}，对应步骤的 marks。

preamble 文件里的 \newcommand{\名字}[参数个数]{定义} 在模板、tex 和公式里展开，展开嵌套超过 32 层时报错。

{{ 表达式 | 格式 }} 插入值。标量不写格式时直接显示：整数写成十进制数字，例如 151936；其他数的指数绝对值达到 4 时写成科学记数法，例如 $1.5\times 10^{-5}$。非标量必须写格式，否则报错。

格式结果
matrix:位数整个张量写成 pmatrix；超过 2 维时按最后两维切块，每块下标标出前面各维（从 0 开始）。块横向排列，一行的列数合计不超过 8，超过时换行，使宽的张量也能放进讲解卡片。
join: "分隔符"一维张量或 token 列表的各项用分隔符连接，token 列表显示 token 文字。
lines:shade=T内置小图。这时表达式可以计算新的值：arange、库里的运算、四则运算与广播、下标、切片和 [:, None]，计算编译成一段运算程序，只用于显示，不进计算图，页面数值变化后重新执行。参数写成 名字=表达式，在编译时算成数。小图的名字和参数见 vizflow 设计的「内置小图」。

插值编译成运行时模板 {{节点名[下标]:位数}}，数值随页面更新；x.grad 取梯度。

面板

写法说明
cost显存与计算量面板。
loss: { parts?, hint? }损失曲线，parts 是每个位置的损失。
sequence: true, tokens, input, label, labels?, sgd?, random?, reset?序列面板。tokens 是 data 里的 token 列表，input、label 是根模块的输入；sgd: { params: all 或参数列表, lr, label? }。
code一段代码。
attention, ids注意力权重面板。
matrices, highlight?, rows?矩阵面板。

除 cost 和 loss 外，面板都可以写 title 和 note（模板）。张量引用按根模块的作用域求值，可以写路径，例如 layers[0].self_attn.qn。

讲解段落

sections 的每一项是 { title?, src, rope? }，编译成 SectionItem，由 ui 的 mountSections 画出。

  • src 是 Markdown 文件，相对于页面文件解析，在运行时读取。冒号块的写法见 docs/guide.md 第 5.3 节，出错时报 Markdown 文件的行号。
  • 块里的 buttons 是 { label, go } 的列表，rope_compare 是 { scores, weights, ids }，scores 和 weights 是形状为 (heads, T, T) 的张量，例如 Qwen3 注意力里的 Ss 和 P。
  • rope: { q, k, rows?, head?, theta, d_head, positions? } 给 RoPE 组件提供数据：q、k 是张量，rows 是 q 和 k 各取第几行，从 0 开始，可以是负数，默认 [-1, 0]；head 从 0 开始，默认 0；d_head 必须是偶数；positions 是曲线画到的位置数，默认 24，至少 2。

内置模块

Qwen3 用到的内置模块按新写法实现，每一步对应 HF 实现的一行代码；其余包内模块还没有迁移。

模块args输入 → 输出步骤 id
Linear（内置）in_features、out_features、bias（默认 True）x → y = linear(x, weight, bias)没有步骤，展示时是一步
Embedding（内置）num_embeddings、embedding_dimx（int64）→ out没有步骤
vizflow/nn/rmsnormhidden_size、eps（默认 1e-6）x: [..., hidden_size] → out；中间结果 xf、sq、ms、mse、r、xh、xcfloat、square、mean、eps、rms、normalize、cast、scale
vizflow/nn/glud_model、d_ff、act（module，默认 SiLU）x → down；子模块 gate_proj、up_proj、down_proj、act_fn，中间结果 gate、a、up、mgate_proj、act_fn、up_proj、gate、down
vizflow/nn/silu无x → out；子模块 sigmoidsigmoid、mul
vizflow/nn/sigmoid无x → outneg、exp、add、recip

  • gqa 按 HF 的批量写法计算：repeat_kv 后所有 head 一起 matmul，softmax 按定义拆成 exp、求和、相除，在 fp32 里算完再转回 q 的 dtype，最后 transpose(0, 1).contiguous() 回到 (T, H, d_head)。

  • rope 没有 HF 里 cos、sin 的 unsqueeze：这里没有 batch 维，(T, d_head) 的表直接和 (H, T, d_head) 广播。

编译接口

interface CompileOptions { base?: string; read?: (url: string) => Promise<string>; }
interface CompiledPage {
  graph: Graph;
  steps: StepsSpec;
  tree: LayoutTree;
  modules: PageModule[];
  panels: PanelItem[];
  sections: SectionItem[];
  nodes: Map<string, Node>;
  sequence?: PageSequence;
  page: { title: string; camera?: CameraOptions };
}
interface PageSequence { tokens: string[]; length: number; get(): number[]; set(ids: number[]): void; }
function compilePage(spec: PageFile, options?: CompileOptions): Promise<CompiledPage>;
function loadPage(url: string, options?: CompileOptions): Promise<CompiledPage>;
function parseYaml(text: string, file: string): unknown;
  • base 是相对引用的基准地址，也是错误信息里的文件名。loadPage 读取 url，以它为基准地址编译。两者都用同一个读取函数读模块文件、preamble 和讲解段落。
  • nodes 按路径查节点：根模块的名字没有前缀，子模块里的名字是 实例路径.名字，参数是 state_dict 的键。
  • steps.backward 是 'reverse'，steps.modules 与 modules 是同一组模块记录。模块记录的 id 是调用的路径前缀，例如 model.layers[0].self_attn。
  • 错误信息的格式是 文件:行:列 路径: 说明，例如 attention.yaml:44:7 forward[3].qt: name 'qnn' is not defined in 'layers[0].self_attn' (Qwen3Attention)。
  • dsl 入口另外导出 PageFile、ModuleFile 等描述文件的类型和 DslError。
