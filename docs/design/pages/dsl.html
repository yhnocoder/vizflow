vizflow 页面描述文件 第一版

由标准模块组成的页面（例如一层 Transformer）可以不写 JavaScript，只写一份 YAML 页面描述文件。dsl 入口把它编译成计算图、步骤、面板、讲解段落、模块记录和一棵布局树，<vizflow-page src="x.yaml"> 再把这些交给已有的挂载流程。页面描述文件只是 JavaScript 接口之上的一层：编译结果就是普通的 Graph、StepsSpec 与 PanelItem[]，遇到描述文件写不出的需求时，页面改用 JavaScript 接口。JavaScript 调用方也可以直接把同样结构的对象传给 compilePage，YAML 只是这份结构的一种写法。

完整示例：examples/qwen3-dsl.yaml 与它引用的 examples/qwen3/attention.yaml。它和 JavaScript 写的 examples/qwen3-structure.html 是同一页，测试比较两页的损失和每个权重的梯度。

文件里写什么

文件分两种。页面文件描述一整页，模块文件描述一个可以复用的模块，例如 RMSNorm。页面本身是根模块，body、steps、backward 的规则与模块相同。

module: RMSNorm
subtitle: RMSNorm
params:
  eps:  { type: float, default: 1e-6 }
  name: { type: text, default_key: true }
inputs:
  x: { shape: [..., n] }
outputs: [out]
weights:
  weight: { shape: [n], init: ones, tex: '\boldsymbol{\gamma}' }
fold:
  label: '$\of{out}$'
  title: \of{name}（已折叠）
  backward:
    title: 穿过 \of{name}（已折叠）
body:
  - sq: { op: x ** 2, tex: '\of{x}^{2}', dtype: fp32 }
  - ms: { op: 'mean(sq, -1, keepdim=true)', tex: '\mathrm{ms}' }
  - r:  { op: 'rsqrt(ms, eps=eps)', tex: r }
  - xh: { op: x * r, tex: '\hat{\of{x}}' }
  - out: { op: xh * weight, dtype: x }
steps:
  - id: rms
    show: [ms, r]
    label: '$\of{ms},\ \of{r}$'
    title: 均方根的倒数
    text: |
      每一行对平方取平均得到 $\mathrm{ms}$，加上 $\epsilon=\of{eps}$ 再取平方根的倒数。
      $$\of{r} = {{ r | matrix:3 }}$$
    backward:
      label: '$\partial\of{ms},\ \partial\of{sq}$'
      title: 传到 ms 和平方
字段出现在内容
module模块模块名
title、lede、hint、camera页面页面标题、导语、场景提示和相机选项。元素把标题和导语画在场景上方，hint 与 camera 原样传给 mountScene。
import两种本文件用到的模块，{ 名字: 引用 }
modules页面只在本页使用的模块，{ 名字: 模块内容 }，内容与模块文件相同，不写 module
subtitle两种大括号上的副标题
formula模块模块的公式，用 \step{id}{...} 标出各部分由哪一步算出，见「模块公式」
params两种参数声明，{ 名字: { type, default?, default_key?, values? } }
dims、real页面根作用域的维度和传给 graph({ real }) 的真实尺寸
dtype页面传给 graph({ dtype }) 的默认 dtype，例如 bf16，不写时是 fp32
vocab页面token 名，传给 graph({ vocab })

outputs模块输出节点的名字列表
weights两种{ 名字: { shape, init?, tex?, dtype? } }，建 param 节点
buffers两种{ 名字: { value, shape?, tex?, dtype? } }，value 是只由参数和维度算出的表达式，建 buffer 节点；shape 把数值按这个形状重排，元素个数必须相同，否则报错 buffer 'x' has N values, which do not fit the shape (...)
body两种节点、子模块实例、group 与 for 的列表，按顺序建图
steps两种本模块的前向步骤：id、show、active?、label?、title?、text?、segment?、backward?、notes?。backward: { label?, title?, text? } 是这一步对应的反向步骤的默认文字，segment 覆盖步骤条上的分段名，notes 见「步骤上的注释」
backward两种按节点名给对应反向步骤的 title、label、text
fold模块模块折叠后那一步的默认文字 { label?, title?, text?, backward?: { label?, title?, text? } }，实例的 fold 逐个字段覆盖它
overview页面总览步骤的 title、text、label、notes；backward: { label?, title?, text? } 在反向的最后加一个反向总览步骤
leaves页面{ title, label?, text? }，在总览之后加一个输入步骤，显示全部叶子（input、label、权重、权重的转置和 buffer），缺 title 时报错 leaves needs a title，见「步骤怎么排」
sequence页面{ tokens, input, label }，用一条 token 序列同时建输入和右移一位的标签，见「序列输入」
init、values页面权重初值的随机种子 { seed }，以及按路径给定的固定数值
panels页面面板列表，见「面板与大括号」
sections页面场景下方的讲解段落，见「讲解段落」
layout页面原样放进编译结果的 layout，目前没有模块读取它

body 的每一项是只有一个键的映射，或者一个 for：

  • name: expr 建一个节点，等价于 name: { op: expr }；{ op, tex, dtype } 同时给出 tex 和 dtype。dtype 写 dtype 名（fp32），或者写一个张量的名字，表示取那个张量的 dtype，对应 torch 里的 .to(x.dtype)。示例里 RMSNorm 把平方写成 fp32，之后的 ms、$r$、$\hat{x}$ 按类型提升都是 fp32，输出写 dtype: x 转回输入的 dtype，所以输入是 bf16 或 fp32 时模块都不用改。名字既不是 dtype、也不是张量时报错。
  • name: { use, params?, inputs, outputs?, weights?, suffix?, tex?, steps?, beside?, inline?, brace?, formula?, title?, subtitle?, fixed?, folded?, split?, fold? } 是子模块实例。inputs 必须恰好给出模块的每个输入，值是表达式；outputs 把模块的输出绑定到父作用域的名字，可以只绑定一部分；weights 把模块的权重绑定到父作用域已有的权重；tex 按模块内的名字覆盖 tex；steps 是步骤补丁。其余字段决定这个实例作为一个模块怎么显示和折叠，见下面的「模块记录」。
  • name: { body, steps?, beside?, formula?, title?, subtitle?, fixed?, folded?, split?, fold? } 是 group，即匿名的内联模块。它的名字直接属于外层作用域，用来画大括号、把步骤分组和整体折叠。
  • { for: h, in: '1..H', name?, brace?, beside?, sequential?, body } 把 body 按 h 从 1 到 H 展开。name 只给 beside 引用，和 body 里的名字一样必须唯一，在嵌套的 for 里要带外层的循环下标。sequential（默认 false）为 true 时，各次迭代按顺序往上叠在主列上，每次迭代的步骤单独成步，用于后一次迭代依赖前一次结果的递推，例如 gated delta rule 按位置更新的状态 $S_t$；默认的迭代互相独立，并排画出、步骤合并，例如 GQA 的各个 head。

模块记录。每个不是 inline 的实例、每个 group 和写了 brace 的 for 迭代对应一个模块记录，编译结果的 modules 列出其中含运算节点的那些（PageModule，见vizflow 设计的「折叠与反向步骤」）。记录的字段来自使用处：

  • title 覆盖大括号的标题，默认是实例名或 group 名（for 里去掉循环下标），可以写 \of{...} 和行内公式。subtitle 默认取模块文件的 subtitle。
  • folded: true 让模块一开始就是折叠的，读者可以展开。fixed: true 表示占位模块：它总是折叠，不能展开，盒子里的计算只用来示意（例如 Qwen3 页的「第 1 到 $N-1$ 层」用 identity 代替）。
  • split: true 让子模块各自成为步骤条上的一段，例如 decoder 层的 input_layernorm、self_attn、MLP 各占一段；不写时整个模块是一段，子模块是段里的小标题。
  • fold 是折叠后那一步的文字，字段与模块文件顶层的 fold 相同，逐个字段覆盖模块文件给的默认值。
  • inline: true 的实例不建模块记录，也不生成子布局树：节点和步骤直接算作外层模块的，路径仍然带实例名。它不能写 title、subtitle、fixed、folded、split、fold，写了报错 an inline instance has no box of its own, so it cannot have 'x'。Qwen3 注意力里的 q_norm、k_norm 和 eager_attention_forward 用 inline，因为 HF 里它们不是单独的一次模块调用。

并排。实例、group 和 for 可以写 beside: 名字，表示这一项在场景里画在前一项的旁边，从同一层开始。名字是紧挨着的前一项的名字（实例名、group 名或 for 的 name），或者是已经 beside 前一项的某一项的名字，这样几项连成一组，例如 c beside b、b beside a 是三条竖道。一组里的项在编译结果的布局树里合成一个 parallel，每项一个分支，按书写顺序从左到右排列；主列从各分支最高的一层再往上一层继续。没有写 beside 的项按原来的规则排在主列上。

并排的几项是同一个模块的实例时，步骤也合并：各实例 id 相同的步骤合成一步，show 和 active 取并集，标题和正文用第一个实例的（模块默认值或这个实例的补丁），按钮文字和反向按钮文字把各实例不同的写法连起来，两边都是一整个行内公式时合成一个公式 $a,\ b$，否则用 , 连接。其余情况下 beside 只影响布局，步骤不变。合并让「q 和 k 各做一次 RMSNorm」只占四步，读者在同一步里看到两边的对应关系。

- q: 'view(x @ Wq.T, T, H, dh)'
- k: 'view(x @ Wk.T, T, Hkv, dh)'
- qk_norm:
    title: q_norm $\cdot$ k_norm
    body:
      - q_norm: { use: RMSNorm, inline: true, suffix: q, inputs: { x: q }, outputs: { out: qn } }
      - k_norm: { use: RMSNorm, inline: true, suffix: k, beside: q_norm, inputs: { x: k }, outputs: { out: kn } }
- apply_rotary_pos_emb:
    use: RoPE
    inputs: { q: qn, k: kn }
    outputs: { q_embed: qr, k_embed: kr }

这里 q_norm 和 k_norm 是两条竖道，从同一层开始，整组由 group qk_norm 画一个大括号；均方根那一步的按钮文字是 $\mathrm{ms}_{q},\ r_{q},\ \mathrm{ms}_{k},\ r_{k}$。RoPE 从两条竖道的上方开始。一个 body 里实例的步骤补丁在这个 body 全部建完之后才编译，所以 q_norm 的补丁可以引用后面 k_norm 的节点，例如在合并后的那一步里同时写出 $r^{q}$ 和 $r^{k}$。以下情况报错，错误信息指向 beside 所在的行：

  • 名字不是紧挨着的前一项，也不是与前一项并排的项，例如中间隔了一个节点。错误信息区分「这个名字前面没有」和「这个名字不是前一项」。
  • 写在单个节点 name: expr 上。并排的单位是实例、group 和 for。
  • 这一项用到了同一组里前面某一项算出的值。并排的项从同一层开始，用到别的竖道的结果的项必须画在那条竖道上方，所以要写在这一组之后。权重、buffer 和只由它们算出的节点（例如权重的转置）不算。

结构检查手写，不用 JSON Schema。未知的字段、缺少的字段和类型不对的值都报错，错误信息的格式是 文件:行:列 路径: 说明，例如 bad.yaml:5:8 body[0].y: name 'nope' is not defined in the page。行号和列号来自 yaml 包解析时保留的位置，传入的是 JavaScript 对象时信息里只有路径。YAML 里的重复键同样报错。

表达式

节点的 op、实例的 inputs、buffer 的 value 和 shape 里的维度都是 PyTorch 风格的表达式：

写法含义
f(a, b, k=v)调用 graph 上的同名方法（内置运算与 defineOp 注册的运算），位置参数和关键字参数按方法签名传递。只能在编译期求值的参数（维度名、参数、数字表达式）先求值成数。运算定义了 rest 时，多出的位置参数收成一个数组，例如 view(x, T, H, dh) 等于 view(x, [T, H, dh])。
a @ b、a ** nmatmul；pow，n 是数
a + b、a - b、a * b、a / badd、sub、mul、div。右边可以是数；数 + 节点 和 数 * 节点 交换成节点在左；数 - 节点 和 数 / 节点 报错
-a、a.T乘 −1；转置，图上已有同一个转置时复用
q[h]、o[1..H]循环下标；按顺序列出全部下标，用在 cat 这类接受节点列表的参数里。下标可以是表达式，例如 S[t-1]
[a, b]节点列表，至少一项，例如 cat([q_rot, q_pass], dim=2)
inf正无穷，-inf 是负无穷，例如 where(em, sc, -inf)。作用域里有名为 inf 的名字时用那个名字
//、1e-6、"none"、true整除；科学计数法；字符串字面量，只用于关键字参数；布尔值
act(x)act 是 op 类型的参数时，调用它的值对应的运算

YAML 的 flow 映射 { ... } 里不加引号的值遇到逗号就结束，所以带逗号的表达式要加引号，例如 { op: 'embedding(ids, E)' }。

作用域、维度与参数

  1. 作用域封闭。名字依次在本模块的 body 节点、inputs、weights、buffers、子实例 outputs 绑定的名字、params 里查找，找不到就报错。模块看不到父模块和页面的名字。
  2. 名字唯一。for 里定义的名字和实例名必须带循环变量下标（q[h]），展开后是 q[1]、q[2]。
  3. 维度靠匹配绑定。inputs 的 shape 是模式，实际形状逐位匹配，名字第一次出现时绑定，再出现时必须相等。模式里可以有一个 ...，匹配任意个维度，这些维度不绑定名字；例如 RMSNorm 的 [..., n] 只要求最后一维，输入可以是 $(T, d)$，也可以是按 head 分好的 $(T, H, d_h)$。推不出的维度声明为 dim 参数。weights 的 shape 只能用已绑定的维度和参数，可以写 H*dh 这类表达式。页面的 dims 是根作用域的维度。
  4. 参数的类型是 int、float、dim、op、tex、text 之一。没给的取 default。text 类型的参数可以写 default_key: true，没给时取实例的键，例如 input_layernorm；这样实例名就是显示的模块名，不用在实例里再写一遍。两者都没有时报错。op 类型的值必须在 values 里列出。
  5. 每个实例默认创建自己的权重；使用处写 weights: { 模块内名: 父作用域名 } 时，这个实例不再创建它，直接用父作用域的权重。
  6. 模块相同、buffer 表达式相同、参数和维度也相同的多个实例共用同一个 buffer 节点。内置的 buffer 函数是 rope_cos(T, dh, theta)、rope_sin(T, dh, theta)、causal_mask(T) 与 zeros(...)，前三个的数值与 examples/qwen3-structure.html 的 rotaryEmbedding 和 mask 相同，zeros 接受任意个维度，给出全 0 的张量，例如递推的初始状态 'S[0]': { value: 'zeros(H, dk, dv)' }。buffer 的名字可以带下标，供 for 里的 S[t-1] 在第一次迭代时引用。rope_cos、rope_sin 算出 $(T, d_h)$ 的表，RoPE 模块用 shape: [T, 1, dh] 把它重排成能和 $(T, H, d_h)$ 广播的形状。
  7. import 的引用 vizflow/nn/x 指包内的 src/nn/x.yaml，构建时以文本打进 dsl 入口，免构建和构建工具两种用法都能用；./x.yaml 这类相对路径相对于引用它的文件，用 fetch 读取，CompileOptions.read 可以替换读取函数。循环引用报错。包内的核心模块见下表。

gluGLU输入 x: [T, d]，输出 down；参数 act（op，可选 sigmoid、relu、gelu、silu，默认 silu）、f（中间维度，dim）和 name（text）。
ropeRoPE输入 q: [T, Hq, dh]、k: [T, Hk, dh]，输出 q_embed、k_embed；参数只有 theta（默认 $10^4$），$d_h$ 从输入推出；cos、sin 表是 $(T, 1, d_h)$ 的 buffer。步骤 cos、rh、sin、add。
gqaGQAgrouped-query attention。输入 q: [T, H, dh]、k: [T, Hkv, dh]、v: [T, Hkv, dv]、mask: [T, T]，输出 o，形状 $(T, H d_v)$；$d_v$ 可以和 $d_h$ 不同，MLA 就是这样。每个 query head $h$ 用 select 取出下标为 $\lfloor (h-1)/(H/H_{kv}) \rfloor$ 的 kv head（下标从 0 起，对应 HF 的 repeat_kv），再算 $S = \operatorname{select}(\mathbf{q},1,h-1)\,\mathbf{k}^{\top}$（select_matmul）、乘 $d_h^{-1/2}$、加 mask、exp、按行求和、相除、乘 $\mathbf{v}$，最后 cat(o[1..H], dim=1)。$H = H_{kv}$ 时是普通的多头注意力。步骤 krep、vrep、kT、S、Ssc、mask、exp、sum、div、pv、concat。
mlaMLADeepSeek V2/V3 的 multi-head latent attention，对应 HF DeepseekV3Attention（q_lora_rank 不为空）。输入 x: [T, d]，输出 att；参数 H、dn（qk_nope_head_dim）、dr（qk_rope_head_dim）、dv（v_head_dim）、rq（q_lora_rank）、rkv（kv_lora_rank），都是 dim，以及 theta（默认 $10^4$）。权重 $W_{qa}$、$W_{qb}$、$W_{kva}$、$W_{kvb}$、$W_o$ 对应 q_a_proj、q_b_proj、kv_a_proj_with_mqa、kv_b_proj、o_proj，子实例 q_a_layernorm、kv_a_layernorm 是 RMSNorm，apply_rotary_pos_emb 是 RoPE，注意力用 inline 的 GQA（$H=H_{kv}$）。RoPE 按 rope_interleave=False 的写法转后 $d_r$ 维；DeepSeek V3 的权重是交错存放的（rope_interleave=True），两者只差 $W_{qb}$ 和 $W_{kva}$ 里这 $d_r$ 行的一个固定排列，$d_r=2$ 时完全相同。不画 YaRN 的缩放。步骤 q_down、q_up、q_split、kv_down、kv_split、q_cat、kv_up、kv_split2、k_expand、k_cat、o_proj，以及 GQA 的步骤。
rmsnorm-zero-centeredZeroCenteredRMSNormQwen3.5 的 Qwen3_5RMSNorm。接口与 rmsnorm 相同；权重初值全 0，输出是 $\hat{x}\odot(1+\boldsymbol{\gamma})$，乘之前在 fp32 里算 $1+\boldsymbol{\gamma}$，最后转回输入的 dtype。步骤 square、rms、normalize、scale。
rmsnorm-gatedGatedRMSNormQwen3.5 Gated DeltaNet 的 Qwen3_5RMSNormGated。输入 x: [..., n] 和形状相同的 gate，输出 out $=\boldsymbol{\gamma}\odot\operatorname{norm}(x)\odot\operatorname{silu}(\mathit{gate})$，silu 在 fp32 里算；权重初值全 1；参数 eps。步骤 square、rms、normalize、scale、act、gate。
l2normL2Norm输入 x: [..., n]，输出 out $=x/\sqrt{\sum x^2+\epsilon}$，在 fp32 里算；参数 eps（默认 $10^{-6}$）。没有权重。步骤 square、norm、normalize。
gated-delta-ruleGatedDeltaRuleHF torch_recurrent_gated_delta_rule（use_qk_l2norm_in_kernel=True）。输入 q、k: [T, H, dk]，v: [T, H, dv]，g、beta: [T, H]，输出 o: [T, H, dv]。q、k 先过 L2Norm，q 再乘 $d_k^{-1/2}$；然后用 sequential 的 for 按位置递推状态 $S_t\in\mathbb{R}^{H\times d_k\times d_v}$：衰减 $\alpha_tS_{t-1}$，读出 $\hat{\mathbf{v}}_t$，写入 $\mathbf{k}_t\boldsymbol{\delta}_t^{\top}$，输出 $S_t^{\top}\mathbf{q}_t$。$S_0$ 是 fp32 的全 0 buffer。模块步骤 scale、stack，每个位置的步骤 decay、read、write、output。
lm-head-nllLMHeadNLL参数 V（dim）；输入 h: [T, d] 与标签 y: [T]，输出 loss、z、logp。

模块把 softmax 拆成 exp、求和、相除三步，把 repeat_kv 画成 select，因为读者要在图上看到这些中间张量；数值与 torch 的融合实现相同。

真实尺寸。维度在编译期同时算出示例值和真实值，真实值按 real 里的同名值取，real 里没有时等于示例值。narrow 的长度、view 的形状这类尺寸参数在两个值不同时必须写成维度名，realShape 才能显示真实尺寸。表达式算出的尺寸（例如 (h-1)*dh）没有现成的名字时，编译器第一次遇到这个尺寸时用 g.addDim 在 graph 的 dims 和 real 里加一个名为 "示例值:真实值" 的维度（例如 "4:128"），再按这个名字传参，编译只进行一遍。页面没有 real 时不加。cat 的列表参数来自范围 o[a..b]、并且范围的真实个数与示例个数不同时（例如 $H$ 的示例值 2、真实值 32），编译器给 cat 加上 pieces 选项，值是表示个数的维度，拼接结果的真实尺寸按「一块的真实尺寸 × 真实个数」计算，后面的 o_proj 因此按 4096 显示。

初值。权重按路径在 values 里查固定数值，没有时按 init 生成。buffer 也可以在 values 里按路径给定数值，替换 value 算出的数值，例如 MoE 路由的偏置 moe_layer.mlp.bias；这样的 buffer 不和其他实例共用。values 里多出的路径报错。

路径与 graph 上的节点名

实例内的名字在全页的路径是「实例名.名字」逐层拼接，例如 layer.self_attn.attn[1].P。panels、backward、步骤补丁、values 和正文模板都按路径或本作用域的名字引用节点。编译结果的 nodes 是 Map<路径, Node>。

graph 上节点的 name 就是路径。一个表达式里间接产生的节点（例如 rsqrt(ms + eps) 里的 ms + eps）没有名字，命名为 路径/k，k 从 1 起按创建顺序编号，例如 layer.input_layernorm.r/1。这些节点和所属的节点在同一步出现。正文模板按最长前缀匹配节点名，所以 {{layer.self_attn.P[1][i, j]}} 能正确识别。

tex 怎么来

  • 默认值由名字推出：小写名字加粗（q 成为 \mathbf{q}，gate 成为 \mathbf{gate}）；大写字母开头的名字照写，名字末尾的数字或小写字母作下标（Wq 成为 W_{q}，x0 成为 \mathbf{x}_{0}）；多个大写字母的名字用 \mathrm（LSE）；带下划线的名字把下划线后的部分作下标。带循环下标的名字加上标 ^{(h)}。
  • 节点的 tex 依次取：使用处 tex 的覆盖、声明里的 tex、使用处绑定的输出名推出的默认值、模块内名字推出的默认值。
  • \of{name} 换成那个名字的 tex。op 参数的 \of{act} 是运算的 tex，\of{act.def} 是运算登记的定义式，sigmoid、relu、gelu、silu 已登记（OP_TEX）。循环变量的 \of{h} 是它的值，float 参数的 \of{eps} 是它的 TeX 写法（10^{-6}）。text 参数的值里也可以写 \of{...}，在模块内展开，名字按模块内的作用域查找，所以页面传给 RMSNorm 的 out_note: $\of{out}$ 是 lm_head 的输入。 写出的是这个实例输出的 tex。
  • 重音命令 \hat、\bar、\tilde、\widehat、\widetilde、\overline、\vec、\dot 的参数是 \of{x}、而 x 的 tex 以下标结尾时，下标移到重音外面：\hat{\of{x}} 在 x 为 \mathbf{x}_{0} 时写成 \hat{\mathbf{x}}_{0}。实例自动加的下标因此不会被重音盖住，elem 也只有一层下标。
  • 步骤的标题、按钮文字、正文和面板文字里的数学符号一律写成 LaTeX（$\partial\of{x}$），不用 unicode 的数学字符。模块的步骤文字用 \of{...} 引用节点，实例自动加的下标就会出现在文字里。
  • 节点的 elem 由 tex 推出，与 explain 追加下标的方式兼容：\mathbf{x} 的 elem 是 {x}，多字母名字用 \mathrm，tex 里已有不在末尾的下标时整体加花括号，追加下标时不产生双下标。
  • 同一作用域里同一个模块有多个实例时，按出现顺序给实例内部节点和权重的 tex 加下标，带循环下标的实例用循环变量的值。已有下标的合并（W_{q} 成为 W_{q,1}），含 \of{} 的 tex 不加，作用域里只有一个实例时不加，buffer 不加。使用处写了 suffix 时用它代替下标。
  • 全页两个节点的 tex 相同时，编译器用 console.warn 给出 vizflow dsl: nodes 'a', 'b' share the tex '...'。

步骤怎么排

  1. 每个模块的 steps 插在该实例在父模块 body 里的位置。一个 step 放在它 show 的节点里最早创建的那一个之后；同一个模块里后写的 step 不排在先写的 step 前面。这样「按 head 拆开」这类步骤可以写在模块末尾，仍然出现在循环之前。
  2. body 里没有被任何 step 的 show 覆盖的节点自动生成一步，标题和标签取节点名。这一步同时显示该节点用到的、还没有出现过的权重、权重的转置和 buffer。权重和 buffer 不单独生成步骤。
  3. 没有写 sequential: true 的 for，各次迭代生成的步骤合并成一步：id 相同的步骤（包括子实例和 group 的步骤）合并，自动生成的步骤按节点在迭代中的位置合并。合并后的 show 和 active 取所有迭代的并集，label、title、text 用第一次迭代的，位置也是第一次迭代的位置。这样 GQA 每个 head 的 $S^{(h)}$、$P^{(h)}$ 共用一组步骤，步骤数不随 head 数增长，与按 head 并排画出的场景一致。并排的同一模块的实例按同样的方式合并，规则见上文「并排」。
  4. 步骤补丁写在使用处的 steps 里，键是「步骤 id」或「子实例路径.步骤 id」，例如 q_norm.square。title、label、text 替换原值，append 接在原文后面，用换行分隔，backward 逐个字段覆盖这一步的反向默认文字。循环里合并的步骤用任一次迭代的路径都能找到。id 不存在时报错 step 'x' does not exist in '路径'。补丁在所在 body 建完后才编译。
  5. 页面写了 leaves 时，总览之后的第一步是输入步骤（kind: 'inputs'），显示全部叶子；之后各步只显示自己算出的节点，用到的叶子已经在输入步骤里出现。
  6. 反向步骤用 createSteps 的 backward: 'reverse' 生成：前向步骤倒过来，每一步一个反向步骤，规则见vizflow 设计的「折叠与反向步骤」。反向步骤的文字按字段取，优先级从高到低是：模块或页面的 backward 按节点名写的文字（写进算出这个节点的那个前向步骤，节点不在任何前向步骤里时报错 node 'x' is not computed in any forward step）、补丁的 backward、步骤声明的 backward。三处都没写的字段用自动内容。
  7. 每一步记下它所属的最内层模块（module）、步骤条上的分段（segment）和段内小标题（sub）。从外往里找第一个没有写 split 的模块，它的标题是分段名；这一步的最内层模块比它更深、本身也没有写 split 时，最内层模块的标题是小标题。不属于任何模块的步骤以按钮文字为分段名。步骤自己写了 segment 时用它。
  8. 正文里的 {{ name | matrix }}、{{ name | matrix:3 }}、{{ name.grad | matrix:3 }} 在编译期按节点形状展开成 \begin{pmatrix}...\end{pmatrix}，每个单元格是一个模板 {{节点名[i, j]:3}}。三维的节点 $(T, H, d_h)$ 每个 head 展开成一个矩阵，下面标 _{h=i}，几个矩阵并排放在 \left[\,\cdots\,\right] 里；只有一个 head 时是一个普通矩阵。
  9. {{ name | rope_wave:cos }}、{{ name | rope_wave:sin:N }} 展开成内置小图 <vf-figure>，画出 RoPE 表每一列随位置变化的曲线，N 是画到的位置数，见vizflow 设计的「正文模板」。节点必须是至少 2 行、最后一维为偶数的表，中间可以夹大小为 1 的维度（$(T, 1, d_h)$）；不满足时编译报错。未知的过滤器报 unknown template filter。
  10. 其余 {{...}} 里的名字按作用域换成 graph 上的节点名，再交给步骤的正文模板。

步骤上的注释

步骤、步骤补丁和 overview 可以写 notes，在这一步的场景里放作者的注释：一段文字，加一条从文字指向目标的手绘箭头。注释只在这一步显示，离开这一步时淡出。

steps:
  mask:
    notes:
      - at: 'M[0,2]'
        side: left
        text: '$s>t$ 的格子是 $-\infty$，取 exp 之后变成 0'
字段内容
at箭头指向的目标，按作用域查找。张量名或张量列表指向整块；带下标的写法 q[0,1,2] 指向一个元素，下标从 0 开始，个数等于张量的维数，箭头落在这个元素柱子的顶端；模块实例名指向这个实例里全部运算节点的范围。名字本身就是一个节点时（例如循环产生的 P[1]）按节点处理。
text注释文字，不能为空，可以有 $...$ 公式和 \of{...}
sideleft、right、above、below 之一，文字放在目标的哪一边。不写时库按四边的空位从多到少尝试，避开场景上的按钮、图例、标签、已显示的柱子和其他注释。写了时优先这一边，这一边被挡住时仍然可以换到别的边。

补丁里的 notes 接在原有注释后面，不替换。以下情况报错：at 不是张量、元素或模块实例（'x' is not a tensor or a module instance），下标个数不对（'z[1]' gives 1 indices, but 'z' has shape (2, 3)），下标越界（'z[2,0]': index 2 is outside 0..1 on axis 0），text 为空，side 不是四个值之一。

注释的文字和箭头用主题颜色 --note（浅色主题 #2e7a55，深色主题 #84cfa4），与表示正负的 --pos、--neg 区分开。文字最宽 260px，箭头在 0.45 秒内画出。同一条注释每次画出的箭头形状相同，形状由注释在步骤里的位置决定。

模块公式

模块文件的顶层、实例和 group 可以写 formula，给出这个模块计算的公式。公式按 LaTeX 写，\step{id}{...} 标出某一部分由哪一步算出：

module: RMSNorm
formula: '\step{scale}{\of{out}=\of{weight}\odot}\step{normalize}{\of{x}\big/}\step{rms}{\sqrt{\operatorname{mean}\big(\step{square}{{\of{x}}^{2}}\big)+\epsilon}}'
  • id 的写法与步骤补丁的键相同：本模块的步骤 id，或「子实例路径.步骤 id」。子实例.* 表示这个子实例里的全部步骤，* 表示本模块的全部步骤，几个 id 用逗号隔开，任一步到达时这一部分出现。\step 可以嵌套。自动生成的步骤用节点名作 id。
  • id 不存在时报错 \step{square}: 'n' has no step 'square'; its steps are rms, scale，列出这个模块的步骤 id；\step 后面不是两个花括号参数时同样报错。
  • 实例的 formula 覆盖模块文件的 formula。rmsnorm、rope、glu、gqa 自带公式。
  • inline 实例没有模块记录，它的 formula 只能和 brace 一起写，公式归属于这个大括号，标题取 brace 的标题；只写 formula 时报错 an inline instance has no module of its own, so its formula needs a brace to name it。没有写 brace 的 inline 实例不使用模块文件的公式。

编译器把 \step{id}{...} 换成 KaTeX 的 \htmlData{vf-step=...}{...}，给对应的前向步骤记下标记（ForwardStep.marks，步骤列表里是 StepInfo.marks）；编译结果里模块的公式在 PageModule.formula，inline 实例的公式在步骤的 brace.formula，步骤列表里是 StepInfo.formula: { title, tex }。折叠的模块那一步带有模块内全部步骤的标记。

显示的位置。场景在左下角当前步骤框（←、→ 按钮和步骤标签）的正上方放一个公式框，只显示一条公式：当前步骤的 StepInfo.formula，没有时从这一步所属的最内层模块开始，向外找第一个有公式的模块。模块标题用小字写在公式上方，公式按正常的行间公式大小显示。总览和输入步骤不显示公式框，这一步所在的模块链上都没有公式时也不显示。只有跟随相机的页面有当前步骤框，所以也只有这类页面显示公式框。公式放在固定的位置，不写在每个模块大括号的标题下面：大括号旁的空间只够放一行标题，公式在那里要缩到十像素左右，还会被相邻的大括号截断。

逐步出现。公式框里每一部分有四种状态：

状态条件显示
未出现前向，这一部分的步骤都还没有到不显示，保留位置，公式的排版不随步骤变化
当前前向，当前步骤是这一部分的步骤之一用正色 --pos，从左到右在 0.7 秒内显出
已出现前向，这一部分的某一步已经过去正文颜色
反向当前反向，当前反向步骤对应的前向步骤是这一部分的步骤之一用负色 --neg；反向时其余部分都按已出现显示

反向步骤对应的前向步骤由 StepInfo.forwardId 给出：分层步骤里，每个反向步骤和折叠模块的反向步骤都记下同一组运算的前向步骤 id。没有 forwardId 的反向步骤（不分层的自动反向步骤、反向总览）按当前步骤自己的公式来源显示，各部分都按已出现显示。

系统设置了减少动画时，各部分直接出现，不做显出动画。

面板与大括号

panels 是 PanelItem 的同构写法，凡是节点的位置都写路径或根作用域的名字：tokens、sliders、ids、columns[].node、matrix、matrices[].matrix、highlight（或 highlight.node）、attention、loss.parts、loss.random.nodes 与 sgd.params。attention 可以写范围 'P[1..H]' 或列表。sgd.params 与 random.nodes 写 all 表示全部权重。matrix: head.W.T 这类表达式也可以写，转置在建图时已经存在时直接复用。title、note、caption、列标题与 loss.text 里的 \of{...} 按根作用域展开。loss 一项单独写 - loss 时用默认选项。sequence: true 的面板需要页面写了 sequence。

大括号来自模块记录。页面编译出 modules 后，autoLayout 按vizflow 设计的「分层布局」生成大括号；标题是模块记录的标题，按 renderText 渲染，可以含行内公式。页面里没有任何模块时（例如只有几个节点的最小页面），autoLayout 按布局树排布，for 里同名实例合成一个括号、并排的几项标题用 · 连接，见vizflow 设计的「自动布局」。

序列输入

语言模型的页面通常把一条 token 序列同时作为输入和右移一位的标签。页面写 sequence: { tokens: [the, cat, sat, on], input: ids, label: y } 时，编译器建两个 label 节点：input 是前 $T$ 个 token 的 id，label 是后 $T$ 个，两者的 tokens 都是页面的 vocab。规则：

  • tokens 至少两个，每个必须在 vocab 里；$T$ 等于个数减 1，根作用域的 dims 里有 T 时必须相等，否则报错 sequence has N tokens, so T must be ..., but dims gives T = ...。
  • 编译结果的 sequence 是 PageSequence：get() 返回当前的 $T+1$ 个 id，set(ids) 在一次 batch 里同时改写输入和标签；个数不对或 id 越界时抛错 sequence.set: expected N token ids between 0 and V-1, got [...]。
  • 元素把 sequence 交给面板和场景：序列面板逐个位置选 token，场景里点击 $\log\mathbf{p}$ 的柱子改的是序列，输入和标签一起变化，见vizflow 设计的「标签与交互」。
interface PageSequence { readonly tokens: string[]; readonly length: number; get(): number[]; set(ids: number[]): void }

讲解段落

sections 在场景和步骤条下方画讲解段落，用来放不属于某一步的长篇讲解（例如 RoPE 为什么能编码相对位置）。每一项编译成 SectionItem，由 ui 的 mountSections 画出，见vizflow 设计的「面板」。

  • { title?, rope?, src } 或 { title?, rope?, rows }，两者只能写一个，都没有时报错 a section needs src or rows。
  • src 是 Markdown 文件，相对于 YAML 文件解析，和 import 的模块路径一样在运行时读取。文件按冒号块分行、分栏：三个或更多冒号加名字的一行打开一个块，只有冒号的一行关闭最近的块；columns 宽度... 只能在最外层，里面只放 column；lead 是开头段落；单独的 --- 结束当前行；其他名字是内置组件，参数写在块的内容里（YAML）。解析由 dsl 的 section-md 完成，出错时报 Markdown 文件的行号，例如 qwen3/rope.md:12:1: '::: lead' is not closed。完整写法见 docs/guide.md 第 5.3 节。
  • rows 直接写在 YAML 里：一行是块的列表，或者 { columns: [宽度...], cells: [[块...], ...] }，宽度个数必须等于栏数；数字是像素，其他写法原样作为 CSS 网格宽度。块是 rope_dial、rope_curve、{ text }、{ lead }、{ buttons: [{ label, go }] }、{ rope_compare: { scores, weights, ids } } 之一。
  • rope: { q, k, rows?, head?, theta, dh, positions? } 给 RoPE 组件提供数据：q、k 可以是 $(T, H d_h)$ 或 $(T, H, d_h)$ 的节点，或每个 head 一个节点的列表；rows 是 q 和 k 各取第几行（负数从末尾数），默认 [-1, 1]；head 默认 1；dh 必须是偶数；positions 是曲线画到的位置数，默认 24，至少 2。

compilePage 的 base 是相对引用的基准地址，也是错误信息里的文件名，省略时文件名是 <page>，页面里不能有相对引用。loadPage 读取 url，以它为基准地址编译。两者都用同一个读取函数读 sections 的 src 文件。steps 的 backward 是 'reverse'，steps.modules 与 modules 是同一组模块记录。dsl 入口另外导出 PageFile、ModuleFile 等类型、DslError 与 OP_TEX。

interface LayoutTree { kind: 'module'; title?: string; subtitle?: string; children: LayoutEntry[] }
  • 根模块是最外层的 LayoutTree，title 为空；页面的 inputs 和 sequence 建的两个节点是它的第一批 node 条目。inline 实例生成一个 title 为空的子树。
  • body 顺序就是 children 顺序，表达式里间接产生的节点排在所属节点之前；weights 和 buffers 作为 node 条目放在第一次用到它的节点前面。权重的转置节点不进入布局树，自动布局从 matmul 节点的输入找到它。
  • 实例和 group 生成子 LayoutTree。一个 for 生成一个 parallel，每次迭代一个分支，没有 brace 的迭代 title 为空；sequential: true 的 for 不生成 parallel，各次迭代的条目依次接在外层的 children 里。实例和 group 的 title 与对应 SceneModule 的标题相同，在 for 里去掉循环下标。
  • 一项和 beside 它的各项合成一个 parallel，每项一个分支。实例和 group 的分支就是它们自己的 LayoutTree；for 的分支是一个 title 为空的 LayoutTree，里面是这个 for 自己的 parallel。
