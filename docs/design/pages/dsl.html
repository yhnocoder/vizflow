vizflow 页面描述文件 第四版

由标准模块组成的页面可以只写 YAML 页面描述文件。一个模块对应 PyTorch 里的一个类：init 对应 __init__，forward 对应 forward，参数路径与 state_dict 的键相同。dsl 入口把文件编译成计算图、步骤、布局、面板和讲解段落，<vizflow-page src="x.yaml"> 把它们交给挂载流程。

完整示例：examples/qwen3/qwen3-dsl.yaml，它导入的模型定义在 src/models/qwen3/。测试 test/dsl/qwen3.test.ts 把 transformers 的 Qwen3ForCausalLM 的参数写进这一页，在 float64 下比较 logits、损失和每个参数的梯度。测试 test/dsl/replaceable.test.ts 把同一页的 attn_implementation（eager 或 flash_attention_2）与 fused_linear_cross_entropy（False 或 True）的另外三种组合编译出来，也在 float64 下与 transformers 的损失和每个参数的梯度比较。其他模型页面还使用旧写法，迁移之前不能编译。

各部分决定图上的什么

  • init：有哪些参数、buffer 和子模块。参数和 buffer 画成张量，子模块的名字是它的括号的默认标题。
  • forward：画哪些张量、怎么连线。连线、悬停卡片和反向传播都由它推出。
  • layout：只调整张量的位置。
  • steps：步骤条、讲解卡片、每一步亮什么、张量什么时候出现、括号和括号上的文字。
  • tex、formula、fold：张量的数学记号、公式卡片、折叠时的讲解。

layout 不影响哪一步亮什么，steps 不影响张量的位置。图上每个张量只有一个位置。

字符串的三种读法

  • 表达式：args 的取值、count、shape、dtype、forward、show、layout、notes.at、面板里的张量引用。按 Python 表达式读，名字就是引用。
  • 模板：label、title、subtitle、text、append、note、hint。普通文字；$...$ 是 LaTeX，{{ }} 插入表达式的值，\viz{名字} 插入张量的 tex。
  • LaTeX：tex 的值和 formula，整个值就是 LaTeX。

表达式支持 + - * / // ** @、比较 == != < <= > >=（不能连写）、and or not、条件表达式 a if c else b、按位取反 ~、函数调用和关键字参数、方法调用、成员访问、下标与切片（可以带步长，例如 x[..., 0::2]）、列表、元组和字面量，语义与 Python 和 torch 相同：列表不自动拼成张量；数在左边的运算按反射运算算；下标里的 None 和 ... 与 torch 相同；转换到当前 dtype 的 .float() 不产生节点。名字先在当前作用域里找，所以 forward 里定义的 cos 会遮住运算 cos，这时写 x.cos()。

  • 张量的比较和 ~ 编译成逐元素运算；数、字符串、bool 和 None 的比较在编译时求值，and、or、not 和条件表达式只接受编译时的 bool。
  • 张量作下标是高级索引，x[idx] 按 idx 取第一维，w[a, b, None] 按两个下标张量逐对取元素并在末尾加一维，与 torch 相同。
  • topk 必须紧跟 [0] 或 [1]：[1] 是编号；[0] 是值，编译成先求编号、再用 gather 取值。largest 只能是 True，sorted 不改变结果，编号按值从大到小排。
  • .bool()、.long()、.int() 与 .float() 一样是类型转换，.type(dtype) 等于 .to(dtype)；float('-inf') 是负无穷。
  • 数的函数与 Python 相同：math.log、math.log2、math.exp、math.sqrt、math.floor、math.ceil，常数 math.pi、math.e、math.inf，以及参数都是数时的 max、min、abs。Triton kernel 里的 triton.cdiv(a, b)（$\lceil a/b\rceil$）和 triton.next_power_of_2(n)（不小于 $n$ 的最小的 2 的幂）也可以用。它们在编译时求值，不产生节点。math 或 triton 被当前作用域里的同名名字遮住时不是这些函数。
  • x.new_empty(大小...) 与 x.new_zeros(大小...) 建一个 dtype 与 x 相同、没有梯度的张量。torch 的 new_empty 不写初值，这里画成 0，所以随后必须用写入覆盖全部元素，例如两次 slice_scatter 对应 HF 的两次 copy_。

Page

title: Qwen3 Basic
model: Qwen3ForCausalLM
import:
  Qwen3DecoderLayer: ./decoder.yaml
config:
  V: 5
  d_model: 4
  dtype: bf16
  seed: 20261010
  tokenizer: { vocab: [on, mat, the, sat, cat] }
  real:
    qwen3-8b: { name: Qwen3-8B, T: 8192, V: 151936, d_model: 4096 }
data:
  tokens: [the, cat, sat, on]
  ids: { expr: 'tokens_to_ids(tokens[:-1])' }
  • model 是根模块的名字，在 modules 或 import 里查找。import 里 vizflow/nn/名字 是和模型无关的包内模块，vizflow/models/模型/名字 是一个模型的包内定义，./x.yaml 相对于当前文件；包内文件之间也用 ./x.yaml、../模型/x.yaml 相对引用。
  • config 的名字按同名传给根模块的 args；seed、tokenizer、real 只属于页面。config.dtype 是参数的 dtype，相当于 model.to(torch.bfloat16)，默认 fp32。
  • data 是根模块的输入，需要计算时写 { expr: ... }。token 列表与 tokens_to_ids 的结果编译成带词表的标签节点，序列面板替换 token 后按原表达式重新计算。
  • real 的第一个规格用于卡片上的真实形状和显存与计算量面板，不改变示例计算。根模块的模板可以读 {{ real['qwen3-8b'].d_model }}。任何模块的模板都可以写 {{ 表达式 | real }}，按第一个规格求这个数的真实值，例如 attention 里的 {{ kv_lora_rank + qk_rope_head_dim | real }}。
  • preamble 是只写 \newcommand 的文件，定义的宏在模板、tex 和公式里展开。包内模块用到的宏在 src/models/preamble.sty，每个页面先载入它，页面的 preamble 再追加或覆盖。

页面可以让读者切换同一个模型的不同实现，例如 HF 的 attn_implementation 和 Liger 的融合损失：

config:
  attn_implementation: eager
  fused_linear_cross_entropy: false
panels:
  - implementations: [attn_implementation, fused_linear_cross_entropy]
    title: 实现
  • implementations 面板的每一项是根模块的一个参数名，config 必须给出它的值，这个值是初始选中的实现。参数写了 options 时，每个选项一个按钮；bool 参数有 False 和 True 两个按钮；其他参数编译报错 'x' needs options or type bool to be switched。
  • 读者点一个按钮时，<vizflow-page> 用新的值覆盖 config 里的同名项，重新编译整页，所以计算图、步骤、布局、显存与计算量都按选中的实现生成。参数值、序列和当前步骤怎样保留，见 vizflow 设计的「页面元素」。

Module

模块文件用 module 写模块名，页面文件的 modules 也可以直接写模块。模块只能读取自己的参数、输入，以及 init 和 forward 定义的名字，同一作用域里一个名字只能定义一次。

args

类型是 dim、int、float、bool、str、list、dtype 或 module，有默认值时写 { type: float, default: 1e-6 }。使用处的 args 可以是字典或列表，列表里的裸名字表示传入调用者同名的值。

str 参数可以写 options，列出允许的取值，至少两项，例如 attn_implementation: { type: str, options: [eager, flash_attention_2], default: eager }。传入的值不在其中时编译报错 arg 'attn_implementation' of Qwen3Attention is 'sdpa', which is not one of eager, flash_attention_2。其他类型的参数不能写 options。实现面板按 options 画按钮，见 Page 一节。

inputs 与 outputs

inputs:
  x: [T, d_model]
  ids: { type: tensor, shape: [T], dtype: int64 }

dtype 是 dtype 的张量只写形状，[T, d_model] 等于 { type: tensor, shape: [T, d_model], dtype: dtype }；dtype 不同时写完整。token 列表写 { type: list, dtype: str }。形状里不是参数的名字从实际输入绑定，已绑定的名字只做检查。从输入绑定的名字在模块里至少还要被引用一次，否则报错，因为只出现一次的名字多半是参数名拼错了。不需要名字的维度写 _，'...' 对上任意个维度；dtype 写 _ 时接受任意 dtype，对应 HF 函数收到参数后自己再转换，例如 torch_chunk_gated_delta_rule 的 g。optional: true 的输入可以不传或传 None，模块里它的名字是 None，对应 HF 的 attention_mask: torch.Tensor | None = None。optional: true 的输出在 forward 里可以是 None（例如只在 if 块的一个分支里算出），这时调用结果里它的名字是 None，模块只有这一个输出时整个调用的结果是 None，对应 Liger 融合损失时 Qwen3ForCausalLM 不返回 logits。序列长度 T 是数据的维度，根模块输入的维度由显存面板的滑块改变。

init

init:
  q_proj:
    use: Linear
    args: { in_features: d_model, out_features: num_heads * d_head, bias: False }
  layers:
    use: list[Qwen3DecoderLayer]
    count: num_layers
    index: layer_idx                # 第 i 层的 layer_idx 是 i
    args: [d_model, d_head, d_ff, num_heads, num_kv_heads, layer_idx]
  mlp:
    if: layer_idx >= first_k_dense_replace
    then: { use: DeepseekV3MoE, args: [d_model, d_moe] }
    else: { use: DeepseekV3MLP, args: [d_model, d_ff] }
  constants:
    pos_freqs: rope_theta ** (arange(0, d_head, 2, dtype=int64).float() / d_head)
    attention_scaling: "0.1 * math.log(factor) + 1.0 if rope_type == 'yarn' else 1.0"
  weights:
    weight: { shape: [hidden_size], init: ones }
  buffers:
    inv_freq:
      shape: [d_head // 2]
      dtype: fp32
      value: 1.0 / pos_freqs
  • 子模块写 { use, args }，没有参数时只写模块名。use: list[M] 配合 count 建层列表，第 $i$ 层的路径是 layers[i]。层列表写 index: layer_idx 时，args 对每一层单独求值，layer_idx 是这一层的序号，对应 HF 的 Qwen3_5DecoderLayer(config, layer_idx)。不同类型的层用这个序号读 layer_types[layer_idx]，再由模块自己按类型创建子模块。
  • 子模块也可以写 present，为假时不创建，名字是 None，对应 HF 里 if 分支只创建其中一个子模块。
  • 按参数选择子模块写 { if, then, else }，if 是只读 args 的 bool 表达式，对应 HF __init__ 里的 if。条件为假且没写 else 时不创建子模块，forward 里它的名字是 None。两个分支的参数路径相同，都是这个名字。
  • weights 和 buffers 的字段相同，区别只在 weights 有梯度。两者都可以写 shape、dtype、present，取值用 init 或 value 二选一。
  • init 是 ones、zeros、normal 或 uniform。uniform 取 $U(-1,1)$，normal 取标准正态，都保留两位小数。
  • value 是编译时求值的表达式，不能读张量。
  • constants 是 __init__ 里算出的数、bool、字符串或编译时的张量，对应 HF 的 self.scaling = ... 和 rope_init_fn 里的局部变量。它们按书写顺序求值，可以读参数和前面的常量，之后在 init、forward 与文字里和参数一样使用。它们不是参数，不进 state_dict，名字不能与参数或成员重名。
  • present 是一个 bool 参数，为假时不创建这个张量，forward 里它的名字是 None，对应 HF 的 self.bias = None。
  • 参数路径沿 init 树拼接，与 state_dict 的键一致，例如 model.layers[0].self_attn.q_proj.weight。

规则 10：weights 和 buffers 没写 dtype 时用页面的 config.dtype；写了 value 时，它的 dtype 和形状要和声明一致，不做隐式转换。init 的随机数按 config.seed，默认 0。

forward

forward:
  - q_linear: q_proj(x)
  - q: q_linear.view(T, num_heads, d_head)
  - rotated: apply_rotary_pos_emb(q=qt, k=kt, cos=cos, sin=sin)
  - qr: rotated.q_embed
  - M: causal_mask(T, dtype=e.dtype)
  - h_last: layers(e, mask=M, cos=cos, sin=sin)
  • 每一项一个结果名，函数和方法是 autograd 的运算。运算结果按 torch 的类型提升推导 dtype，matmul 两侧 dtype 不同时报错，有意的转换写成 x.float()、x.to(dtype)。
  • 调用子模块写 实例(位置参数, 名字=值)。多输出的模块返回具名结果，用 result.名字 取出。调用是赋值的整个表达式时，模块的输出用调用处的名字命名。
  • 只持有参数、HF 从不调用其 forward 的模块可以省略 forward，例如 nn.Conv1d：Qwen3.5 只读取 self.conv1d.weight。
  • 同一个实例可以调用多次，共用参数；第 $k$ 次调用（$k\ge2$）的节点路径前缀是 实例路径#k。层列表依次调用各层，第一个位置参数逐层串联。
  • 表达式里间接产生的节点名是结果名加 /序号，例如 ex/1。布局运算和类型转换不单独画，画在最近的已画出的源节点上。
  • 每个 forward 结果都要被某一步展示，或由一个被展示的模块调用算出，否则报错。确实不需要展示的结果写进 unshown。
  • 循环外的结果可以是 None，对应 HF 里由配置决定、可能不执行的一段，例如 denominator: s.sum(-1) + 1e-20 if norm_topk_prob else None。这时不产生节点，展示它的步骤按规则 12 不生成。
  • 结果也可以是数或 bool，例如 masking: n >= n_block_max - n_masking_steps，对应 kernel 代码里的局部变量。计算它时产生了张量就报错。它不是节点，不需要展示，可以在后面的表达式、if 条件、range 和步骤模板里使用；在循环里每一轮记下各自的值，步骤读取时按规则 11 取值。
  • 表达式支持比较 ==、!=、<、<=、>、>=（不能连写），条件表达式 a if 条件 else b（只求值选中的一边，条件必须是 True 或 False），以及数的 %（与 Python 一样，结果与除数同号）。
forward:
  - core_attn_out: zeros_like(value)
  - for: i in range(num_chunks)
    do:
      - q_i: query[:, i]
      - v_new: v_i - v_prime
      - core_attn_out[:, i]: attn_inter + attn_i @ v_new
      - last_recurrent_state: last_recurrent_state * decay_i + update_i
  • 循环写 { for: i in range(n), do: [...] }。range 与 Python 相同，接受 range(stop)、range(start, stop)、range(start, stop, step)，step 是非零整数，可以为负，例如 range(n_block - 1, -1, -1) 从后往前。循环在编译时展开，每一轮的节点路径带 [i]，tex 带下标 $_{i}$，例如 q_i[1]。真实规模下轮数不同时，显存与计算量按真实轮数计算。
  • 循环可以嵌套，内层的 range 可以读外层的循环变量，节点路径每层循环带一个下标，例如 acc_s[0][1][0]。内层 range 的 start 或 stop 直接写出外层循环变量时，内层循环里的节点按「外层各轮的内层轮数之和」计份数：画出的份数是示例尺寸下各轮内层轮数之和，真实份数是真实尺寸下外层每个取值对应的内层轮数之和。causal 注意力里第 $m$ 个 query 块只处理前几个 kv 块，按这条规则统计时，真实规模下的 kv 块数是三角形的面积，不是 query 块数乘 kv 块数。范围里只出现由外层变量算出的名字（例如 n_block_max）时不按这条规则，内层轮数取当前这一轮的值，再与外层份数相乘，所以 flash_fwd_kernel 在 range 里写出完整的表达式。
  • layers[i](h, ...) 调用层列表的第 $i$ 层，对应 HF 的 for i, decoder_layer in enumerate(self.layers)，用于每层收到的参数不同的情况，例如按 layer_types[i] 选择 mask。
  • 循环里可以重新绑定循环外定义的名字，对应 HF 在循环里改写 last_recurrent_state；循环外同一个名字只能定义一次。
  • x[下标]: 表达式 是 HF 的 x[...] = ...，只能写在循环里，得到写入后的新张量，原张量不变。下标里每一维是 :、一个整数或一段切片，可以有一个 ...。整数下标编译成 select_scatter，切片编译成 slice_scatter，多个维度从左到右嵌套，例如 attn[..., i, :i] 是 select_scatter(attn, slice_scatter(attn[..., i], 新值, -1, None, i), -2, i)。
  • 'x[...]': 表达式 写整个张量，编译成覆盖整个张量的 slice_scatter(x, 新值, 0)，对应循环里的原地更新，例如 Liger 的 grad_weight.addmm_(...) 写成 'grad_weight[...]': grad_weight + grad_logits_chunk.transpose(0, 1) @ _input_chunk。其他覆盖整个张量的下标（例如 x[:]）报错，提示改写成 x[...] 或换一个名字。写入的结果在显存统计里与被写的张量共用存储，在循环里反复写同一个缓冲区不按每次写入新增一份，见 vizflow 设计的「显存与计算量」。
forward:
  - h_norm: model(ids)
  - hidden_states: h_norm
  - if: fused_linear_cross_entropy
    then:
      - loss: liger_flce(hidden_states, lm_head.weight, y)
    else:
      - z: lm_head(hidden_states)
      - logp: log_softmax(z.float())
      - result: nll_loss(logp=logp, y=y)
      - loss: result.loss
  • { if: 条件, then: [...], else: [...] } 对应 HF 代码里按配置走不同路径的 if，else 可以省略。条件在编译时求值，可以读参数、常量和 forward 里算出的数与 bool，结果必须是 True 或 False，读到张量时报错；在循环里每一轮单独求值。
  • 只执行选中的分支。没有执行的分支里直接定义的名字是 None，在循环里按轮记为 None，所以步骤可以照常引用它们，展示它们的步骤按规则 12 不生成。两个分支可以定义同一个名字，例如上面的 loss。
  • 没有执行的分支里调用的子模块在这次 forward 里没有被调用，它的步骤同样按规则 12 不生成。上面的 liger_flce、log_softmax 由 init 的 present 按同一个参数决定是否创建。

save、backward 与 kernel

module: flash_attn_func
forward:
  - fwd_result: fwd(q, k, v)
  - out: fwd_result.out
  - softmax_lse: fwd_result.softmax_lse
save: [q, k, v, out, softmax_lse]
backward:
  - dq: zeros_like(q)
  - dot: dot_do_o(grad_out, out)
  - main: dq_dk_dv(grad_out, q, k, v, softmax_lse, dot.dsoftmax_sum, dot.dq_accum)
  - grad_q: convert_dq(main.dq_accum_out, dq)
  - grad_k: main.dk_expanded
  - grad_v: main.dv_expanded
backward_steps:
  - { id: dq, show: dq }
  - { id: dot, show: dot }
  - { id: main, show: main }
  - { id: convert, show: convert_dq }
  - { id: gqa, show: [grad_k, grad_v] }
  • 写了 backward 的模块对应 torch.autograd.Function：forward 是 Function.forward，save 是 ctx.save_for_backward，backward 是 Function.backward。计算图反向时执行 backward 里的运算，不对 forward 里的运算求导，所以 forward 里除输出以外的张量没有梯度。这样页面可以画出 FlashAttention 和 Liger 实际执行的反向，它们的反向与对前向逐个运算求导的结果在数学上相同，计算过程不同。
  • backward 的写法与 forward 相同，可以用循环、if 和子模块调用。grad_输出名 是这个输出收到的梯度，save 列出的名字是保存下来的张量；save 只能列 forward 里的张量（包括输入），同一个名字不能保存两次。参数、成员和形状里绑定的维度名照常可以读。
  • 每个浮点输入的梯度是 backward 里名为 grad_输入名 的张量，形状必须与输入相同；写 grad_x: None 表示这个输入没有梯度。save 里名为 grad_输入名 的张量也算，Liger 在前向算出 grad_weight，保存后直接作为 weight 的梯度。整数 dtype 的输入不需要梯度。浮点输入的梯度没有给出时报错 the backward of M must set grad_x, the gradient of input 'x', or set it to None。
  • backward 的节点路径前缀是 调用路径.backward，例如 model.layers[0].self_attn.flash_attention_forward.flash_attn_func.backward.grad_out。grad_输出名 的 tex 默认是 \mathrm{d} 加输出的 tex，模块的 tex 里写 grad_out 可以改写；保存的张量沿用原张量的 tex。
  • backward_steps 的写法与 steps 相同，展示 backward 算出的张量和调用。写了 backward 的模块必须写 backward_steps，backward 里定义的每个名字都要被某一步展示，否则编译报错 'x' of the backward of M is not shown by any of its backward_steps。

规则 13：backward_steps 编译成反向步骤，放在前向最后一个属于这次调用、或展示这次调用输出的步骤处：反向走到这一步时，先按书写顺序走 backward_steps，再走这一步自己的反向步骤。没有这样的前向步骤时编译报错 no forward step shows the call 'x', so its backward steps have no place。它们在步骤条上位于这次调用的分组之下，有子步骤的步骤成为分组，id 是 调用的分组 id.backward.步骤 id。调用所在的模块折叠时，反向只有折叠模块的一步，不生成这些步骤。

kernel: true 的模块是一个 GPU kernel：一次调用里除输出以外创建的张量都在片上的 shared memory 和寄存器里，显存统计不计它们，FLOP 照常计。flash_fwd_kernel 的分数块和概率块因此不出现在显存里，与 FlashAttention 不把 $T\times T$ 矩阵写回显存一致。kernel 只能是 true 或 false。

Layout

规则 1：布局默认每行 forward 一层，按 forward 的顺序从前往后排。同一层里的左右顺序按数据来源自动排。调用子模块的一行展开成子模块 forward 的各层。

只把一个已有张量赋给新名字的一行（例如 x1: x，对应 HF 的 residual = hidden_states）也画成一层，数值与原张量相同，梯度原样传回，不占额外显存。它和原张量之间的连线画成虚线，表示中间没有计算。没有步骤 show 它、它又是某个模块调用的输入时，它随这个调用的第一步出现，不单独成为一步，也不在这个调用的括号里。

layout:
  place:
    M: { with: position_ids }       # 和 position_ids 同一层，左右自动排
    x: { left: y }                  # 同一层，在 y 左边；还有 right
    z: { after: w }                 # 在 w 后面一层；还有 before
    weight: { right: y }            # weight 和 buffer 也可以放，只能用 with、left、right
  merge:
    - [q_norm, k_norm]              # 两个结构相同的调用逐层对齐，并排画
  • place 的值是这个模块 forward 里算出的张量；键是算出的张量，或者 init 里的 weight、buffer。每项只写一个方向。left、right、with 放进目标所在的层，横向位置与已有的张量重叠时向外挪开。
  • weight 和 buffer 没有自己的层，只能用 with、left、right。没写 place 时，它们画在第一次用到它们的那一层。做 matmul 的权重画成这个 matmul 的矩阵，place 不能移动它，写了会报错。
  • merge 的两个调用必须是同一个模块、各调用一次。两边的第 $k$ 层合成一层，左边的调用画在左侧，合并后的层放在后调用的那一行的位置。

规则 4：merge 只影响位置，不会让两边的步骤一起亮；一起亮要在 steps 里写 zip。

Step

步骤是一棵树。只写 show 的步骤是叶子；有 steps 的步骤，以及 show 一个有步骤的模块调用的步骤，是一组。

steps:
  - id: overview
    show: all()                     # 还有 inputs()、parameters()，可以相加
  - id: prepare
    title: 位置和 mask
    steps:
      - id: mask
        show: [M, position_ids]     # 同一个张量可以在多步里亮
      - id: rotary_emb              # show 省略时等于 id，这里是一次模块调用
  - id: res1
    show: a
    brace: true
    subtitle: '$\viz{x}+\viz{att}$'
  - id: qk_norm
    show: zip(q_norm, k_norm)
  - id: model
    flat: true
    edit:
      prepare.rotary_emb.cos_sin: { append: ... }

规则 8：show 省略时等于步骤的 id。

show

  • 张量或张量列表：一步，亮这些张量。
  • 一个模块调用：子步骤取那个模块自己的 steps。同一个实例调用多次时名字不能指定是哪一次，编译报错。
  • zip(a, b)：两个同一模块的调用，子步骤按 id 逐个合成一步，两边的子步骤 id 必须相同。合成的一步亮两边的张量，标题取两边标题的并列。
  • all()、inputs()、parameters() 可以用 + 相加。all() 是其他所有步骤亮的张量的并集；inputs() 是根模块的输入，parameters() 是全部参数和 buffer。

规则 7：show 一个模块调用时，子步骤取那个模块自己的 steps。模块没有 steps 时只有一步，亮这次调用用到的参数和算出的张量。

规则 6：一步亮的张量是 show 里的张量，加上其中算出来的张量的直接输入，连线一起画出。

规则 5：张量在它第一次亮的那一步出现，之后一直在原位。

括号

规则 2：有子步骤的步骤画一个括号，框住它下面所有步骤 show 的张量。show 一个模块调用的步骤也算有子步骤。括号上的文字是这一步的 title、subtitle；show 模块调用时没写 title 就用调用的名字，没写 subtitle 就不显示副标题。只亮张量的步骤写 brace: true 才画括号，框住它 show 的张量。

括号框住的张量在布局里不连续时编译报错，报错列出夹在中间的张量：steps: the brace of 'res1' (残差相加) frames tensors that are not next to each other; ... lies between them。这时用 layout 调整位置，或改变步骤的分组。括号按嵌套深度排列：最外层画在右侧，第二层也在右侧更靠近图，更深的画在左侧。

步骤条

规则 9：步骤条的分组就是步骤树：有子步骤的步骤成为一组，flat: true 的除外。有子步骤的步骤写了 text 时，它自己也是一步，排在子步骤前面。没写 text 时它不占一步。这一步自己不 show 张量，它高亮从外面流进这组步骤的激活：子步骤 show 的张量所读取的、在这组之外、此前已经出现过的计算结果，不含参数、buffer 和输入这类叶子。相机框住这些张量。例如 model.norm 的这一步高亮 $\mathbf{h}_{\mathrm{last}}$，不高亮 $\gamma$。

flat: true 的步骤把子步骤直接放在上一级，步骤条不单独成组，图上不画括号。步骤条第一级的分组是分段，分段内显示最内层分组的标题。

折叠

规则 3：模块调用可以由读者点击折叠或展开，初始状态由步骤的 expand 决定，默认展开。展开时画成括号，子步骤逐个走；折叠时画成盒子，子步骤合成一步，讲解取模块的 fold。

步骤上的 fold 改写这次调用折叠后那一步的讲解，模块顶层的 fold 是默认值。zip 的步骤不能折叠。

讲解与修改

  • label、title、text 是这一步的讲解，append 在正文后追加；backward 改写对应的反向步骤，notes 在场景里加注释。有子步骤的步骤只有写了 text 才能写 append、label、notes 和 backward。
  • edit 按路径修改展开出来的子步骤，路径是从这一步往下的步骤 id，用点连接，例如 prepare.rotary_emb.cos_sin。edit 不能改 show。
  • formula 写在有子步骤的步骤上，显示在它下面每一步的公式卡片里；没写时取模块的 formula。

循环步骤

- id: layers
  loop: layer = layers[i]
  defaults:
    title: Qwen3DecoderLayer
    subtitle: 第 {{ i }} 层
  rules:
    - at: -1
      subtitle: 最后一层

loop 对列表的每一项生成一步，i 从 0 开始。先合并 defaults 与 at 匹配的规则，再求值模板。show 默认是循环变量。

- id: chunk
  loop: i in range(num_chunks)
  defaults:
    title: 第 {{ i }} 块
    steps:
      - { id: v_new, show: [v_prime, v_new] }
      - { id: state, show: last_recurrent_state }

loop: i in range(n) 对 forward 循环的每一轮生成一步，步骤的 id 是 chunk[i]，at 按轮的序号匹配。show 必须写。range 与 forward 一样接受一到三个整数，step 不能为 0，可以为负。

- id: row_block
  loop: m in range(triton.cdiv(T, block_m))
  defaults:
    title: 'query 块 {{ m }}'
    steps:
      - id: kv_block
        loop: n in range(min(triton.cdiv(T, block_n), triton.cdiv((m + 1) * block_m, block_n)) - 1, -1, -1)
        defaults:
          title: 'kv 块 {{ n }}'
          steps:
            - { id: qk, show: [k_tile, acc_s, cols, future, acc_s_masked] }

循环步骤可以写在另一个循环步骤的 defaults.steps 里，与 forward 的嵌套循环对应。内层的 range 和模板可以读外层的循环变量，以及 forward 在外层这一轮算出的名字。

规则 11：在 range 循环步骤里，forward 循环里绑定的名字取第 i 轮的值；嵌套时取各层当前这一轮的值，名字只在外层循环里绑定时取外层这一轮的值。在循环步骤外，循环前已经定义、循环里又重新绑定的名字取循环前的值，只在循环里定义的名字取最后一轮的值。步骤按 forward 的顺序写，循环前的步骤展示初值，最后一轮的步骤展示终值。

规则 12：show 或省略 show 时的 id 是一个值为 None 的名字，或者是一个这次 forward 没有调用的子模块（创建了但调用写在没有执行的 if 分支里，或者根本没有调用）时，这一步不生成，edit 与 formula 里对它的引用一起忽略。show 是列表时，值为 None 的项跳过，全部是 None 时这一步不生成。不同类型的层共用一份 steps 时，只有这一层创建的子模块有步骤。

tex 与 formula

节点的 tex 按以下顺序决定，先找到的生效：外层模块 tex 里按相对路径写的名字（例如 mlp.a），调用处的名字的 tex，模块自己的 tex，由名字推出（W_q 是 $W_{q}$）。层列表里的模块给 tex 加上标 ^{[i]}，序号从 0 开始。tex 末尾已经是上标时并进同一个上标，例如 $\mathbf{s}^{\mathrm{grp},[1]}$；tex 在顶层有其他上标或撇号时先加花括号，例如 ${\mathbf{k}'}^{[1]}$；tex 在顶层有 + - = ,、\cdot、\times 等运算时是复合表达式，整体加括号再加上标，例如 $\left(\sum\mathbf{w}+10^{-20}\right)^{[1]}$。

formula 里 \step{步骤路径}{公式片段} 标出由哪一步算出的部分：前向走到这一步之前不显示，走到时用正色标出；反向时整条公式显示，当前步骤对应的部分用负色标出。子实例.* 表示子实例的全部步骤，几个路径用逗号隔开。

{{ 表达式 | 格式 }} 插入值。格式有 matrix:位数、join: "分隔符"（张量或 config 里的列表）、real（见 Page 一节）和内置小图 lines:...，小图的写法见 vizflow 设计的「内置小图」。
