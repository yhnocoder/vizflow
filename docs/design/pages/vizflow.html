vizflow 设计 第一版

vizflow（npm 包名 @yhnocoder/vizflow）是一个用来编写交互式计算图讲解页面的 JavaScript 库。页面用声明式的 API 描述张量、运算、布局和讲解，库负责前向与反向计算、自动推导反向传播的每一步、悬停卡片、3D 场景和面板。本文档写页面怎么写、各模块的接口、影响显示和数值的常量，以及改动时容易被破坏的设计决定。

页面里不写任何反向代码和连线代码。反向步骤、每条边的局部导数和每张卡片都由库根据运算定义推导，并由有限差分、PyTorch 对拍、边求和三道检查保证正确。

vizflow 解决什么问题

vizflow 来自两张手写的交互式计算图：一张讲 softmax 与交叉熵，一张讲 Qwen3 的 lm_head 与 NLL Loss。手写的页面有两个问题。第一，两个页面大部分代码相同，但每次重写的刻度、标签位置、卡片措辞都略有不同，读者在页面之间切换时会感到不一致。第二，反向传播的每条边、每张卡片都是手写的，图越复杂越容易写错，而这类错误读者最难发现。vizflow 把重复的部分收进库里，页面只描述自己独有的内容；反向传播由库从运算定义推导。

库只规定页面怎么写，页面讲什么由调用方决定。库提供计算图模型、运算定义、布局模板和渲染方式；一张图里有哪些张量、讲哪几步、每一步写什么，都写在调用方的页面里。vizflow 有自己的仓库、文档、示例和测试，打包后供静态站使用，静态站固定引用某个版本。库升级不影响已经写好的页面，页面需要新功能时改版本号。

为什么用 JavaScript 库描述页面

页面由作者和 Claude 共同编写，多数时候作者在 Claude 生成的代码上修改，所以可调试性比语法简洁更重要。JavaScript 有编辑器高亮、补全和报错，可以在浏览器里打断点；专门设计的文本格式需要另写解析器，报错难以看懂，遇到没有设计过的需求时也无法用一段自定义代码处理。

页面只调用一套声明式 API。样式、刻度、悬停、步进的逻辑只存在于库里，页面没有地方写出差异，一致性由此保证。库用 TypeScript 编写并输出类型声明，页面作者写普通 JavaScript 时编辑器也能给出补全和提示。

由标准模块（RMSNorm、注意力、MLP 等）拼成的页面，JavaScript 写法里大部分是重复的建图和布局代码。这类页面可以改写成 YAML 页面描述文件，见「页面描述文件怎么写」和单独的文档 vizflow 页面描述文件。描述文件编译成同一套 JavaScript 接口的数据，报错带文件名、行号和列号；描述文件写不出的需求仍然用 JavaScript 写。

一个页面怎么写

脚本按「建图、写讲解、挂载界面」三段写：

import { graph } from '@yhnocoder/vizflow/core';
import { createSteps } from '@yhnocoder/vizflow/steps';
import { mountScene, board, stack } from '@yhnocoder/vizflow/scene3d';
import { mountSteps, mountPanels } from '@yhnocoder/vizflow/ui';

const g = graph({
  dims: { d: 4, V: 5 },
  real: { d: 4096, V: 151936, name: 'Qwen3-8B' },
});

const h = g.input('h', [1, 'd'], [0.8, -1.1, 0.5, 1.4]);
const W = g.param('W', ['V', 'd'], [
  [ 0.9, -0.6,  0.3,  0.6],
  [ 0.2, -0.8,  0.6,  0.2],
  [-0.4,  0.2,  0.9,  0.3],
  [ 0.5,  0.7, -0.6, -0.2],
  [-0.7,  0.4, -0.3, -0.5],
], { tex: 'W', elem: 'W' });
const t = g.label('t', [0], { tokens: [' mat', ' floor', ' sofa', ' dog', ' sat'] });

const z    = g.matmul(h, W.T, { name: 'z' });
const L    = g.logsumexp(z, -1, { keepdim: true, name: 'LSE' });
const logp = g.sub(z, L, { name: 'log p', tex: '\\log\\mathbf{p}', elem: '\\log p' });
const loss = g.nll_loss(logp, t, { name: 'loss', tex: '\\ell', elem: '\\ell' });

const steps = createSteps(g, {
  overview: {
    title: '整张图',
    text: String.raw`
      目标 token 是 {{t:token}}。

      $$\ell = -\log\operatorname{softmax}(\mathbf{h}W^{\top})_t = \mathrm{LSE}(\mathbf{z}) - z_t = {{loss:3}}$$
    `,
  },
  forward: [
    { show: [h, W.T], label: String.raw`$\mathbf{h},\ W^{\top}$`, title: String.raw`输入：$\mathbf{h}$ 和 $W^{\top}$`,
      text: String.raw`$W$ 按 PyTorch 存成 $(V,d)$，前向计算 <code>h @ W.T</code>，图里画的是 $W^{\top}$。` },
    { show: z, active: [h, W.T, z], label: String.raw`$\mathbf{z} = \mathbf{h}W^{\top}$`, title: String.raw`lm_head：$\mathbf{z} = \mathbf{h}W^{\top}$`,
      text: String.raw`
        $h_k$ 沿 $W^{\top}$ 的第 $k$ 行经过每个方块，每一列从后往前累加。

        $$z_{ {{t+1}} } = \sum_k h_k W^{\top}_{k, {{t+1}} } = {{z[t]}}$$
      ` },
    { show: L, label: 'LSE', title: 'log-sum-exp',
      text: String.raw`
        先减去最大值 $m$ 再取指数，最大的一项是 $e^0 = 1$，不会溢出。

        $$\mathrm{LSE} = m + \log\sum_j e^{z_j - m} = {{LSE}}$$
      ` },
    { show: logp, label: 'log p', title: 'log_softmax',
      text: String.raw`
        每个 logit 减去同一个 LSE。

        $$\log p_{ {{t+1}} } = z_{ {{t+1}} } - \mathrm{LSE} = {{log p[t]}}$$
      ` },
    { show: loss, label: String.raw`$\ell$`, title: 'nll_loss',
      text: String.raw`
        nll_loss 按标签取出一个元素再取负号。

        $$\ell = -\log p_t = {{loss:3}}$$
      ` },
  ],
  backward: 'auto',
});

const PYTORCH = `logits = lm_head(h)
logp = F.log_softmax(logits.float(), dim=-1)
loss = F.nll_loss(logp, t)`;

mountSteps('#steps', steps);
mountScene('#stage', g, {
  steps,
  layout: [board(h, W.T, z), stack(z, L, logp, loss)],
});
mountPanels('#side', g, [
  { loss: {
      sgd: { params: [W], lr: 0.5, label: '更新一步 W' },
      random: { nodes: [h], range: [-2, 2] },
      reset: true,
  } },
  { sliders: h, min: -2.5, max: 2.5, step: 0.01, title: '隐状态 h' },
  { tokens: t, columns: [z, logp, { node: z, grad: true, title: String.raw`$\partial\ell/\partial\mathbf{z}$` }], title: '目标 token' },
  { matrix: W.T, highlight: t, title: String.raw`$W^{\top}$` },
  { matrix: W.T, grad: true, highlight: t, title: String.raw`$\partial\ell/\partial W^{\top}$` },
  { code: PYTORCH, title: 'PyTorch' },
], { steps });

页面里写的只有这些。反向的五个步骤（$\ell$ 与 $\log\mathbf{p}$、LSE、$\mathbf{z}$、$W^{\top}$、$\mathbf{h}$）、每条边的悬停卡片、每个张量的层名卡片，都由库根据计算图推导。

同样的页面也可以不写容器和挂载调用，只放一个 <vizflow-page> 元素，把计算图、步骤、面板和场景配置设为它的属性，见「页面元素」一节。

页面用 ES module 加载，不能通过 file:// 直接打开，本地预览时需要启动一个 http server。

页面描述文件怎么写

由标准模块组成的页面（例如一层 Transformer）可以不写 JavaScript，只写一份 YAML 页面描述文件，由 dsl 入口编译成计算图、步骤、面板、讲解段落、模块记录和一棵布局树，<vizflow-page src="x.yaml"> 再把这些交给已有的挂载流程。文件格式、模块、表达式、步骤与折叠、序列输入、讲解段落和编译接口写在单独的文档 vizflow 页面描述文件 里。

模块怎么划分，各入口加载什么

模块按用途拆开，因为很多场合只需要其中一部分。只需要数值时，例如在笔记里放一张梯度表或者写测试，只引入 core，three.js、Solid、KaTeX 都不会加载。只想在文章里嵌一个带滑块的 softmax 小部件时，引入 core 和 ui，不需要 3D。完整的一页才用到全部模块。

依赖方向是单向的：tensor ← autograd ← explain ← steps；ui 依赖 autograd、steps、formula、theme；scene3d 依赖 autograd、explain、steps、formula、theme，并直接引用 ui/figure-spec 与 ui/figures（卡片里的 RoPE 小图）；element 依赖 steps、ui、scene3d，设置 src 时再动态加载 dsl；dsl 依赖 autograd、explain、steps，直接引用 ui/figure-spec 检查模板里的小图参数，并引用 scene3d 与 ui 的类型。figure-spec 与 figures 不引用 Solid，所以 dsl 不加载 three.js 和 Solid。图里没有画 dsl。除了这两个文件，模块之间只通过各自目录的 index.ts 引用。

模块之间不直接调用，都围绕同一个计算图协作。计算图是唯一的数据来源：输入变化后它重算前向和反向，然后发出更新通知；3D 场景、面板和讲解正文各自订阅通知、读取需要的数值，彼此不知道对方是否存在。steps 只输出一个状态对象，说明当前方向、第几步、每个节点是否出现和是否高亮。scene3d 读取这个状态决定颜色和透明度；页面没有创建 steps 时，scene3d 使用「全部显示」的默认状态。

库不使用模块级可变状态，所有状态挂在计算图实例和 mount 返回的句柄上，同一个页面可以放两张互不干扰的图。例外有以下几处：运算注册表与讲解注册表（定义本身不可变，与 torch 的全局算子表同理）；formula 的当前适配器（setAdapter）与 KaTeX 渲染缓存；theme、ui、scene3d、element 与 formula 注入 <style> 时按 id 判断，同一页面只注入一次。

计算图怎么建，输入变化后怎么更新

建图

graph(options?: {
  dims?: Record<string, number>;
  real?: { name?: string } & Record<string, number | string>;
  check?: boolean;
  dtype?: Dtype;
}): Graph

type Dtype = 'bool' | 'uint8' | 'int8' | 'int16' | 'int32' | 'int64' | 'fp8_e4m3' | 'fp8_e5m2' | 'fp16' | 'bf16' | 'fp32' | 'fp64';

interface NodeOptions {
  tex?: string;
  dtype?: Dtype;
  elem?: string;
  card?: { forward?: Partial<CardText>; backward?: Partial<CardText> };
}
interface CardText { title: string; tex: string[]; note: string }
interface SplitOptions { names?: string[]; tex?: string[]; elem?: string[] }

interface Graph {
  readonly dims: Readonly<Record<string, number>>;
  readonly real: Readonly<Record<string, number | string>> | undefined;
  readonly dtype: Dtype;
  readonly nodes: readonly Node[];
  readonly version: number;
  input(name: string, shape: (number | string)[], values: Nested, options?: NodeOptions): Node;
  param(name: string, shape: (number | string)[], values: Nested, options?: NodeOptions): Node;
  label(name: string, values: Nested, options?: NodeOptions & { tokens?: string[]; classes?: number }): Node;
  buffer(name: string, shape: (number | string)[], values: Nested, options?: NodeOptions): Node;
  split(tensor: Node, split_size: number | string, dim?: number, options?: SplitOptions): Node[];
  loss(node?: Node): Node;
  findLoss(): Node | undefined;
  node(name: string): Node | undefined;
  subscribe(fn: () => void): () => void;
  batch(fn: () => void): void;
  reset(): void;
  jacobian(out: Node, input: Node, options?: { row?: number }): Tensor;
}
选项或方法行为
dims命名维度，例如 { d: 4, V: 5 }。shape 中的字符串在建图时解析成数字，未定义的名字抛错。
real真实模型的尺寸，例如 { d: 4096, V: 151936, name: 'Qwen3-8B' }。每个节点的 realShape 用这些尺寸重算，层名卡片多显示一行「真实模型」。
check打开有限差分检查，见「正确性怎么保证」。
dtype真实模型里张量的默认 dtype，默认 fp32；Qwen3 等以 bfloat16 发布的模型写 bf16。dtype 只用于显示，计算内核始终用 float64 计算。各节点的取值规则见下文「节点」。不在 Dtype 列表里的值抛错 graph: unknown dtype 'x', expected one of ...。
input、param叶子节点。values 可以是扁平数组或嵌套数组，元素个数必须等于 shape 的元素个数。两者的区别是 param 可以被损失面板的「更新一步」更新。
label整数标签，shape 从 values 推断：0 是 ()，[0] 是 (1,)，[[0],[1],[2]] 是 (3, 1)。tokens 是每个类别的显示名，classes 是类别数，默认等于 tokens.length。
buffer常量叶子，对应 torch 的 register_buffer，例如 RoPE 的 cos、sin 表和 causal mask。值可以含 -Infinity。它没有梯度：grad 为 null，不进入自动生成的反向步骤，不能放进损失面板的 sgd.params 与 random.nodes，模板里对它取 .grad 在编译时报错。它可以 set，reset 时恢复创建时的值。3D 场景照常画出它；它连到运算的边在前向画出，反向不画，因为反向连线表示梯度经过的路径，而 buffer 没有梯度。用 input 表示这类张量时，读者会在反向步骤和梯度下降里看到一个本不该训练的量，所以单独设一种叶子。
split对应 torch.split(tensor, split_size, dim)，返回若干个 narrow 节点组成的数组，本身不是运算节点。split_size 不整除时最后一块较小。split_size 可以是 dims 里的维度名，规则见「尺寸参数可以写维度名」。options 的 names、tex、elem 按块逐个给出，个数必须等于块数；没给 names 时第 $i$ 块（从 1 开始）命名为 名字_i，例如 q_1。任何一块的名字已经存在时抛错，这时一个节点也不创建。dim 默认 0，第三个参数是对象时视为 options。
loss、findLossloss(node) 指定损失节点。findLoss() 返回当前损失节点：指定过时返回指定的节点，否则取最后创建的、元素个数为 1 的运算节点，都没有时返回 undefined。不传参数的 loss() 与 findLoss() 相同，但没有损失节点时抛错；steps、explain 与 scene3d 用 findLoss() 判断一个节点是否是损失。
node按名字查找节点，比较时忽略空白，'log p' 与 'logp' 相同。
batchfn 内的多次 set 合并成一次重算和一次通知。
reset所有叶子节点恢复创建时的值。
jacobian当前值下 out 对 input 的完整 Jacobian，shape 为 out.shape 接上 input.shape。给出 row 时只取第一维第 row 行的块：输出与输入的第一维必须相同，结果 shape 为两者各自去掉第一维后拼接，批量 softmax 页用它显示当前样本的 $(V, V)$ Jacobian。结果不是计算图的节点，供矩阵面板显示，例如 softmax 页的 $\operatorname{diag}(\mathbf{p}) - \mathbf{p}\mathbf{p}^{\top}$。

节点名重复时抛错。运算节点不给 name 时自动命名为运算名加序号，例如 exp1。

core 另外导出 moduleJacobian(g, { nodes }, input, output): number[][]：只沿 nodes 里的运算节点做反向，算出当前值下 output 对 input 的 Jacobian，行是 output 的元素、列是 input 的元素（都按行主序展平）。模块外的节点不参与，所以它是这个模块自己的 Jacobian。场景用它给折叠的模块画整体 Jacobian 的连线，见「折叠的模块」。

节点

class Node {
  readonly id: number;
  readonly graph: Graph;
  readonly kind: 'input' | 'param' | 'label' | 'buffer' | 'op';
  readonly name: string;
  readonly op: string | undefined;
  readonly inputs: readonly Node[];
  readonly attrs: Readonly<Record<string, unknown>>;
  readonly shape: readonly number[];
  readonly realShape: readonly number[];
  readonly dtype: Dtype;
  readonly tex: string;
  readonly elem: string;
  readonly tokens: readonly string[] | undefined;
  readonly card: NodeOptions['card'];
  get value(): Tensor;
  get grad(): Tensor | null;
  get T(): Node;
  set(values: Nested): void;
  index(...idx: number[]): number;
}
  • tex 是张量级的 LaTeX，例如 \mathbf{h}；elem 是元素级的底，元素写作 elem 加下标，下标从 1 开始，例如 h_{2}、W^{\top}_{2,3}。elem 本身以下标结尾时（_{...}，或 _ 加一个字符），元素下标并进这个下标：\mathrm{ms}_{1} 的元素写作 \mathrm{ms}_{1,2}，r_1 写作 r_{1,2}。直接在后面再加一个下标会得到双下标，KaTeX 报错。卡片、连线卡片和 3D 标签都经过同一个函数拼元素名，规则只在这一处；判断 elem 是否以下标结尾的 trailingSubscript 由 explain 入口导出，页面描述文件的编译器用它合并实例下标。默认值：名字是单个字母时 elem 为该字母，tex 对非标量为粗体字母、对标量为字母本身；名字更长时两者都是 \mathrm{名字}。
  • dtype 是这个张量在真实模型里的 dtype，悬停提示、层名卡片和连线卡片都显示它。选项里给了 dtype 时用给出的值，否则：label 是 int64；input、param、buffer 取 graph({ dtype })；运算节点按输入推导，整数和 bool 输入不参与，浮点输入取位数最大的那个，位数相同但类型不同（bf16 与 fp16）时取高一级的 fp32，没有浮点输入时按位数取最宽的整数类型（bool 最窄，uint8 与 int8 混用得到 int16）；fp8_e4m3 与 fp8_e5m2 混用时抛错 add 'x': cannot promote fp8_e4m3 with fp8_e5m2, give the dtype explicitly，torch 对这种组合也报错。这条规则与 torch 的类型提升一致，所以只有模型显式转换类型的地方需要写 dtype，例如 RMSNorm 先转成 float32 计算、最后转回输入的 dtype。
  • grad 对 label 和 buffer 为 null。运算节点在两种情况下 grad 也为 null，与 torch 里不求梯度或梯度为 None 的张量对应：它的每个可求导参数都不依赖 param 或 input（例如 topk_mask 的输出），或者从它到损失没有一条只经过可求导参数的路径（例如只用来挑选专家的分数，以及损失之后创建的节点）。这样的节点不进入自动生成的反向步骤，3D 场景里也不画它的反向连线。param 和 input 总有梯度，不在损失上游时为全零。
  • W.T 是二维节点的转置。第一次访问时创建 transpose 节点并缓存，之后返回同一个节点。g.matmul(h, W.T) 和 board(h, W.T, z) 各取一次 W.T，布局必须找到计算图里的同一个节点，所以缓存不能去掉。转置节点名为 W.T，tex 与 elem 默认在原节点的写法后加 ^{\top}；原写法含 ^、' 或 _ 时先整体加花括号，例如 {W_{q}}^{\top}，否则追加元素下标时会出现双下标。
  • set 只允许 input、param、label、buffer 调用。index 返回 label 的整数值，等于 Math.round(value.get(idx))。

张量

张量用行主序、连续存储的 Float64Array 加 shape 表示，不做 stride 视图。JavaScript 的数本来就是 64 位浮点，PyTorch 对拍数据也用 float64 生成，比较时可以用很小的容差。0 维张量的 shape 是 ()，元素个数为 1。label 同样存成 Float64Array，取值时取整。

数值的显示格式全库统一，由 formatNumber(v, { digits?, tex? }) 给出：给了 digits 时保留这么多位小数；否则 $|v| \ge 100$ 保留 0 位，$|v| \ge 10$ 保留 1 位，$|v| \ge 1$ 保留 2 位，其余保留 3 位。结果是 -0、-0.00 这类时去掉负号。正文里负号写成 U+2212（−），LaTeX 里（tex: true）保留 ASCII 的 -。shape 由 formatShape 写成 (1, 4)、(5,)、()。

重算与通知

拖动滑块、更换目标 token、点「更新一步」都需要当场重算，悬停卡片上的当前值和 3D 场景里的柱子也在运行时从计算图读取，所以计算内核在页面打开期间一直运行。vizflow 处理的张量通常只有几十个元素，重算开销可以忽略。

  • 建图时每创建一个节点，立即算出它的前向值。
  • set 之后同步执行：全部前向、全部反向、version 加一，然后按订阅顺序调用每个订阅者一次。batch 内的 set 只在 batch 结束时执行一次。
  • 反向时所有梯度清零，损失节点的梯度为 1，按创建顺序倒序调用每个运算的 backward，把结果累加到输入节点的梯度上。同一节点被多处使用时梯度相加；不可微的参数跳过。

对外的通知只有 version 和 subscribe，与界面框架无关。Solid 只在 ui 内部把通知转成 signal。

运算怎么定义，怎么与 torch 对齐

命名与参数

张量语义与 PyTorch 一致，包括广播规则、dim 的负数下标、keepdim、reduction='mean'、ignore_index=-100。读者在图里建立的理解可以直接对应到训练代码上。shape 也采用 torch 的约定：行向量写成 $(1,d)$，批量写成 $(B,d)$；nn.Linear 的权重存成 $(V,d)$，前向计算 h @ W.T。

运算的函数名和参数名沿用 torch 的写法，例如 log_softmax、nll_loss、keepdim、ignore_index。JavaScript 没有关键字参数，因此 torch 里按位置传的参数在这里按同样的顺序传，torch 里通常按关键字传的参数放进最后一个选项对象：

torch 里接受数的地方这里也接受数：add、sub、mul、div 的第二个参数可以是数，对应 x + eps、x * scaling。第一个参数仍然必须是节点。数不成为节点，存进节点的 attrs.other，不画连线；卡片公式里直接写这个数，格式与模板的统一数值格式相同（formatNumber(v, { tex: true })，负数加括号），局部导数照常计算，例如 g.mul(x, 0.5) 对 $x$ 的局部导数是 0.5。

选项对象里除了 torch 的关键字参数，还可以写 name 和 NodeOptions 的字段；未知的键抛错。位置参数可以省略，省略时用默认值。库自己的 API（graph、defineOp、mountScene 等）不是 torch 的概念，按 JavaScript 习惯用驼峰命名。页面里下划线命名的是对应 torch 的运算，驼峰命名的是 vizflow 自己的功能。

错误信息用英文，写明运算名、节点名和 shape，例如 matmul: cannot multiply (1, 4) by (5, 4)。shape 不匹配在建图时抛出。

定义新运算

每个运算定义四件事，反向传播和全部讲解内容都由它们推导。数值部分是前向怎么算、反向怎么算（给定输出梯度，求每个输入的梯度）；讲解部分是元素级的连线模式，以及每条边的局部导数（一个数值函数加一段公式模板）。讲解部分放在 explain 模块，只需要数值的场合不会加载。

interface OpDef<A extends object = Record<string, unknown>> {
  name: string;
  args: string[];
  tensors: string[];
  list?: string;
  rest?: string;
  scalars?: string[];
  sizes?: string[];
  defaults?: Partial<A>;
  shape(inputs: number[][], attrs: A): number[];
  forward(inputs: Tensor[], attrs: A): Tensor;
  backward(gradOut: Tensor, inputs: Tensor[], out: Tensor, attrs: A): (Tensor | null)[];
  differentiable?: boolean[];
  explain?: OpExplain;
}
defineOp(def: OpDef): void
  • name 与 torch 同名；args 是 torch 的位置参数名，按 torch 的顺序；tensors 列出其中哪些是张量参数；defaults 是放进选项对象的关键字参数及默认值。
  • differentiable 标出每个张量参数是否求梯度，默认全部求。nll_loss 的 target、gather 的 index、embedding 的 input、where 的 condition、topk_mask 的 input 为 false。label 与 buffer 本身没有梯度，作为任何运算的输入都不求梯度。
  • list 是一个张量参数的名字，这个参数接受节点数组，例如 cat 的 tensors。数组里的节点按顺序展开成运算的输入，forward、backward、shape 收到的输入个数等于数组长度，讲解里的 arg 是节点在数组里的位置。为了让输入下标与参数一一对应，list 必须是唯一的张量参数，并且不能与 differentiable 同时使用；违反时 defineOp 抛错。有限差分报错时这类输入写作 tensors[1]。
  • scalars 列出可以传数的张量参数，例如 add 的 other。传了数时它不成为输入，存进 attrs 的同名字段，forward 收到的输入少一个，运算自己按 attrs 计算。
  • sizes 列出可以写维度名的非张量参数，例如 narrow 的 length。计算 shape 前按 dims 换成数，计算 realShape 前按 real 换成数，规则见上文「尺寸参数可以写维度名」。值是数组时逐个元素换算（view 的 shape）。sizes 也可以列出只在 defaults 里出现的关键字参数（cat 的 pieces）。
  • rest 是最后一个位置参数的名字，调用时多出来的位置参数收成一个数组交给它，所以 g.view(a, T, H, dh) 与 g.view(a, [T, H, dh]) 相同，与 torch 的 x.view(T, H, dh) 写法一致。
  • 重复注册同名运算抛错。注册后的运算在运行时出现在 g 上，可以写成 g.<name>(...)；TypeScript 通过对 interface Graph 的声明合并补充类型。
  • defineOp 可以写在页面里临时使用，也可以放进单独的文件供多个页面共用。加一个运算不需要修改核心库。
  • 运算名不能与 Graph 已有的成员同名（例如 input、loss、node），defineOp 遇到这样的名字抛错，因为 g.<运算名> 会遮蔽这些方法。

正确性怎么保证

反向由运算定义自动推导，它的正确性完全取决于每个运算的定义。库用三道检查发现定义里的错误，每道检查比较不同的两方：

检查比较的两方发现的错误运行时机
有限差分backward 与 forward反向公式写错测试中对所有内置运算；页面打开检查时每次重算之后
PyTorch 对拍vizflow 的前向值与梯度和 PyTorch 的结果前向语义与 torch 不一致测试

有限差分

检查对每个运算节点取一个固定种子生成的上游梯度 $u$（形状同输出），记 $\phi(x) = \langle u, f(x)\rangle$。对每个可微输入的每个元素 $x_j$，按式 \eqref{eq:fd} 计算数值导数 $\tilde g_j$，步长 $\varepsilon = 10^{-6}$，与 backward(u, ...) 给出的第 $j$ 个元素 $g_j$ 比较：

\begin{equation} \tilde g_j = \frac{\phi(x+\varepsilon e_j) - \phi(x-\varepsilon e_j)}{2\varepsilon} \label{eq:fd} \end{equation}

满足式 \eqref{eq:tol} 时通过：

\begin{equation} |g_j - \tilde g_j| \le 10^{-6} + 10^{-4}\,|\tilde g_j| \label{eq:tol} \end{equation}

函数在不可导的点上（例如 max 有并列最大值时）两侧导数不同，中心差分没有意义。检查另算右侧差分 $(\phi(x+\varepsilon e_j) - \phi(x))/\varepsilon$ 与左侧差分 $(\phi(x) - \phi(x-\varepsilon e_j))/\varepsilon$，两者之差超过 $10^{-3}(1 + |\tilde g_j|)$ 时跳过这个元素。这个阈值与式 \eqref{eq:tol} 的容差分开设定：光滑点上两侧差分之差约为 $\varepsilon |\phi''|$，远小于阈值，所以光滑点照常检查。

不通过时抛出 Error，信息写明运算、节点、输入和下标：

gradient check failed: op 'exp' (node 'u'), input 0 'x' at [2]: backward 1.234567 vs numeric 4.567890

检查的开关是 graph({ check })。页面写了 check 时按页面写的值，不写时的默认值取决于页面用的是哪一种产物：

  • 构建工具产物（dist/module/）：默认值为 process.env.NODE_ENV !== 'production'。Vite、webpack 等构建工具在构建页面时把 process.env.NODE_ENV 替换成常量，所以 vite 开发服务器下检查打开，vite build 的生产产物里检查关闭。运行环境里既没有替换也没有 process 时，读取出错，默认值为关闭。
  • 直接引用的产物（dist/*.js）：默认关闭。浏览器直接加载这份产物，读不到构建环境的「开发模式」变量，要检查时页面写 check: true。

检查函数也单独导出为 checkOp(def, inputs, attrs)，测试对所有内置运算调用它。

PyTorch 对拍

有限差分只能说明反向和前向自洽，不能说明前向符合 torch 的语义。仓库里的 Python 脚本用 PyTorch CPU 版计算每个运算和两个示例页面完整计算图的若干组输入、前向值与梯度，导出成 JSON 提交进仓库，JSON 里记录生成时的 torch 版本。测试读取这些 JSON 与 vizflow 的结果逐元素比较，通过条件为 $|a - b| \le 10^{-9} + 10^{-9}\,|b|$，其中 $b$ 是 torch 的值；torch 为 NaN 时 vizflow 也必须是 NaN。PyTorch 只用于生成测试数据，不进入库本身，运行测试也不需要安装 torch。

边求和

悬停卡片上的局部导数和传回的量来自 explain，与 backward 是两份独立的代码。第三道检查把两者绑定：随机输入与随机上游梯度下，每个可微输入元素所有出边的「局部导数 × 上游梯度」之和，应当等于 backward 的结果，通过条件同样为 $|a - b| \le 10^{-9} + 10^{-9}\,|b|$。矩阵乘的边经过乘积格子，按「输入到格子的局部导数 × 格子到输出的局部导数 × 输出的上游梯度」计算。

前向步骤由页面列出，因为前向分几步、每一步讲什么是作者对内容的组织。第 0 步是总览，由 overview 给出，默认标题「总览」。

  • 前向第 $k$ 步（$k \ge 1$）：revealed 为第 1 到 $k$ 步 show 的并集；active 为第 $k$ 步的 active，默认等于 show。总览时全部 revealed、全部 active。
  • visible 是所有 forward.show 的并集，按拓扑序排列。没有放进任何一步的中间节点不显示，也不单独成为反向步骤。
  • 前向按钮文字 label 默认等于 title。按钮文字里的 $...$ 按行内公式渲染，不含 $ 时原样显示为文字。

反向步骤默认自动生成（'auto'）。规则如下：

  1. visible 中可求梯度的节点（label 与 buffer 除外）按拓扑序倒序排列。
  2. 损失节点与它之前第一个可见节点合成第一步，之后每个可见节点一步。lm_head 页因此得到「$\ell$ 与 $\log\mathbf{p}$、LSE、$\mathbf{z}$、$W^{\top}$、$\mathbf{h}$」五步。
  3. merge 中的每组节点并入组内最早出现的那一步。softmax 批量页用 { auto: true, merge: [[l_b, logy, y]] } 把 $\ell$、$\ell_b$、$\log y$、$y$ 放进同一步。
  4. 反向第 $k$ 步：revealed 为第 1 到 $k$ 步节点的并集，active 为第 $k$ 步的节点。

图里没有损失节点时（例如只演示 softmax 的小部件），自动反向生成 0 步；这时给了 merge 或 override 会抛错。

自动步骤的默认标题为 $\partial\ell/\partial X$，$X$ 是节点的 tex（合并的步骤用其中第一个非损失节点），按钮文字默认 $\partial X$，默认正文是该节点反向层名卡片的公式。override 按反向步骤的下标覆盖标题、正文或按钮文字。steps 入口导出 backwardGroups(g, visible, spec)，按反向步骤的顺序返回每一步包含的节点（visible 是前向步骤里出现过的节点），createSteps 和页面描述文件的编译器都用它，所以编译器算出的下标与实际生成的步骤一致。

反向时，如果某条边的上游梯度在结构上恒为零（例如 nll_loss 只取目标类，其余类别的边），这条边的不透明度降低（当前步骤 0.35，总览 0.12），读者可以直接看出哪些路径上没有梯度。所有连线都画成实线：虚线在边很多的场景里会形成大片断续的纹理，干扰阅读，所以只用不透明度区分状态。是否恒为零由 explain 的 zeroGrad(e) 给出，它只依赖图结构和 label 的当前值。

批量模式下 focus 是选中的样本下标，默认 0。setFocus 改变它，下标超出 visible 中节点的行数时抛错；scene3d 据此高亮这一行，正文模板用它代入这一行的数值。切换样本只改变高亮和正文，不改变计算图的数值。

页面没有创建 steps 时，allVisible(g) 给出默认状态：方向为前向，全部显示、全部高亮。

每一步的 id 在折叠状态变化前后保持不变，界面和场景用它判断「是不是同一步」：总览是 f:overview，前向第 $k$ 个步骤声明是 f:k（从 0 起），输入步骤是 f:inputs，反向步骤是 b:k，反向总览是 b:overview，折叠的模块是 F:模块 id 与 B:模块 id。segment 是步骤条上的分段名，默认是按钮文字；sub 是段内小标题；module 是这一步所属的最内层模块。

折叠与反向步骤

一整层 Transformer 有上百个节点，逐个运算讲解时读者看不到结构。页面描述文件编译出的步骤用 backward: 'reverse' 和 modules：每个模块可以折叠成一步，折叠后它的内部节点从图上隐去，只留输入、输出和参数，读者先看整体，再展开感兴趣的模块。JavaScript 页面也可以直接这样写。

  • PageModule 描述一个模块：nodes 是它的运算节点；inputs 是被它使用、但不在模块里的运算节点；params 是它用到的叶子（权重的转置同时带上权重本身）；outputs 是被模块外使用的节点，没有时取最后一个节点；parent 是外层模块的 id。StepModule 另外带分段名、小标题和折叠后那一步的前向、反向文字。
  • 折叠状态的初值是 fixed || folded。folded(id) 读取，setFolded(id, b) 与 setAllFolded(b) 修改，id 不存在时抛错 folded: module 'x' does not exist、setFolded: module 'x' does not exist。fixed 的模块不受这两个方法影响。状态改变后步骤列表重建，然后通知订阅者。
  • 前向：总览之后，kind: 'inputs' 的步骤（有的话）是第 1 步。其余每个步骤声明是一个单元：show 里不是叶子的节点是它算出的节点，没有时取全部 show；它用到的节点是这些节点的输入（权重的转置同时带上权重）；active 默认是两者的并集。叶子指 input、param、label、buffer 和权重的转置（isLeafLike），它们在输入步骤里出现。前向第 $k$ 步的 revealed 是输入步骤的 show 加上到这一步为止各单元算出的节点。
  • 单元所属的模块链上有折叠的模块时，从最外层的折叠模块开始，连续属于它的单元合成一个 kind: 'module' 步骤：显示模块的输出，高亮输出、输入和参数，标题默认「标题（已折叠）」，按钮文字默认是模块标题。
  • 反向：前向的单元和折叠模块倒过来，每个一步。一个单元的反向步骤高亮它用到的节点里有梯度的那些；没有这样的节点时跳过，只有第一步例外。第一步同时包含损失节点。折叠模块的反向步骤高亮它的输入和参数，标题默认「穿过 标题（已折叠）」，按钮文字默认 $\partial$ 标题。单元的默认标题、按钮文字和正文与 'auto' 相同，以第一个收到梯度的节点为主语；只给了标题时正文为空。overview.backward 给出时，反向最后再加一个总览步骤，全部显示、全部高亮。
  • 折叠或展开以后，当前位置尽量保持：依次找 id 相同的步骤、同一方向里节点有重叠的步骤、包含原来那一步的折叠模块步骤，都没有时回到同一方向的第一步。

反向按单元倒序，而不是按节点倒序，是因为读者在前向里按单元建立的分组（例如 RMSNorm 的四步）在反向里应当一一对应；折叠后一个模块只占一步，前向与反向的步数随之一起变化。

正文模板

步骤正文是作者写的 HTML 字符串，其中 $...$ 与 $$...$$ 是公式，双花括号 {{...}} 里的是数值模板。模板用双花括号，与 LaTeX 的单花括号区分，\mathbf{h}、W^{\top}_{k,t} 不是模板。作者写 {{z[t]}}，页面就显示当前值，并在输入变化时更新，正文里代入的数字始终与图上的状态一致。steps.text() 只替换模板，公式由 ui 通过 formula 渲染。steps 同时导出 compileTemplate(g, text): (focus: number) => string，把任意一段文字按同样的规则编译成求值函数。面板的说明文字（损失面板的 text、各面板的 note）在挂载时用它编译，模板写错时 mountPanels 直接抛错。

模板   := '{{' 表达式 (':' 格式)? '}}'
表达式 := 引用 (('+' | '-') 整数)?
引用   := 'b' | 名字 ('.grad')? ('[' 下标 (',' 下标)* ']')?

正文通常写成跨多行的 String.raw 模板字符串，TeX 命令只写一个反斜杠，不需要用 + 拼接，也不需要手写 <p>。Chromium 把两个中文字符之间的换行显示成一个空格，所以库在渲染前整理多行文字，整理由 renderText 完成，步骤正文和各面板的文字因此规则相同：

  • 文字里没有换行时不做任何处理，按原样渲染。
  • 有换行时，先去掉所有行共同的缩进和开头、结尾的空行，再按空行分块。
  • 块内每行去掉行首和行尾的空白。相邻两行按换行前后的两个字符连接：其中一个是 CJK 标点（U+3000 到 U+303F 的 CJK 符号和标点，U+FF00 到 U+FFEF 的全角形式）时直接相连；两个都是 CJK 字符时直接相连；其余情况连接处放一个空格。换行前后紧挨公式或 HTML 标签时，按非 CJK 字符处理。
  • CJK 字符指以下 Unicode 范围：CJK 统一表意文字 U+4E00 到 U+9FFF、扩展 A U+3400 到 U+4DBF、兼容表意文字 U+F900 到 U+FAFF、U+20000 到 U+2FFFF 的扩展区；平假名与片假名 U+3040 到 U+30FF、片假名扩展 U+31F0 到 U+31FF；谚文字母 U+1100 到 U+11FF、谚文兼容字母 U+3130 到 U+318F、谚文音节 U+AC00 到 U+D7AF；以及上面两类 CJK 标点。
  • 整块是一个 $$...$$ 公式时原样保留；以块级标签 p、div、ul、ol、pre、table、h1 到 h6、blockquote、vf-figure 开头的块不再包段落，其中 pre 块保留换行；其余的块包进 <p>。
  • 公式里的换行原样交给 KaTeX，KaTeX 把它当作空白。模板 {{...}} 解析前去掉全部空白，里面可以换行。

换行规则这样定，是因为中文、日文、韩文的词之间不加空格，换行处放空格会显示成多余的空隙；英文和公式之间需要空格。全角标点前后本来就不加空格，所以只要一侧是 CJK 标点就直接相连，例如句号后面接英文单词。作者不需要在行尾留空格，编辑器删除行尾空格也不影响结果。

整理放在 renderText 里，因为面板的 text、note 与卡片说明都经过 renderText，放在这里所有文字只有一套规则。没有换行时不整理，是为了让已有的单行文字渲染结果不变。String.raw 里 ${ 是插值的开头，公式以模板开头时写成 $ {{x}}$。

模板可以写在公式里，例如 $z_{ {{t+1}} } = {{z[t]}}$。模板紧贴 LaTeX 花括号时要留一个空格；出现 {{{ 或 }}} 时报错。

  • 解析前去掉模板内的空白，名字按图中的节点名做最长前缀匹配，因此名字可以含点：{{W.T.grad[0, t]}} 是节点 W.T 的梯度。label 的名字作为下标时取它的整数值，t[b] 取第 b 行。
  • b 是 steps.focus，可以单独使用，例如 样本 {{b+1}}。b 是保留名：图里有名为 b 的节点（例如偏置）而模板用到 b 时，创建 steps 时抛错，要求改名。原因是两种含义无法从模板里区分。
  • 下标从 0 开始。显示从 1 开始的序号时写 {{t+1}}。
  • 格式为整数时表示小数位数，例如 {{loss:3}}；{{t:token}} 输出 tokens[t]。
  • 标量节点可以省略下标；shape 为 $(1,n)$ 的节点只写一个下标时视为 [0, i]，$(n,1)$ 视为 [i, 0]；label 按整数输出。
  • 公式内的数用 formatNumber(v, { tex: true })，公式外用 U+2212 负号。
  • 不能解析的模板在创建 steps 时抛出带模板原文的错误，对 label 或 buffer 取 .grad 也在这时报错。模板只能读取节点的值与梯度，不执行任意 JavaScript。

悬停卡片

悬停卡片分两种，内容都由 explain 根据运算定义生成。ui 和 scene3d 只负责显示，以后增加 2D 渲染时卡片可以直接复用。

层名卡片在悬停层名时出现。

  • 前向：标题为节点的 tex（$\mathbf{z}$）；公式为 tex = 前向模板，例如 $\mathbf{z} = \mathbf{h}W^{\top}$；下面依次列出 shape、真实模型（给了 real 时，写作 Qwen3-8B：(1, 151936)）、dtype、当前值。当前值超过 8 个元素时只列前 8 个，后面加省略号。
  • 反向：标题为 $\frac{\partial\ell}{\partial X}$，$X$ 是节点的 tex；公式是链式法则展开，对节点 $X$ 的每个消费者 $Y$ 写一项（只计结构上通向损失的运算，旁支和损失之后的节点不列，它们的项恒为 0），只有一个消费者时不写求和：
\begin{equation} \frac{\partial\ell}{\partial X} = \sum_{Y} \Big(\frac{\partial Y}{\partial X}\Big)^{\top} \frac{\partial\ell}{\partial Y} \label{eq:chain} \end{equation}

反向卡片的行依次为 shape、真实模型、dtype、Jacobian、当前梯度。Jacobian 每个消费者一行，写作 $\partial Y/\partial X$：(...)，括号里是输出 shape 与输入 shape 各自去掉大小为 1 的维度后拼接，例如 $\partial\mathbf{z}/\partial\mathbf{h}$ 写作 (V, d)。作者在节点的 card 选项里给出的字段覆盖自动内容，没给的字段用自动内容。卡片的标题和各行都按 renderText 渲染，所以只用 LaTeX 写数学符号。

3D 场景显示层名卡片时，用一张数值格子代替「当前值」「当前梯度」和 Jacobian 三行：格子按张量的行列排开（三维张量按 $(T, H d_h)$），前向显示值、反向显示梯度，保留 2 位小数，底色按正负取 --pos 或 --neg，深浅为 8% 加上按这张格子的最大绝对值线性增加的 0 到 62%；列数超过 10 时格子只着色、不写数字。非有限值（mask 的 $-\infty$）写成 $-\infty$，不着色。读者可以在卡片里一次看全整个张量，不必逐个悬停柱子。

连线卡片只在反向时悬停连线出现，分三行：这条边的局部导数、上游传来的梯度、两者相乘后沿这条边传回的量。节点有多条出边时，卡片说明各条边的贡献相加并给出合计，例如 $z_i$ 经 $\log p_i$ 与经 LSE 的两条边相加得到 $p_i - \delta_{it}$。卡片最后一行写传回的梯度的 dtype，等于这条边起点张量的 dtype。

连线模式

每个运算从一个固定的小集合里选一种连线模式，scene3d 根据模式和布局模板决定线怎么画，卡片根据局部导数和公式模板生成文字，两者都不需要知道具体是哪个运算。新运算选定一种模式，就能得到全部讲解内容。

乘积格子只存在于 explain，不是计算图的节点，数值为 $A_{r,k}B_{k,i}$。这样计算图与 torch 保持一致，讲解仍然可以画出「一行乘一列再累加」的过程。每条边有稳定的 id：同一个运算、同一位置的边在 label 变化前后 id 相同，select 模式的 id 用输出下标。

embedding、narrow、cat 选 elementwise 加 selected，不选 select。scene3d 把 select 运算的输入当作按类别对齐的张量，并把输出画成标量节点；embedding 的 weight 按行对应类别，narrow 与 cat 的输出是完整的张量，按 select 处理会画错。

一个张量参数是 label、或在 differentiable 里为 false 时，它的元素没有边，selected 给出的这类元素也被跳过。buffer 参数照常生成边，3D 场景只在前向画这些边，反向跳过。

所有公式模板只使用 KaTeX 和 MathJax 都支持的命令：\frac、\partial、\mathbf、\top、\operatorname、\mathrm、\sum、\log、\exp、\sqrt、\sigma、\Big、\left、\right、\cdot、\times、\to、\delta、\odot、\epsilon、\infty。embedding 的前向公式写作 $E[\mathbf{x}]$，用两个输入节点的 tex；narrow 与 cat 写作 $\operatorname{narrow}(\mathbf{x},1,0,4)$、$\operatorname{cat}(\mathbf{a},\mathbf{b})$；view、select、select_matmul 写作 $\operatorname{view}(\mathbf{x})$、$\operatorname{select}(\mathbf{x},1,0)$、$\operatorname{select}(\mathbf{q},1,h)\,\mathbf{k}$；指数为 2 的 pow 写作 $\mathbf{x}\odot\mathbf{x}$；给了 eps 的 rsqrt 写作 $\frac{1}{\sqrt{a+\epsilon}}$。formatNumber 把 $\pm\infty$ 写成 ∞，LaTeX 里写成 \infty。

场景接受一到三维的张量。三维张量 $(T, H, d_h)$ 画成 $T$ 行、$H d_h$ 列的板，分层布局在每 $d_h$ 列之间多留一道缝表示 head 的分界（见「分层布局」），与 view 只分组、不移动数据的含义一致；超过三维时抛错 scene3d: node 'x' with shape (...) has more than three dimensions。

视觉原则

3D 只用于内容本身具有空间结构的地方，画面保持克制。

  • 坐标轴刻度固定。拖动滑块时只有柱子变化，坐标不重新缩放，读者可以比较前后两个状态。每个张量前向、反向各有一个固定刻度，默认在挂载时由初始值决定：初始值中的最大绝对值对应高度上限的 0.8 倍，非有限值（例如 causal mask 的 $-\infty$）不参与计算，这些元素按截断画。之后刻度不随数值变化，作者也可以在布局模板的选项里直接指定刻度。柱子高度超过上限时截断，截断处留一道 0.07 个单位厚的缝。高度上限按块的种类取：平面张量的柱子 1.2，矩阵乘的权重板 0.85，一维权重 1.0。
  • 颜色只用一组：橙色（--pos）表示正，蓝色（--neg）表示负，前向数值和反向梯度共用。目标类用墨线框标出，不额外占用颜色。
  • 没有辉光、粒子和自动旋转。动效只有三种：数值变化时柱子高度的过渡，模块大括号显示、隐藏和变色时的透明度过渡，时长都是 200 毫秒，缓出；相机跟随时换步骤后的相机过渡，见「相机」。prefers-reduced-motion 时都直接跳到终值。
  • 未出现的柱子高度为 0，不画轮廓线；底板不透明度 0.2，目标列的墨线框 0.15。已出现的柱子轮廓线在当前步骤高亮时为 0.85，其余为 0.32，权重板的轮廓线再乘 0.85；底板 0.5，墨线框 0.95。不在当前步骤的柱子颜色向画布底色混合 55%。标量节点（圆柱和方块）的轮廓线已出现时 0.9，未出现时 0.3。反向时上游梯度恒为零的边不透明度降低，连线都画成实线。
  • 只画最前一行（默认打开，右上角「只画最前一行」切换）：一个运算的边如果都不跨行（每条边两端张量的第 0 维下标相同），只画终点在所在块最前一行（$z$ 最大）的边，其余行的计算相同，全画会让线叠成一片；有跨行边的运算（例如注意力分数、$P\mathbf{v}$）照常画出全部边。悬停一根柱子时，与它相连的边即使不在最前一行也显示并加深。任一端是一维张量的边不受影响。
  • 遮挡半透明（有 steps 时默认打开，右上角「遮挡半透明」切换）：不在当前步骤的块，屏幕包围盒与当前步骤某个已出现的块重叠超过 6px、并且沿视线方向比它近 0.3 个单位以上时，柱子、标量节点和底板的填充不透明度降到 0.15 并且不写深度，轮廓线、底板边框和墨线框乘 0.35，不显示截断缝、刻度轴、标题和数值。当前步骤的块包括这一步高亮的节点、前向时它们的输入、反向时它们的使用者。6px 的阈值让只擦到边缘的块保持原样；0.3 个单位的深度差让同一层并排的块不互相变透明。相机移动或过渡时每帧重新判断。总览步骤和输入步骤不启用。
  • 柱子的数值标签只在已出现并且属于当前步骤的张量上显示，分层布局里 RMSNorm 这类按行归一化的模块内部的中间张量不显示数值；总览步骤所有张量都属于当前步骤。批量时数值标签和标量节点的标签只显示选中样本那一行。每个数值按 formatNumber 的默认规则单独决定小数位数。
  • 只在数值、相机或步骤变化以及过渡进行中时渲染，静止时不重绘。
  • 浏览器不支持 WebGL 时，画布位置显示一行提示，讲解和面板照常可用。

布局模板

张量在场景里的位置由布局模板决定。

模板摆法
stack把几层张量按计算顺序往上叠，高度表示计算的先后。
node放置标量节点，例如 $S$、LSE 和损失。只接受每行最多 1 个元素的节点（形状 ()、(1,)、(B, 1)），其他形状抛错并提示改用 stack。
board矩阵乘专用，按课本的摆法把三个矩阵排在同一块地面上：右侧的矩阵放在后方，左侧的矩阵放在左前方，结果放在右侧矩阵正前方，与它的列对齐。

以 $\mathbf{h}\,(1\times d)\cdot W^{\top}\,(d\times V)=\mathbf{z}\,(1\times V)$ 为例：$h_k$ 连到 $W^{\top}$ 第 $k$ 行的入口，沿这一行经过每个乘积格子；每一列从后往前累加乘积，落到 $z_i$。换成批量时 $\mathbf{h}$ 和 $\mathbf{z}$ 在 $W^{\top}$ 前方排成 $B$ 行，第 0 行在最前，后面的行依次往后，最后一行紧挨 $W^{\top}$，$W^{\top}$ 保持不动。

所有模板都接受位置、间距和缩放参数，例如 board(h, W.T, z, { at: [x, y, z], gap: 0.7 })。默认值不需要调整就能使用，每一项也都可以单独改。board 的 gap 是行距，默认 0.7 个单位；列距为 1.45 个单位；scale 同时缩放行距、列距和各块之间的距离，柱子底面尺寸不变。scales 按节点名指定柱子刻度，覆盖由初始值决定的默认刻度。

board(a, b, out) 的摆法（默认值取自 lm_head 页）：$b$ 为 $(d, V)$，元素 $(k, i)$ 放在 $x = (i - \tfrac{V-1}{2})\cdot 1.45$，$z = 2.9 - 1.3 - (d-1-k)\cdot\mathit{gap}$，第 0 行在最后方；$out$ 的第 $r$ 行放在 $z = 2.9 + 1.4\,(B-1-r)$，第 0 行在最前，最后一行紧挨 $b$，批量行的方向与 stack 一致；列与 $b$ 对齐；$a$ 的第 $r$ 行与 $out$ 同一 $z$，放在左前方 $x = x_0 - 4.3 + 0.95k$。三块各有一块 0.04 厚的浅色底板。$b$ 的行号标签 k=1…d 放在底板左边缘再往左 0.15 处，与各行对齐；$a$ 的列标签 k=1…d 放在地面上、最前一行柱子前方 0.7 处。类别对齐的张量的 token 标签去掉引号，前导空格显示为 ␣。柱子底面：$a$ 0.6×0.6，$b$ 0.58×0.4，$out$ 0.62×0.62。

stack 把节点按顺序往上放。每行元素数大于 1 的张量是「平面张量」，放在上一层上方 level（默认 5.2）处，列与上一层对齐，列数不同时以上一层的 $x$ 中心为中心、按列间距排开，例如 MLP 的 down_proj 输出仍在中间维度那一层正上方；上一层也是平面张量时再往后（$z$ 减小）移 back（默认 0.7），让两层的标签和柱子在斜视角下沿对角线错开。softmax 页用 level: 3.0，单样本 back: 1.7、批量 back: 2.2，层高较小、后移较大，场景在画布中横向展开。批量时第 0 行放在 at 的 $z$ 处，后面的行依次往后（$z$ 减小）间隔 1.4 排开，样本 1 在最前面，与 board 的批量行方向一致。左侧有一条三个整齐刻度的纵轴，放在最左一列再往左 2.0 处、与底板后边缘同一深度，刻度标签在轴的左侧，这一层还没有出现时不画纵轴；放在后边缘、离板足够远，是为了不与板前方的类别标签（例如「1 · 目标」）相交。类别标签放在板前方 0.7 处；某一列的柱子为负、数值标签挂在柱子下方时，这一列的类别标签在屏幕上移到数值标签正下方，两者不重叠。批量时类别标签不标「· 目标」，各行的目标由墨线框标出。每行只有 1 个元素的节点是「标量节点」：由 reduce 或 dense 模式的运算从平面张量得到的（LSE、$S$）放在两层之间的侧面，$x$ 为列右端加 2.6，$z$ 比源张量靠后 back 的一半（默认 0.35），画成半径 0.27、高 0.17 的扁圆柱，批量时各行的圆柱在默认视角下互不重叠；由 select 模式得到的（$y$、nll_loss 的损失）放在源张量目标列正上方 2.6 处（高于柱子的截断高度，节点不会压在最高的柱子上），随目标列移动；其余标量的位置由选项 scalars 决定。默认值 'rise' 让它们继续往上 0.7，一列标量节点保持紧凑，标签由重叠检测挪开。取 'row' 时，跟在侧面标量节点后面的标量（例如 RMSNorm 的 $\mathrm{ms}$、$\mathrm{ms}+\varepsilon$、$r$）与它同高、同一深度，依次往右移 SCALAR_ROW_GAP（3.0 个单位，乘以 scale），排成一行；批量时每行的节点各自排成一行。往上叠时，批量的一列标量在竖直方向占很高的范围，会伸进上一层的底板和标签；3.0 个单位在默认视角下能放下圆柱和它左侧的节点标签（例如 $(\mathrm{ms}_1+10^{-6})_1 = 0.323$），相邻两个节点和标签互不重叠。select 节点上方的一列标量（$\log y$、损失）在两种取值下都往上叠，位置不变。select 节点和它上方的一列标量（例如 $y$、$\log y$ 和损失）把标签放在节点侧面、与节点中心同高，前向与反向相同，不压住上方的节点：标签离节点在屏幕上的轮廓 0.15 个单位（沿默认视角的屏幕水平方向量取，圆柱取半径，方块取它在这个方向上的半宽）；单样本放在右侧，批量放在左侧，因为各行的节点向右后方排开。侧面的 LSE、$S$ 和 node 模板放置的标量节点把标签放在节点上方。由 select 节点经逐元素运算得到、行数相同的标量（例如批量时的 $\log y_b$、$\ell_b$）每行跟随自己那一行的目标列；行数变少的标量（例如对批量取平均的损失）放在列的中间。损失节点画成 1.1×0.5×0.8 的扁方块，其他标量节点画成扁圆柱。

与 label 的类别维对应的张量（列数等于类别数，并且被 label 经 select 运算使用，或是这种张量的上游同列张量）称为「类别对齐」的张量：它们的底板上画出目标列的墨线框，列标签用 token 名，点击它们的柱子可以更换目标。

一个节点只放置一次。已经被前面的布局模板放置的节点出现在 stack 里时作为起点，不重复放置；作为 board 的 a 时留在原处，板上每一行的连线从它的柱顶接过来，所以一个输入可以喂给几块板（Transformer 的 q、k、v 投影共用同一个输入）。例如 [board(h, W.T, z), stack(z, L, logp, loss)] 中，z 由 board 放在地面上，stack 从 z 往上叠放 LSE、$\log\mathbf{p}$ 和损失。

自动布局

节点多的页面（例如 Qwen3 的一整个 decoder 层）手写每个模板的位置很繁琐。autoLayout 按模块层级生成 layout 和 modules，结果直接交给 mountScene，生成的仍然是 stack 和 board 模板，编辑模式照常可用。

type LayoutEntry = { kind: 'node'; node: Node } | LayoutTree | { kind: 'parallel'; branches: LayoutTree[] };
interface LayoutTree { kind: 'module'; title?: string; subtitle?: string; children: LayoutEntry[] }
autoLayout(tree: LayoutTree, steps?: StepsSpec): { layout: LayoutItem[]; modules: SceneModule[]; levels?: LevelPlan }

steps 带有 modules 并且 backward 是 'reverse' 时（页面描述文件编译出的步骤都是这样），autoLayout 不用布局树，改按步骤生成分层布局：layout 为空，levels 是 levelPlan(steps)，modules 来自步骤的模块记录，规则见下一节「分层布局」。否则按下面的规则从布局树生成模板。

children 按计算顺序排列，权重和 buffer 放在第一次用到它的节点前面。parallel 的每个分支是一次重复的计算，例如每个 attention head 一个分支；页面描述文件里 beside 并排的每一项也是一个分支。最外层的树是根，不画大括号；title 为空的树也不画。

  • 主列自下而上。每行元素数大于 1 的节点占一层，层高 4.2；相邻的这类节点连同它们之间的标量节点放进同一个 stack（back 为 0，scalars 为 'row'），标量节点按 stack 的规则放在两层之间的侧面或目标列上方，跟在侧面节点后面的标量排成一行。主列的中心是 $x=0$，每层的第 0 行在 $z=0$。
  • 矩阵乘 $\mathbf{z}=\mathbf{a}B$ 的 $B$ 是二维节点、并且还没有被放置时画成 board(a, B, z)，放在主列当前最高一层的上一层，$\mathbf{z}$ 的第 0 行同样在 $z=0$。这包括 $B$ 是权重转置 W.T 的投影，也包括注意力里的 $\mathbf{q}\mathbf{k}^{\top}$ 和 $P\mathbf{v}$；作为 $B$ 的节点只由这块板放置，主列里不再单独放。只通过 W.T 使用的二维权重 W 不放进场景。连续几块板共用同一个 $\mathbf{a}$ 时（q、k、v 投影，gate 和 up 投影）放在同一层，沿 $x$ 方向依次排开，相邻两块的占位范围之间留 1.0，整组以主列中心为中心。
  • parallel 的每个分支各占一条竖道，从同一层开始往上排，竖道沿 $x$ 方向依次排开，相邻两条的占位范围之间留 1.0，整组以主列中心为中心。分支结束后，主列从各分支最高的一层再往上一层继续。
  • 一维权重（例如 RMSNorm 的 $\boldsymbol{\gamma}$）和 buffer（cos/sin 表、causal mask）放在侧道上：高度与第一个使用它的节点相同，$x$ 方向放在这一层全部内容的右侧，占位范围之间留 1.5。同一层有几个时依次往右排。
  • 标签不参与这里的排布，所以占位范围按估计计算：平面张量左侧算到刻度轴再往左 1.5（块名标签的位置），右侧算到底板边缘；有标量节点放在侧面的层，右侧再算到这一行最右的标量节点再往右 1.5；板的左侧算到底板边缘再往左 1.5（行号和块名标签的位置）。
  • 大括号：根下面第一层有标题的模块放在左侧，更深的放在右侧，与 Qwen3 页一致。每个分支先按这些规则列出自己的模块，parallel 各个分支里排在同一位置的模块合并成一个大括号，节点取并集，标题取各分支里不同的标题，按分支顺序用 · 连接，副标题同样处理。两个 head 的 q_norm 标题相同，合并后仍是 q_norm；q 竖道和并排的 k 竖道合并成 q_norm · k_norm；for 的 brace 给出的每次迭代的标题（例如 head 1、head 2）也合并成一个括号。这样同样高度不会并排几个括号。模块的节点包括它的树里的全部节点和这些节点所在板上的 $B$；一个都没有放进场景的模块不输出。

分层布局

分层布局按前向步骤把场景排成一列自下而上的「层」，每一层是一个 $y$ 高度，层里的块沿 $x$ 方向排开。它与讲解的步骤一一对应：读者在第几步，相机就停在哪几层；模块折叠时它的层收进一个盒子。levelPlan(steps) 在挂载前算出层和列，resolve({ folded, aligned }) 在每次折叠状态变化时按当前的折叠状态算出各层的高度、盒子和大括号的范围，场景据此重建。

层怎么分。

  • 每个前向单元（输入步骤以外的步骤声明里算出的节点）占自己的几层，单元内按依赖深度分层：不依赖本单元其他节点的在第一层，依赖它们的往上一层。
  • matmul 与 select_matmul 画成板：$B$ 画成权重板放在输出所在的层，输出的每一列对着 $B$ 的一列。$B$ 是权重（或权重的转置）的线性层，如果输入 $A$ 只被下一个单元的板使用、并且这些板的 $A$ 都是它，$A$ 移到板的那一层，与板并排（例如 q、k、v 投影共用一个输入）。$B$ 是激活（注意力里的 $\mathbf{k}^{\top}$、$\mathbf{v}$）时，$B$ 移到板的那一层。
  • embedding 的输出与 embedding 表画在同一层，表画成权重板。
  • view 节点不单独画，图上用它的源节点代表它，块的标题写成 view 的 tex = 源节点的 tex。
  • 一个节点在某个顶层模块里算出、在另一个模块里被使用时，使用的模块里画一份副本：副本独占一层，放在第一个使用它的单元之前；被线性层的板当作 $A$ 使用时，副本放在板的那一层。原件和副本之间画一条连线，已出现时不透明度 0.32，否则 0.06。读者在每个模块的入口都能看到这个模块拿到的输入，不必回头找。
  • 一维权重（RMSNorm 的 $\boldsymbol{\gamma}$）和 buffer 放在使用它的节点所在的层。

块的种类。平面张量画成柱子板（plate）；矩阵乘的 $B$ 和 embedding 表画成权重板（tile），放在板层的后方；一维权重画成一排柱子（vector），放在这一层后方；每行一个数、并且被更宽的逐元素运算使用的张量（RMSNorm 的 $\mathrm{ms}$、$r$，softmax 的 $Z$）画成圆柱（disc），放在源张量右侧；0 维的损失画成方块（box）。三维张量按 $(T, H d_h)$ 画，每个 head 的 $d_h$ 列之间多留一道缝；一个节点被 narrow 按固定宽度切开使用时也按这个宽度分组。

列怎么排。主列（残差流）从 $x = -7.2$ 开始，列距 0.95。板放在 $A$ 的右侧，留 1.45；板的列距是 $11.4 / \text{列数}$，限制在 0.74 到 1.45 之间，几块共用 $A$ 的板接着排开，板与板之间留一道缝。逐元素运算的输出与第一个输入的列对齐；narrow 与按 head 取出的 select 对齐到被取出的那几列；cat 把各输入的列接起来。

相机

相机采用正交投影，避免透视变形影响对高度的判断。相机有两种模式：默认的全图取景，以及 camera.follow: true 的相机跟随。两种模式下读者都可以在小范围内旋转，鼠标右键拖动（触屏双指）在屏幕平面内平移；按住 Ctrl 或 Meta 再滚动滚轮才缩放，缩放以画面中心为准，缩放倍数乘 $e^{-0.0025\,\Delta y}$（$\Delta y$ 是滚动量），停止滚动 120 毫秒后刷新标签。不按修饰键的滚轮交给页面滚动，读者滚动长页面经过画布时页面不会停住。场景右上角的「复位视角」回到默认方向和当前的取景。下表是默认值；mountScene 的 camera 选项可以覆盖斜视方向（direction）、相对初始方位角的水平旋转范围（azimuth）、极角范围（polar）和缩放范围（zoom）。softmax 页用它给出自己的数值：方向 $(0.62,\ 0.5,\ 1)$，水平 $-0.75$ 到 $+0.6$ 弧度，极角 $0.55$ 到 $1.5$ 弧度。

全图取景。取景根据所有元素与标签的包围盒在相机坐标下的投影自动计算，元素移动或缩放后不需要手动调整相机：几何体的投影四周留 12px，每个标签按它的像素尺寸和锚点计入，外沿离画布边缘也留 12px，在这个约束下取能放下全部内容的最大缩放，内容尽量填满画布。放在节点上方的节点标签按「翻到节点左侧」的位置计入，所以画布右侧不必为它们预留宽度；放在节点侧面的标签按实际位置计入。节点标签的宽度取前向与反向两种文字中较宽的一种，切换步骤时不需要重新取景。挂载、画布尺寸变化、字体加载完成与「复位视角」时重新取景。柱子按取景时的实际高度计入；读者拖动滑块让柱子变高时不重新取景，避免画面随数值跳动，柱子超出画布时按「复位视角」重新取景。

相机跟随。块很多的图（例如 Qwen3 从 token 到损失的一整页）放进一屏时每个块都太小，读者看不清正在讲的内容，所以跟随模式用固定的比例尺，上下移动相机去看当前步骤的那几层，场景比画面宽时也左右移动：

  • 比例尺：缩放为 1 时每个单位 44 像素；画布很窄时保证至少能看到 35.2 个单位宽，即视锥的半高取 $\max(H/88,\ 17.6/\text{宽高比})$，$H$ 是画布高度的像素数。水平方向和深度方向的取景中心默认是全图的中心，不随步骤变化。
  • 场景比画面宽时水平跟随：把全部块、标签锚点和大括号投影到屏幕水平方向（与斜视方向和竖直方向都垂直的水平向量），场景的范围超过视锥宽度减去两侧各 4 个单位时，取景中心沿这个方向移到当前步骤高亮块的范围中点，并限制在场景两端往里各半个视锥宽度再加 4 个单位以内，画面不移出场景。当前步骤的块比画面宽时（例如 Qwen3.5 的 q_proj 输出宽一倍），缩放再取 $\min$ 于「视锥宽度减 8 个单位」与这些块宽度之比。场景能放进画面时（例如 Qwen3 一层的页面），取景与上一条相同。4 个单位留给左侧大括号的标题。
  • 每次步骤变化后，目标高度是当前步骤高亮块所在层的 $y$ 范围中点再往上 0.9，缩放是 $\min(1,\ 2h/(\Delta y + 10))$，$h$ 是视锥的半高、$\Delta y$ 是这个范围的高度，所以跨几层的步骤会缩小一些，单层的步骤保持原尺寸。目标高度限制在 $[\,y_{\min} + 0.82\,h' - 2,\ y_{\max} - 0.82\,h' + 1\,]$，$y_{\min}$、$y_{\max}$ 是最低层和场景顶部，$h'$ 是按目标缩放算出的半高，画面不会移到场景以外。
  • 总览步骤、输入步骤和没有高亮块的步骤看全图：高度是全图的中点，缩放是 $\min(1,\ 2h/(\text{全图高度} + 6))$。
  • 相机每帧向目标靠近剩余距离的 $1 - e^{-9\,\Delta t}$，高度差小于 0.01 并且缩放差小于 0.002 时停止；prefers-reduced-motion 时直接跳到目标。读者用滚轮缩放时取消这次过渡。
  • 总览步骤和输入步骤只画块和外层的大括号：不显示块的标题、数值、连线和内层（left）大括号，大括号标签不显示副标题和折叠按钮，读者先看整体结构。
  • 远处淡出（默认打开，右上角「远处淡出」切换）：与当前步骤高亮的运算块相距超过 2 层、并且不在当前步骤的块向底色混合 88%（标量节点 85%），轮廓线降到 0.08，底板降到 0.1，不显示标题，两端都在远处的连线不画。
  • 数值标签在缩放不小于 0.55 时才显示；板上最前一行以外的行在缩放不小于 1.45 时才显示。
  • 标签不做重叠检测；锚点投影超出画布 1.2 倍范围（标准化设备坐标的绝对值大于 1.2）的标签不显示。
  • 右上角的工具按钮依次是「跳到模块…」（列出全部大括号，点击后相机移到那个模块的中部，缩放为 1）、「远处淡出」、「遮挡半透明」（有步骤时）、「只画最前一行」、「全部折叠」「全部展开」（有步骤和模块时）和「复位视角」。按钮按下时表示功能打开，这几个开关的含义见「视觉原则」与上面的远处淡出。画布左下角有上一步、下一步按钮，中间写着「前向」或「反向」、段内小标题和这一步的按钮文字，读者不必滚回步骤条也能翻页。

模块大括号

modules 在图的两侧用竖直的大括号标出模块，例如 Qwen3 一层里的 RMSNorm、Attention、MLP。每个模块的大括号在三维场景里画成折线，与连线使用相同的线条材质和线宽：上下两端各有一个向图一侧弯的小钩，中点有一个指向外侧的尖角，括号宽 0.42 个单位，钩和尖角的圆弧半径为 0.45 个单位，模块很矮时缩到竖直范围的四分之一（最小 0.05），每段弧用 14 段折线。标题（衬线字体，15px，按 renderText 渲染，可以含公式）、副标题（等宽字体，10.5px，--muted 色）和折叠按钮（11px，--pos 色，模块可以折叠时才有）上下排列，放在尖角外侧：side 为 'left'（默认）时右对齐在尖角左边，'right' 和 'outer' 时左对齐在尖角右边。斜视时括号的竖直位置随视角的仰角平移（最小斜率 0.2），让尖角在屏幕上对准模块的块。

这一节的规则用于布局模板生成的场景。分层布局的大括号由 levels 给出竖直范围和 $x$ 位置，见「分层布局」；颜色、显示状态和标签的规则与这里相同。

  • 竖直范围：模块的节点中已经放进布局并且可见（steps.visible）的块，下端是这些块的最低处，即底板的 $y$ 再往下 0.4；上端是最高处，柱子按这个块的高度上限计、圆柱和方块按自身高度计，再往上 0.4。
  • 水平位置：大括号竖直地放在整个场景的左侧或右侧，$x$ 取全部可见块（含底板和标签锚点）的 $x$ 范围外侧再留 1.6 个单位，$z$ 取这个模块自己的块的 $z$ 范围中心，括号与它标出的块在同一深度，跟随取景时不会因为离块太远而落到画面外。位置不随步骤变化，读者对照各步时括号不跳动。
  • 嵌套与错开：模块 B 的 nodes 是模块 A 的 nodes 的真子集时 B 在 A 里面，同一侧越外层的括号离图越远，每层再往外 2.2 个单位；同一侧互不包含、竖直范围重叠的模块也错开到不同的列，各自取不与已放置的括号冲突的最内一列。
  • 显示状态：模块的节点在当前步骤一个都还没出现时，大括号和标签都不显示；有节点出现时显示，括号用 --line-strong 色、标题用 --muted 色；当前步骤的高亮块里有这个模块的节点时，括号用 --ink 色、透明度 0.55，标题用 --ink 色。括号的显示和变色用 200 毫秒的透明度过渡，标签用与其他标签相同的透明度过渡。主题切换时重新读取颜色。
  • 标签参与标签避让，优先级与块标题相同（5），可以移动；全图取景时计入全部模块的括号和标签，跟随取景时不计入模块。
  • nodes 里没有放进布局的节点忽略；一个都没有时抛错 modules: '<title>' has no placed node。
  • 编辑模式不能拖动大括号，「复制配置」不输出 modules。

标签与交互

层名、数值、刻度、token 等标签用 HTML 覆盖在画布上，按投影位置放置，公式由 KaTeX 渲染。标签投影到屏幕后先处理越界：放在节点上方的节点标签右端超出画布（离右边缘不足 12px）时翻到节点左侧，右端对齐节点中心；左端越界时翻到右侧。放在节点侧面的标签不翻转，取景已为它们留出位置。锚点投影到画布以外的标签不显示，读者平移、缩放或跟随取景以后，画面外的块不会把标签挤到画布边缘。然后做一次重叠检测：按优先级（块标题与模块标签 5、节点标签 4、数值 3、类别 2、行号与刻度 1）依次放置；块标题、模块标签和节点标签可以移动，与已放置的标签相交时按上、下、左、右的顺序以 4px 为步长尝试平移，最多 12 步，取第一个不相交、并且离画布边缘至少 12px 的位置，找不到时隐藏这个标签，它不占位置，后放置的标签可以用它原来的地方；读者用 labels 指定了偏移的标签不移动也不隐藏，按指定位置显示；其余标签不移动，与已放置的标签相交或越出安全区时隐藏。优先级高的标签先放置，所以被隐藏的是优先级低的标签。隐藏只影响显示，自动取景仍按全部标签的原位计算，切换步骤或转动视角后有了空位的标签重新显示。标签的像素尺寸在文字或样式变化时测量一次并缓存，字体加载完成后重新测量；每帧只做投影和重叠检测。位置只在相机、布局或数值变化时重新计算。相机跟随时不做重叠检测，见「相机」。块的标题写节点的 tex，反向时写 $\partial\ell/\partial$ 加节点的 tex。

元素之间的连线是竖直切线的三次贝塞尔曲线，两个控制点沿竖直方向离端点两端高度差的 0.45 倍，起点向上、终点向下，不会在端点处回钩。高度差超过 4.2 的长连线在深度方向弯出去，控制点改为高度差的 0.3 倍：默认向前弯 0.9；连到权重板（板的 $B$）的向后弯 2.6；连到残差相加（add）的向前弯 1.8。长连线因此不穿过中间各层的块。

悬停柱子的提示依次显示元素名（反向时是 $\partial\ell/\partial$ 元素名）、类别对齐的列的 token 名、当前值（保留 3 位小数，$-\infty$ 写成 $-\infty$）、节点名和 dtype（写作 节点名 · bf16），可以点击设为目标的柱子最后写「点击设为目标 token」（label 只给了 classes 时为「点击设为目标类」）。连线卡片只在反向时出现，取屏幕空间距离 6px 以内最近的一条已出现的边。卡片优先放在指针右下 18px，越界时翻到另一侧。

  • 悬停柱子显示数值提示；悬停层名显示层名卡片。
  • 悬停柱子时，起点或终点是这个元素的连线不透明度提到至少 0.95，其余连线乘 0.3，读者能直接看出这个元素从哪里来、流向哪里。有 token 轴的张量，再在和这个元素同一个 token 的那些元素（token 轴上的下标相同，$(T, d)$ 的张量是一行，$(T, H, d_h)$ 的张量是所有 head 的这一行）底下画一个框：框比这些柱子的底面外扩 0.12，填充 --pos，不透明度 0.3，边线 0.9，抬高 0.012 以免与底板重叠。哪个轴是 token 按运算的语义沿计算图推导，不比较尺寸：input 和 label 的第 0 轴是 token；param 和 buffer 没有 token 轴；逐元素运算按广播把输入的 token 轴对到输出；matmul 保留左操作数没有被收缩的 token 轴，右操作数的 token 轴是最后一维时成为输出的最后一维；transpose 交换、select 去掉或前移、view 在前面各维的乘积不变时保留这个轴；embedding 沿用索引的 token 轴；softmax 与 log_softmax 保留，sum、mean、max、logsumexp 沿 token 轴归约时去掉，否则按 keepdim 平移；没有列出规则的运算没有 token 轴。所以 $\mathbf{k}^{\top}$ 的 token 轴是第 1 维，悬停时框出的是一列；$T$ 与 $d_h$ 相等时结果也不变。
  • 反向时悬停连线显示连线卡片，并加粗这条连线。
  • 前向时点击 logits 或 $\log\mathbf{p}$ 的柱子，把它设为目标类，即更新对应的 label 节点；批量时同时选中这一行的样本。页面有序列输入（sequence 选项），并且这个 label 的值是序列里连续的一段时，改的是序列里对应位置的 token：标签是输入右移一位，所以输入和标签一起变化，图上其他位置的预测也随之改变。提示里的 token 名与类别标签相同，不加引号，前导空格显示为 ␣。
  • 悬停层名显示层名卡片，点击层名把卡片固定住；buffer 是 $(T, d_h)$ 的 RoPE cos 或 sin 表时，前向卡片里还画出 rope_wave 小图。
  • 场景订阅 theme，主题切换时重新读取颜色。

编辑模式

自动取景和标签避让之后，作者仍然需要微调位置。mountScene(el, g, { edit: true }) 打开编辑模式，只在作者写页面时使用。编辑模式在画布右下角显示可以折叠的「编辑布局」面板。面板展开时，自动取景把面板左边缘到画布右边缘的宽度从可用宽度中扣除（最多扣到画布宽度的一半），场景放在面板左侧；面板折叠后取景恢复使用整个画布宽度。面板支持以下操作：

  • 拖动张量块：按住块的柱子、圆柱或底板，在水平面内移动。结果写进放置这个块的模板：board 的三个块一起移动，写成 board 的 at；node 模板写成它的 at；stack 里直接从 at 起放置的第一层写成 stack 的 at，其余各层写成 stack 的 offsets。坐标保留两位小数。
  • 调整间距：面板里每个 board 有 gap、scale 两个数值输入，每个 stack 有 level、back，步长 0.05，输入后场景立即重排。
  • 移动标签：拖动块名标签或标量节点的标签，结果写成 mountScene 的 labels，单位为像素，取整数。因找不到空位而隐藏的标签不接收指针事件，不能拖动。
  • 「设为默认视角」：把当前的相机方向（从观察目标指向相机，各分量保留两位小数）写成 camera.direction，视角回到这个方向下的自动取景。缩放不写入配置，取景始终自动计算。
  • 「复制配置」：在面板的文本框里显示 layout、camera、labels 三项的代码，同时尝试写进剪贴板；按钮旁显示「已复制」或「请从文本框复制」，2 秒后淡出（prefers-reduced-motion 时直接消失）。文本框不折行，可以横向滚动。代码是 mountScene 选项对象里的属性，替换页面里原来的这几项即可。节点写成 g.node('节点名')，g 是页面里图的变量名；camera、labels 没有内容时不输出。

每次拖动结束或数值变化后，视角回到默认方向并重新自动取景，所以编辑模式里看到的位置与把配置粘贴回页面后打开时一致。拖动过程中不重新取景，块跟随指针移动。

编辑模式写出的两个选项也可以手写：

  • stack 的 offsets：按节点名把这个 stack 放置的某一层整体平移 $[dx, dy, dz]$，包括柱子、底板、刻度轴和标签；后面以这一层为起点的层跟着平移，前面的层不动。例如 stack(z, L, logp, loss, { offsets: { 'log p': [1, 0, -0.5] } }) 移动 $\log\mathbf{p}$ 和它上方的损失，LSE 不动。
  • mountScene 的 labels：按节点名把块名标签（柱子块）或节点标签（标量节点，批量时每一行）从锚点处的原始位置平移 $[dx, dy]$ 像素，$x$ 向右、$y$ 向下。给出偏移的标签不再左右翻转，也不参与避让移动；其他标签照常避开它。自动取景按偏移后的位置计入这些标签。

位置的最终来源始终是页面里的配置代码。编辑模式不保存任何状态，不使用浏览器存储，所以不存在两份需要同步的配置。只有页面代码里写了 edit: true 时才出现编辑界面，没有快捷键或网址参数可以打开它，看图的人不能进入编辑模式，发布出去的页面布局是固定的。edit 省略或为 false 时不创建任何编辑相关的元素和事件监听。

面板与页面布局

挂载

每个带界面的模块只提供 mount(容器, ...) 形式的入口，只在页面给出的容器里渲染，铺满容器，并在容器尺寸变化时重排。模块不决定页面布局，页面可以把它们放在任何位置。只有 element 入口按固定的布局组合这几个 mount，见「页面元素」。每个 mount 返回带 dispose() 的句柄，用于释放监听和 WebGL 资源。scene3d 的 dispose() 还会主动释放 WebGL 上下文，页面反复挂载和释放场景时不会耗尽浏览器允许的上下文数量。

mountSteps(el: string | HTMLElement, steps: Steps): Mounted
mountPanels(el: string | HTMLElement, g: Graph, items: PanelItem[], options?: { steps?: Steps; sequence?: PageSequence }): Mounted
mountSections(el: string | HTMLElement, g: Graph, items: SectionItem[], options?: { steps?: Steps; onJump?: () => void }): Mounted
interface Mounted { dispose(): void }

mountSteps 画出步骤条、左右按钮和讲解正文，正文里的 <vf-figure> 换成内置小图。步骤条有两种样式。steps.modules 为空时是前向、反向两组按钮。不为空时是时间轴：第一行是「前向」「反向」两个标签页、一条分段进度条和「当前位置/总步数」，进度条按当前方向的步骤的 segment 把相邻的同名步骤分成一段，每段的宽度与段内步数成正比，当前段内按位置填充，点击一段跳到它的第一步；第二行是当前段的名字（折叠模块的段后加「（已折叠）」）、段内各步的按钮，sub 变化处插入小标题。几十步的页面用分段代替一长排按钮，读者能看出自己在哪个模块里。

指针移到进度条的一段上（或用键盘聚焦它）时，这一段上方弹出一张小卡片，箭头指向这一段：第一行是段名和状态，状态是「第 i / n 步」（当前段，用 --pos 着色）、「n 步」（还没到）或「n 步 · 已完成」；下面最多列出 5 个步骤的按钮文字，已完成的圆点实心，当前步用 --pos；段内多于 5 步时列出当前步附近的 5 步，前后各写「前 k 步」「后 k 步」。只有一步、且按钮文字等于段名时不列步骤。读者不用点进去就能知道每一段讲什么。

键盘的左右方向键切换步骤。焦点在输入框或步骤条以外的按钮上，或按着 Alt、Ctrl、Meta 时不响应；焦点在步骤条自己的按钮上时照常切换。同一页有多个步骤条时，只有最近一次点击或聚焦落在其中的那个响应方向键，点击步骤条以外的地方不改变这一选择。

步骤按钮的左右内边距为 9px，桌面宽度下 lm_head 页的 11 个按钮在约 860px 宽的步骤卡片里排成一行。步骤卡片宽度不超过 560px 时按钮排成一行横向滚动，右端 24px 渐隐，提示还可以往右滚。讲解正文和面板里的独立公式块超出宽度时在公式块内横向滚动，不截断。

面板

面板拆成单独的小部件，页面只挂载需要的几个，可以放在侧栏、画布下方或正文里。第一版只组合这些现成的面板，不支持在页面里编写新的面板。

面板内容
loss损失读数与损失曲线。sgd 加一个「更新一步」按钮，对 params 中的每个节点执行一次 $\theta \leftarrow \theta - \eta\,\nabla_\theta \ell$，$\eta$ 为 lr，曲线记录每一步的损失。random 加一个按钮，把 nodes 的值在 range 内随机取值。buffer 是常量，放进 params 或 nodes 时挂载就抛错 loss panel: buffer 'M' is a constant without gradient and cannot be in sgd.params；reset 为 true 时加一个调用 g.reset() 的按钮。text 是读数下方的一行说明，写法与步骤正文的模板相同，例如 目标 "{{t:token}}"，log p = {{log p[t]}}。除「更新一步」以外的任何输入变化都会清空曲线。parts 是逐位置的损失节点（例如 reduction="none" 的 $\ell_t$），读数下面每个位置一行 $\ell_t$。hint 是还没有曲线时曲线位置上的提示文字。「更新一步」按钮的文字后面自动加「（$\eta = $ 学习率）」。
sliders一个输入节点的每个元素一个滑块。
tokenstoken 与目标类表，每行一个类别，单选设为目标类。columns 列出要并排显示的节点值或梯度；给了 sliders 时每行再带一个滑块，用于 softmax 页按类别调 logits。token 的前导空格显示为 ␣；数值列显示三位小数，梯度列按正负着色。
matrix矩阵热力图，单元格颜色按正负取 --pos 或 --neg，深浅表示大小。grad: true 显示梯度；highlight 是 label 节点，框出目标类所在的列；写成 { node: t, axis: 'row' } 时框出目标类所在的行，例如 Jacobian 只有第 $t$ 行参与损失。label 有 tokens 且类别数等于列数时，列表头显示 token，否则显示 1 起的序号。数值显示两位小数，显示为 0.00 的格子不着色；颜色深浅按挂载时这张矩阵的最大绝对值换算，limit 直接给出这个值，之后不变，读者可以比较更新前后的深浅。highlight: { node, all: true } 框出 label 里出现的每一个类别的列。rows 是行表头的 tex，第 $i$ 行写成它加下标 $i$（例如 $h_1$），没有时写序号。caption 是矩阵上方的图注。note 是卡片底部的说明文字。也可以传入一个从图上取值的函数，函数的参数是计算图与当前的 steps 状态（没有挂载 steps 时 focus 为 0），例如 softmax 页用 { matrix: (g, state) => g.jacobian(p, x, { row: state.focus }) } 显示当前样本的 Jacobian $\operatorname{diag}(\mathbf{p}) - \mathbf{p}\mathbf{p}^{\top}$，它不是计算图里的节点。
matrices同一张卡片里并排放几个矩阵，例如 $W^{\top}$ 和它的梯度。每个矩阵有自己的 grad、caption、limit，highlight、rows、title、note 是整张卡片共用的。
attention注意力权重表，每个 head 一个方阵并排，行和列的表头是 ids 的 token。右上角（列号大于行号）是被 causal mask 挡住的位置，显示为 ·。颜色深浅按 1 换算，因为注意力权重在 0 到 1 之间。节点不是方阵时抛错 attention panel: node 'x' must be a square matrix, got shape (...)。
sequence序列面板，需要 mountPanels 的 sequence 选项，否则抛错 sequence panel: mountPanels needs the sequence option。每个位置一个下拉框选 token，labels 是各位置的标签（默认写序号）。sgd 与损失面板相同；random 加一个「随机序列」按钮；reset 加一个「重置」按钮，调用 g.reset() 并恢复挂载时的序列。
code代码卡片，例如对应的 PyTorch 代码。# 到行尾显示为注释色。
note一段说明文字，可以写公式和数值模板。

面板的标题、列标题、按钮文字、序列标签和图注都按 renderText 渲染，数学符号只用 LaTeX 写；默认标题里的节点名用节点的 tex，例如 matrix 面板的默认标题是 $W^{\top}$，(4, 5)。

mountSections 画出页面描述文件的讲解段落（SectionItem，见 vizflow 页面描述文件 的「讲解段落」）。每段是一张卡片，行按 CSS 网格分栏，窄屏下各栏上下排列。正文用 renderMarkdown 渲染，可以写模板，随数值更新；lead 是字号稍大的开头段落。内置组件：rope_dial 画两个随位置 $t$、$s$ 转动的箭头（实线是旋转后的 $\mathbf{q}'$、$\mathbf{k}'$，虚线是旋转前），rope_curve 画一个 head 的点积随 $t-s$ 变化的曲线，两者共用段落的 rope 数据和同一组滑块状态；rope_compare 并排比较每个 head 加与不加 RoPE 的打分和权重；buttons 的每个按钮跳到第一个显示 go 节点的前向步骤，没有这样的步骤时跳到 go 所在模块折叠后的那一步，然后调用 onJump（元素用它把画布滚进视野）。没有传 steps 时按钮抛错 section: buttons need the steps option，找不到步骤时抛错 section: node 'x' is not shown by any forward step；段落没有 rope 却用了 RoPE 组件时抛错 section: rope_dial needs the section's rope option。

ui 内部用 Solid：计算图一更新，面板、步骤条、正文和卡片里许多零散的位置需要各自刷新，Solid 的细粒度响应式让每处只在自己读到的值变化时更新。Solid 只是内部实现，页面通过 mount 调用，不需要编译 JSX，手写 HTML 的静态站可以直接使用。3D 场景用 three.js 命令式编写，不经过 Solid。

  • graph 是计算图，steps 是 createSteps 的第二个参数，panels 是 mountPanels 的面板列表，scene 是 mountScene 的选项（不含 steps 与 edit，元素自己传入），edit 对应场景的编辑模式，默认 false。sections 是 mountSections 的段落列表，sequence 交给 mountPanels 的 sequence 选项。
  • 元素在文档中且 graph 与 steps 都已设置时挂载。panels 不设置时不画面板，sections 不设置时不画讲解段落，scene 不设置时不画 3D 场景。
  • 设置属性后，元素在当前任务的微任务里重新挂载一次：先释放已有的场景、步骤条、面板和 Steps，再按全部属性重新创建。页面连续设置几个属性只挂载一次。读取 createdSteps 时，如果还有待处理的挂载，先同步完成挂载再返回，所以页面设置完属性后可以立即调用 page.createdSteps.go(3)。
  • 设置了 scene 时，元素用动态 import() 加载 scene3d，加载完成后再挂载 3D 场景；没有设置 scene 的页面不加载 three.js。步骤条和面板同步挂载，createdSteps 也同步可用。场景加载完成之前元素被移除或重新挂载时，这次加载的结果不再挂载。场景挂载出错时（例如布局里的节点形状不符合模板），元素释放已挂载的全部内容，并用 reportError 报告这个错误，错误出现在控制台。
  • createdSteps 是元素创建的 Steps，只读；未挂载时为 undefined。每次重新挂载都换成新的对象。
  • 元素从文档移除时（disconnectedCallback）释放全部内容，包括 WebGL 上下文和计算图上的订阅；再次加入文档时重新挂载。
  • 元素用 light DOM，不用 shadow root。theme、KaTeX、ui 与 scene3d 的样式注入在 document 里，shadow root 内的节点用不到这些样式。元素只移除自己创建的布局节点。
  • customElements.define 只在 vizflow-page 尚未定义时调用，同一页面加载两次入口不会报错。属性在元素定义之前就已设置时，元素升级后照常读取。

从页面描述文件加载。页面写 <vizflow-page src="page.yaml">，或设置 JavaScript 属性 src（它与 HTML 属性同步）。

  • 设置 src 后，元素用动态 import() 加载 dsl 与 scene3d，以 document.baseURI 为基准把 src 解析成绝对地址，调用 loadPage 编译，再用 autoLayout(compiled.tree, compiled.steps) 算出布局、分层布局和模块大括号。没有设置 src 的页面不加载 YAML 解析器。
  • 编译完成后，元素把 graph、steps、panels（列表为空时不画面板）、sections（列表为空时不画）、sequence 和 scene（layout、modules、levels、sequence、hint、camera）设为编译结果并立即挂载，然后派发 load 事件。compiled 是编译结果，未加载完成时为 undefined。
  • 从 src 挂载时，元素在布局前面放一个 header.vf-header：h1.vf-title 是页面的 title，按纯文本显示；p.vf-lede 是 lede，用 renderText 渲染公式。页面之后又直接设置了 graph 时不画这个标题。
  • 读取或编译出错时，元素清空自己的内容，显示一段 p.vf-load-error，文字是 src: 错误信息，并用 reportError 报告错误。
  • 加载完成之前 src 又被改变时，只采用最后一次加载的结果。

元素里的布局与 lm_head 示例页相同：有面板时外层是 .vf-split，没有面板时是 .vf-stack；左栏 .vf-main 是纵向排列、间距 14px 的 flex 容器，依次放画布 .vf-stage、步骤条 .vf-steps 和讲解段落 .vf-article；面板放在 aside.vf-side。讲解段落里的跳转按钮把画布平滑滚动到视野顶部。.vf-stage 高度为 var(--vf-stage-height)，最小高度 400px，视口宽度 980px 以下为 360px，圆角 14px，带 --line 色边框和 --surface 底色。这些样式由 element 入口注入，只作用于 vizflow-page 内部。用 JavaScript 属性挂载时，标题、导语等页面自己的内容写在元素外面；从 src 加载时由元素画出，.vf-header 下边距 20px、最大宽度 760px，标题用衬线字体，字号 clamp(28px, 3.6vw, 40px)，导语用 --muted 色。

公式怎么渲染

第一版只用 KaTeX，但其他模块不直接调用 KaTeX，统一通过 formula 的接口渲染，KaTeX 是接口的一个适配器。接口按异步渲染设计：调用方先拿到一个占位元素，适配器渲染完成后填充。KaTeX 本身是同步的；以后加入渲染为异步的 MathJax 时，只需要新写一个适配器。

interface FormulaAdapter { render(tex: string, display: boolean, target: HTMLElement): void | Promise<void> }
render(tex: string, options?: { display?: boolean }): HTMLElement
renderText(html: string, target: HTMLElement): void
renderMarkdown(source: string, target: HTMLElement): void
setAdapter(adapter: FormulaAdapter): void
katexAdapter: FormulaAdapter
  • render 立即返回占位元素 <span class="vf-tex">。
  • renderText 把正文中的 $...$、$$...$$ 换成 render 的结果，其余部分按 HTML 插入。文字含换行时先按「正文模板」一节的规则整理成段落。
  • renderMarkdown 用同样的规则整理段落，另外把以 1 到 6 个 # 加空格开头的块写成对应级别的标题，把 `代码` 写成 <code>、**粗体** 写成 <b>。讲解段落的正文用它渲染。
  • 独立公式在最外层（不在花括号、\begin...\end 或 \left...\right 里面）的每个 \qquad 处拆开，各段分别按独立公式渲染，放进一个可以换行的横排容器 .vf-display-row，段间距 2em。正文里常把几个矩阵用 \qquad 并排写在一个公式里，窄屏下拆开后可以各自换到下一行，不用横向滚动。
  • 行内公式后面紧跟的中文收尾标点（，。、；：！？）」』》〉）与公式放在一个不换行的容器里，标点不会单独换到下一行的开头。
  • KaTeX 的 \arraystretch 设为 1.1，矩阵的行距比默认值略大。
  • KaTeX 适配器按（公式，是否 display）缓存渲染结果。渲染出错时不抛出，占位元素显示原始 TeX 并加 vf-tex-error 类。
  • KaTeX 的 CSS 由 formula 入口引入。
  • 公式模板只使用 KaTeX 和 MathJax 都支持的写法，命令列表见「连线模式」一节末尾。

打包与引用

库用 Vite 的库模式打包，输出 ES module 和类型声明。npm run build 构建两份产物，分别给两种引用方式使用，入口相同，入口之间共用的代码都拆成公共 chunk：

产物给谁用第三方库字体有限差分检查的默认值
dist/module/*.js用 npm 和构建工具（Vite、webpack 等）的项目，exports 的 import 指向它three.js、Solid、KaTeX、yaml、@fontsource 保留为 import，由构建工具解析import @fontsource 与 KaTeX 的 CSS 文件，字体由构建工具输出开发模式打开，生产构建关闭
dist/*.js不用构建工具的静态站，通过 jsDelivr 引用或复制 dist/打包进产物输出到 dist/fonts/，代码按自身地址请求关闭

element 入口在两份产物里都有：用构建工具时写 import '@yhnocoder/vizflow/element'，不用构建工具时引用 dist/element.js。element 只用动态 import() 引用 dsl，src/nn/ 下的核心模块文件用 Vite 的 ?raw 以文本打进 dsl 入口，两份产物都不需要另外复制 YAML 文件。

两份产物的类型声明都是 dist/types/，exports 的 types 指向它，公开的类型声明不引用 three.js、Solid、KaTeX。

构建工具产物

构建工具产物不打包第三方库，所以 three.js、Solid、KaTeX 和三个 @fontsource 字体包列在 package.json 的 dependencies，安装 vizflow 时一起安装。页面自己也引用 three.js 时，构建工具把两边的 import 解析到同一份 three.js，页面里只有一个实例，不会出现 three.js 的「Multiple instances」警告；打包进产物时页面会有两份。

字体通过 import CSS 文件交付：theme 引入 @fontsource 的 CSS，formula 的 KaTeX 适配引入 katex/dist/katex.min.css，CSS 里的 url() 由构建工具处理，开发服务器和生产构建的字体都能正常加载。不用按 import.meta.url 计算字体地址的原因是：Vite 开发服务器会把依赖预打包到缓存目录，模块地址随之改变，按模块地址算出的字体路径就不存在了。

检查的默认值写成 process.env.NODE_ENV !== 'production'，因为 Vite 和 webpack 都会替换这个表达式。库模式构建时 Vite 保留 process.env.*，不在库自己的构建里替换，留给页面的构建工具。

源码里与产物有关的三个模块各有一个 .module.ts 版本：字体（theme/fonts）、KaTeX 样式（formula/katex-style）和检查默认值（autograd/check-default）。构建工具产物用 .module.ts 版本，直接引用的产物、开发服务器和测试用原版本。

直接引用的产物

静态站可以直接 import 这份产物，不需要 import map。three.js、Solid、KaTeX 打包进产物，three.js 只在引用 scene3d 时加载，KaTeX 只在引用 formula（包括间接引用）时加载，yaml 打包在 dsl.js 里，只在引用 dsl 或元素设置了 src 时加载。

字体文件输出到 dist/fonts/，包括 KaTeX 的字体和 @fontsource 的 Source Serif 4、Geist、Geist Mono，全部是 woff2。theme 与 formula 的代码以自身所在文件的地址为基准请求 fonts/ 下的文件，所以入口文件和 chunk 都放在 dist/ 根目录，复制产物时 fonts/ 要和它们保持在同一目录。

版本号遵循 semver，静态站固定引用某个版本。产物可以复制进静态站，也可以通过 jsDelivr 按版本号和文件路径引用。jsDelivr 按文件路径取文件，不经过 exports，所以 exports 指向构建工具产物不影响这种写法：

import { graph } from 'https://cdn.jsdelivr.net/npm/@yhnocoder/vizflow@0.1.0/dist/core.js';

sideEffects 与测试

注入样式或注册自定义元素的模块（theme 及其字体模块、ui、formula 的 KaTeX 样式模块、scene3d、element）和两份产物的 .js 文件在 sideEffects 中列出，否则构建会把只为注入样式而写的 import 删掉。
