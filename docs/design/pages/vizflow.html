vizflow 设计 第一版

vizflow（npm 包名 @yhnocoder/vizflow）是一个用来编写交互式计算图讲解页面的 JavaScript 库。页面用声明式的 API 描述张量、运算、布局和讲解，库负责前向与反向计算、自动推导反向传播的每一步、悬停卡片、3D 场景和面板。本文档写页面怎么写、各模块的接口、影响显示和数值的常量，以及改动时容易被破坏的设计决定。

页面里不写任何反向代码和连线代码。反向步骤、每条边的局部导数和每张卡片都由库根据运算定义推导，并由有限差分、PyTorch 对拍、边求和三道检查保证正确。

vizflow 解决什么问题

vizflow 来自两张手写的交互式计算图：一张讲 softmax 与交叉熵，一张讲 Qwen3 的 lm_head 与 NLL Loss。手写的页面有两个问题。第一，两个页面大部分代码相同，但每次重写的刻度、标签位置、卡片措辞都略有不同，读者在页面之间切换时会感到不一致。第二，反向传播的每条边、每张卡片都是手写的，图越复杂越容易写错，而这类错误读者最难发现。vizflow 把重复的部分收进库里，页面只描述自己独有的内容；反向传播由库从运算定义推导。

库只规定页面怎么写，页面讲什么由调用方决定。库提供计算图模型、运算定义、布局模板和渲染方式；一张图里有哪些张量、讲哪几步、每一步写什么，都写在调用方的页面里。vizflow 有自己的仓库、文档、示例和测试，打包后供静态站使用，静态站固定引用某个版本。库升级不影响已经写好的页面，页面需要新功能时改版本号。

为什么用 JavaScript 库描述页面

页面由作者和 Claude 共同编写，多数时候作者在 Claude 生成的代码上修改，所以可调试性比语法简洁更重要。JavaScript 有编辑器高亮、补全和报错，可以在浏览器里打断点；专门设计的文本格式需要另写解析器，报错难以看懂，遇到没有设计过的需求时也无法用一段自定义代码处理。

页面只调用一套声明式 API。样式、刻度、悬停、步进的逻辑只存在于库里，页面没有地方写出差异，一致性由此保证。库用 TypeScript 编写并输出类型声明，页面作者写普通 JavaScript 时编辑器也能给出补全和提示。

脚本按「建图、写讲解、挂载界面」三段写：

import { graph } from '@yhnocoder/vizflow/core';
import { createSteps } from '@yhnocoder/vizflow/steps';
import { mountScene, board, stack } from '@yhnocoder/vizflow/scene3d';
import { mountSteps, mountPanels } from '@yhnocoder/vizflow/ui';

const g = graph({
  dims: { d: 4, V: 5 },
  real: { d: 4096, V: 151936, name: 'Qwen3-8B' },
});

const h = g.input('h', [1, 'd'], [0.8, -1.1, 0.5, 1.4]);
const W = g.param('W', ['V', 'd'], [
  [ 0.9, -0.6,  0.3,  0.6],
  [ 0.2, -0.8,  0.6,  0.2],
  [-0.4,  0.2,  0.9,  0.3],
  [ 0.5,  0.7, -0.6, -0.2],
  [-0.7,  0.4, -0.3, -0.5],
], { tex: 'W', elem: 'W' });
const t = g.label('t', [0], { tokens: [' mat', ' floor', ' sofa', ' dog', ' sat'] });

const z    = g.matmul(h, W.T, { name: 'z' });
const L    = g.logsumexp(z, -1, { keepdim: true, name: 'LSE' });
const logp = g.sub(z, L, { name: 'log p', tex: '\\log\\mathbf{p}', elem: '\\log p' });
const loss = g.nll_loss(logp, t, { name: 'loss', tex: '\\ell', elem: '\\ell' });

const steps = createSteps(g, {
  overview: {
    title: '整张图',
    text: '目标 token 是 {{t:token}}。'
      + '$$\\ell = -\\log\\operatorname{softmax}(\\mathbf{h}W^{\\top})_t = \\mathrm{LSE}(\\mathbf{z}) - z_t = {{loss:3}}$$',
  },
  forward: [
    { show: [h, W.T], label: 'h, Wᵀ', title: '输入：h 和 Wᵀ',
      text: '$W$ 按 PyTorch 存成 $(V,d)$，前向计算 <code>h @ W.T</code>，图里画的是 $W^{\\top}$。' },
    { show: z, active: [h, W.T, z], label: 'z = hWᵀ', title: 'lm_head：z = hWᵀ',
      text: '$h_k$ 沿 $W^{\\top}$ 的第 $k$ 行经过每个方块，每一列从后往前累加。'
        + '$$z_{ {{t+1}} } = \\sum_k h_k W^{\\top}_{k, {{t+1}} } = {{z[t]}}$$' },
    { show: L, label: 'LSE', title: 'log-sum-exp',
      text: '先减去最大值 $m$ 再取指数，最大的一项是 $e^0 = 1$，不会溢出。'
        + '$$\\mathrm{LSE} = m + \\log\\sum_j e^{z_j - m} = {{LSE}}$$' },
    { show: logp, label: 'log p', title: 'log_softmax',
      text: '每个 logit 减去同一个 LSE。'
        + '$$\\log p_{ {{t+1}} } = z_{ {{t+1}} } - \\mathrm{LSE} = {{log p[t]}}$$' },
    { show: loss, label: 'ℓ', title: 'nll_loss',
      text: 'nll_loss 按标签取出一个元素再取负号。$$\\ell = -\\log p_t = {{loss:3}}$$' },
  ],
  backward: 'auto',
});

const PYTORCH = `logits = lm_head(h)
logp = F.log_softmax(logits.float(), dim=-1)
loss = F.nll_loss(logp, t)`;

mountSteps('#steps', steps);
mountScene('#stage', g, {
  steps,
  layout: [board(h, W.T, z), stack(z, L, logp, loss)],
});
mountPanels('#side', g, [
  { loss: {
      sgd: { params: [W], lr: 0.5, label: '更新一步 W' },
      random: { nodes: [h], range: [-2, 2] },
      reset: true,
  } },
  { sliders: h, min: -2.5, max: 2.5, step: 0.01, title: '隐状态 h' },
  { tokens: t, columns: [z, logp, { node: z, grad: true, title: '∂ℓ/∂z' }], title: '目标 token' },
  { matrix: W.T, highlight: t, title: 'Wᵀ' },
  { matrix: W.T, grad: true, highlight: t, title: '∂ℓ/∂Wᵀ' },
  { code: PYTORCH, title: 'PyTorch' },
], { steps });

页面里写的只有这些。反向的五个步骤（$\ell$ 与 $\log\mathbf{p}$、LSE、$\mathbf{z}$、$W^{\top}$、$\mathbf{h}$）、每条边的悬停卡片、每个张量的层名卡片，都由库根据计算图推导。

页面用 ES module 加载，不能通过 file:// 直接打开，本地预览时需要启动一个 http server。

模块怎么划分，各入口加载什么

模块按用途拆开，因为很多场合只需要其中一部分。只需要数值时，例如在笔记里放一张梯度表或者写测试，只引入 core，three.js、Solid、KaTeX 都不会加载。只想在文章里嵌一个带滑块的 softmax 小部件时，引入 core 和 ui，不需要 3D。完整的一页才用到全部模块。

依赖方向是单向的：tensor ← autograd ← explain ← steps；ui 依赖 autograd、steps、formula、theme；scene3d 依赖 autograd、explain、steps、formula、theme。模块之间只通过各自目录的 index.ts 引用。

入口内容加载的第三方依赖
@yhnocoder/vizflow/coretensor 与 autograd：张量、计算图、运算注册、有限差分检查无
@yhnocoder/vizflow/explain每个运算的连线模式、局部导数、公式模板、卡片内容无
@yhnocoder/vizflow/steps步骤状态与正文模板无
@yhnocoder/vizflow/formula公式渲染接口与 KaTeX 适配器KaTeX 及其 CSS
@yhnocoder/vizflow/theme颜色变量、字体、页面布局类Source Serif 4、Geist、Geist Mono 字体文件
@yhnocoder/vizflow/ui步骤条、讲解正文、面板、悬停卡片Solid、KaTeX
@yhnocoder/vizflow/scene3d3D 渲染、布局模板、相机、标签、编辑模式three.js、KaTeX

模块之间不直接调用，都围绕同一个计算图协作。计算图是唯一的数据来源：输入变化后它重算前向和反向，然后发出更新通知；3D 场景、面板和讲解正文各自订阅通知、读取需要的数值，彼此不知道对方是否存在。steps 只输出一个状态对象，说明当前方向、第几步、每个节点是否出现和是否高亮。scene3d 读取这个状态决定颜色和透明度；页面没有创建 steps 时，scene3d 使用「全部显示」的默认状态。

库不使用模块级可变状态，所有状态挂在计算图实例和 mount 返回的句柄上，同一个页面可以放两张互不干扰的图。例外有以下几处：运算注册表与讲解注册表（定义本身不可变，与 torch 的全局算子表同理）；formula 的当前适配器（setAdapter）与 KaTeX 渲染缓存；theme、ui、scene3d 与 formula 注入 <style> 时按 id 判断，同一页面只注入一次。

计算图怎么建，输入变化后怎么更新

建图

graph(options?: {
  dims?: Record<string, number>;
  real?: { name?: string } & Record<string, number | string>;
  check?: boolean;
}): Graph

interface NodeOptions {
  tex?: string;
  elem?: string;
  card?: { forward?: Partial<CardText>; backward?: Partial<CardText> };
}
interface CardText { title: string; tex: string[]; note: string }

interface Graph {
  readonly dims: Readonly<Record<string, number>>;
  readonly real: Readonly<Record<string, number | string>> | undefined;
  readonly nodes: readonly Node[];
  readonly version: number;
  input(name: string, shape: (number | string)[], values: Nested, options?: NodeOptions): Node;
  param(name: string, shape: (number | string)[], values: Nested, options?: NodeOptions): Node;
  label(name: string, values: Nested, options?: NodeOptions & { tokens?: string[]; classes?: number }): Node;
  loss(node?: Node): Node;
  findLoss(): Node | undefined;
  node(name: string): Node | undefined;
  subscribe(fn: () => void): () => void;
  batch(fn: () => void): void;
  reset(): void;
  jacobian(out: Node, input: Node, options?: { row?: number }): Tensor;
}
选项或方法行为
dims命名维度，例如 { d: 4, V: 5 }。shape 中的字符串在建图时解析成数字，未定义的名字抛错。
real真实模型的尺寸，例如 { d: 4096, V: 151936, name: 'Qwen3-8B' }。每个节点的 realShape 用这些尺寸重算，层名卡片多显示一行「真实模型」。
check打开有限差分检查，见「正确性怎么保证」。
input、param叶子节点。values 可以是扁平数组或嵌套数组，元素个数必须等于 shape 的元素个数。两者的区别是 param 可以被损失面板的「更新一步」更新。
label整数标签，shape 从 values 推断：0 是 ()，[0] 是 (1,)，[[0],[1],[2]] 是 (3, 1)。tokens 是每个类别的显示名，classes 是类别数，默认等于 tokens.length。
loss、findLossloss(node) 指定损失节点。findLoss() 返回当前损失节点：指定过时返回指定的节点，否则取最后创建的、元素个数为 1 的运算节点，都没有时返回 undefined。不传参数的 loss() 与 findLoss() 相同，但没有损失节点时抛错；steps、explain 与 scene3d 用 findLoss() 判断一个节点是否是损失。
node按名字查找节点，比较时忽略空白，'log p' 与 'logp' 相同。
batchfn 内的多次 set 合并成一次重算和一次通知。
reset所有叶子节点恢复创建时的值。
jacobian当前值下 out 对 input 的完整 Jacobian，shape 为 out.shape 接上 input.shape。给出 row 时只取第一维第 row 行的块：输出与输入的第一维必须相同，结果 shape 为两者各自去掉第一维后拼接，批量 softmax 页用它显示当前样本的 $(V, V)$ Jacobian。结果不是计算图的节点，供矩阵面板显示，例如 softmax 页的 $\operatorname{diag}(\mathbf{p}) - \mathbf{p}\mathbf{p}^{\top}$。

节点名重复时抛错。运算节点不给 name 时自动命名为运算名加序号，例如 exp1。

节点

class Node {
  readonly id: number;
  readonly graph: Graph;
  readonly kind: 'input' | 'param' | 'label' | 'op';
  readonly name: string;
  readonly op: string | undefined;
  readonly inputs: readonly Node[];
  readonly attrs: Readonly<Record<string, unknown>>;
  readonly shape: readonly number[];
  readonly realShape: readonly number[];
  readonly tex: string;
  readonly elem: string;
  readonly tokens: readonly string[] | undefined;
  readonly card: NodeOptions['card'];
  get value(): Tensor;
  get grad(): Tensor | null;
  get T(): Node;
  set(values: Nested): void;
  index(...idx: number[]): number;
}
  • tex 是张量级的 LaTeX，例如 \mathbf{h}；elem 是元素级的底，元素写作 elem 加下标，下标从 1 开始，例如 h_{2}、W^{\top}_{2,3}。默认值：名字是单个字母时 elem 为该字母，tex 对非标量为粗体字母、对标量为字母本身；名字更长时两者都是 \mathrm{名字}。
  • grad 对 label 为 null；不在损失上游的节点，以及损失之后创建的节点，梯度为全零。
  • W.T 是二维节点的转置。第一次访问时创建 transpose 节点并缓存，之后返回同一个节点。g.matmul(h, W.T) 和 board(h, W.T, z) 各取一次 W.T，布局必须找到计算图里的同一个节点，所以缓存不能去掉。转置节点名为 W.T，tex 与 elem 默认在原节点的写法后加 ^{\top}。
  • set 只允许 input、param、label 调用。index 返回 label 的整数值，等于 Math.round(value.get(idx))。

张量

张量用行主序、连续存储的 Float64Array 加 shape 表示，不做 stride 视图。JavaScript 的数本来就是 64 位浮点，PyTorch 对拍数据也用 float64 生成，比较时可以用很小的容差。0 维张量的 shape 是 ()，元素个数为 1。label 同样存成 Float64Array，取值时取整。

数值的显示格式全库统一，由 formatNumber(v, { digits?, tex? }) 给出：给了 digits 时保留这么多位小数；否则 $|v| \ge 100$ 保留 0 位，$|v| \ge 10$ 保留 1 位，$|v| \ge 1$ 保留 2 位，其余保留 3 位。结果是 -0、-0.00 这类时去掉负号。正文里负号写成 U+2212（−），LaTeX 里（tex: true）保留 ASCII 的 -。shape 由 formatShape 写成 (1, 4)、(5,)、()。

重算与通知

拖动滑块、更换目标 token、点「更新一步」都需要当场重算，悬停卡片上的当前值和 3D 场景里的柱子也在运行时从计算图读取，所以计算内核在页面打开期间一直运行。vizflow 处理的张量通常只有几十个元素，重算开销可以忽略。

  • 建图时每创建一个节点，立即算出它的前向值。
  • set 之后同步执行：全部前向、全部反向、version 加一，然后按订阅顺序调用每个订阅者一次。batch 内的 set 只在 batch 结束时执行一次。
  • 反向时所有梯度清零，损失节点的梯度为 1，按创建顺序倒序调用每个运算的 backward，把结果累加到输入节点的梯度上。同一节点被多处使用时梯度相加；不可微的参数跳过。

对外的通知只有 version 和 subscribe，与界面框架无关。Solid 只在 ui 内部把通知转成 signal。

运算怎么定义，怎么与 torch 对齐

命名与参数

张量语义与 PyTorch 一致，包括广播规则、dim 的负数下标、keepdim、reduction='mean'、ignore_index=-100。读者在图里建立的理解可以直接对应到训练代码上。shape 也采用 torch 的约定：行向量写成 $(1,d)$，批量写成 $(B,d)$；nn.Linear 的权重存成 $(V,d)$，前向计算 h @ W.T。

运算的函数名和参数名沿用 torch 的写法，例如 log_softmax、nll_loss、keepdim、ignore_index。JavaScript 没有关键字参数，因此 torch 里按位置传的参数在这里按同样的顺序传，torch 里通常按关键字传的参数放进最后一个选项对象：

PyTorchvizflow
torch.logsumexp(z, dim=-1, keepdim=True)g.logsumexp(z, -1, { keepdim: true })
F.nll_loss(logp, t, ignore_index=-100)g.nll_loss(logp, t, { ignore_index: -100 })

选项对象里除了 torch 的关键字参数，还可以写 name 和 NodeOptions 的字段；未知的键抛错。位置参数可以省略，省略时用默认值。库自己的 API（graph、defineOp、mountScene 等）不是 torch 的概念，按 JavaScript 习惯用驼峰命名。页面里下划线命名的是对应 torch 的运算，驼峰命名的是 vizflow 自己的功能。

错误信息用英文，写明运算名、节点名和 shape，例如 matmul: cannot multiply (1, 4) by (5, 4)。shape 不匹配在建图时抛出。

第一版内置运算

运算集合由两个示例页面决定。反向只支持一阶导数，不支持高阶导数、in-place 操作和 GPU。所有运算只支持 float64。

运算调用说明
add、sub、mul、divg.add(a, b)广播。反向把梯度按广播过的维度求和回输入的 shape。

matmulg.matmul(a, b)2 维乘 2 维，以及 1 维与 2 维的组合，按 torch 规则

logsumexp、softmax 这类运算在 vizflow 里是原子运算，不拆成基础运算组合，因为读者要在图上看到 LSE 是一个节点。

定义新运算

每个运算定义四件事，反向传播和全部讲解内容都由它们推导。数值部分是前向怎么算、反向怎么算（给定输出梯度，求每个输入的梯度）；讲解部分是元素级的连线模式，以及每条边的局部导数（一个数值函数加一段公式模板）。讲解部分放在 explain 模块，只需要数值的场合不会加载。

interface OpDef<A extends object = Record<string, unknown>> {
  name: string;
  args: string[];
  tensors: string[];
  defaults?: Partial<A>;
  shape(inputs: number[][], attrs: A): number[];
  forward(inputs: Tensor[], attrs: A): Tensor;
  backward(gradOut: Tensor, inputs: Tensor[], out: Tensor, attrs: A): (Tensor | null)[];
  differentiable?: boolean[];
  explain?: OpExplain;
}
defineOp(def: OpDef): void
  • name 与 torch 同名；args 是 torch 的位置参数名，按 torch 的顺序；tensors 列出其中哪些是张量参数；defaults 是放进选项对象的关键字参数及默认值。
  • differentiable 标出每个张量参数是否求梯度，默认全部求。nll_loss 的 target 与 gather 的 index 为 false。
  • 重复注册同名运算抛错。注册后的运算在运行时出现在 g 上，可以写成 g.<name>(...)；TypeScript 通过对 interface Graph 的声明合并补充类型。
  • defineOp 可以写在页面里临时使用，也可以放进单独的文件供多个页面共用。加一个运算不需要修改核心库。
  • 运算名不能与 Graph 已有的成员同名（例如 input、loss、node），defineOp 遇到这样的名字抛错，因为 g.<运算名> 会遮蔽这些方法。

正确性怎么保证

反向由运算定义自动推导，它的正确性完全取决于每个运算的定义。库用三道检查发现定义里的错误，每道检查比较不同的两方：

检查比较的两方发现的错误运行时机
有限差分backward 与 forward反向公式写错测试中对所有内置运算；页面打开检查时每次重算之后
PyTorch 对拍vizflow 的前向值与梯度和 PyTorch 的结果前向语义与 torch 不一致测试
边求和explain 的局部导数与 backward卡片上的局部导数、传回的量与真实梯度不一致测试中对所有带 explain 的运算

有限差分

检查对每个运算节点取一个固定种子生成的上游梯度 $u$（形状同输出），记 $\phi(x) = \langle u, f(x)\rangle$。对每个可微输入的每个元素 $x_j$，按式 \eqref{eq:fd} 计算数值导数 $\tilde g_j$，步长 $\varepsilon = 10^{-6}$，与 backward(u, ...) 给出的第 $j$ 个元素 $g_j$ 比较：

\begin{equation} \tilde g_j = \frac{\phi(x+\varepsilon e_j) - \phi(x-\varepsilon e_j)}{2\varepsilon} \label{eq:fd} \end{equation}

满足式 \eqref{eq:tol} 时通过：

\begin{equation} |g_j - \tilde g_j| \le 10^{-6} + 10^{-4}\,|\tilde g_j| \label{eq:tol} \end{equation}

函数在不可导的点上（例如 max 有并列最大值时）两侧导数不同，中心差分没有意义。检查另算右侧差分 $(\phi(x+\varepsilon e_j) - \phi(x))/\varepsilon$ 与左侧差分 $(\phi(x) - \phi(x-\varepsilon e_j))/\varepsilon$，两者之差超过 $10^{-3}(1 + |\tilde g_j|)$ 时跳过这个元素。这个阈值与式 \eqref{eq:tol} 的容差分开设定：光滑点上两侧差分之差约为 $\varepsilon |\phi''|$，远小于阈值，所以光滑点照常检查。

不通过时抛出 Error，信息写明运算、节点、输入和下标：

gradient check failed: op 'exp' (node 'u'), input 0 'x' at [2]: backward 1.234567 vs numeric 4.567890

检查的开关是 graph({ check })。页面写了 check 时按页面写的值，不写时的默认值取决于页面用的是哪一种产物：

  • 构建工具产物（dist/module/）：默认值为 process.env.NODE_ENV !== 'production'。Vite、webpack 等构建工具在构建页面时把 process.env.NODE_ENV 替换成常量，所以 vite 开发服务器下检查打开，vite build 的生产产物里检查关闭。运行环境里既没有替换也没有 process 时，读取出错，默认值为关闭。
  • 直接引用的产物（dist/*.js）：默认关闭。浏览器直接加载这份产物，读不到构建环境的「开发模式」变量，要检查时页面写 check: true。

检查函数也单独导出为 checkOp(def, inputs, attrs)，测试对所有内置运算调用它。

PyTorch 对拍

有限差分只能说明反向和前向自洽，不能说明前向符合 torch 的语义。仓库里的 Python 脚本用 PyTorch CPU 版计算每个运算和两个示例页面完整计算图的若干组输入、前向值与梯度，导出成 JSON 提交进仓库，JSON 里记录生成时的 torch 版本。测试读取这些 JSON 与 vizflow 的结果逐元素比较，通过条件为 $|a - b| \le 10^{-9} + 10^{-9}\,|b|$，其中 $b$ 是 torch 的值；torch 为 NaN 时 vizflow 也必须是 NaN。PyTorch 只用于生成测试数据，不进入库本身，运行测试也不需要安装 torch。

边求和

悬停卡片上的局部导数和传回的量来自 explain，与 backward 是两份独立的代码。第三道检查把两者绑定：随机输入与随机上游梯度下，每个可微输入元素所有出边的「局部导数 × 上游梯度」之和，应当等于 backward 的结果，通过条件同样为 $|a - b| \le 10^{-9} + 10^{-9}\,|b|$。矩阵乘的边经过乘积格子，按「输入到格子的局部导数 × 格子到输出的局部导数 × 输出的上游梯度」计算。

前向步骤由页面列出，因为前向分几步、每一步讲什么是作者对内容的组织。第 0 步是总览，由 overview 给出，默认标题「总览」。

  • 前向第 $k$ 步（$k \ge 1$）：revealed 为第 1 到 $k$ 步 show 的并集；active 为第 $k$ 步的 active，默认等于 show。总览时全部 revealed、全部 active。
  • visible 是所有 forward.show 的并集，按拓扑序排列。没有放进任何一步的中间节点不显示，也不单独成为反向步骤。
  • 前向按钮文字 label 默认等于 title。

反向步骤默认自动生成（'auto'）。规则如下：

  1. visible 中可求梯度的节点按拓扑序倒序排列。
  2. 损失节点与它之前第一个可见节点合成第一步，之后每个可见节点一步。lm_head 页因此得到「$\ell$ 与 $\log\mathbf{p}$、LSE、$\mathbf{z}$、$W^{\top}$、$\mathbf{h}$」五步。
  3. merge 中的每组节点并入组内最早出现的那一步。softmax 批量页用 { auto: true, merge: [[l_b, logy, y]] } 把 $\ell$、$\ell_b$、$\log y$、$y$ 放进同一步。
  4. 反向第 $k$ 步：revealed 为第 1 到 $k$ 步节点的并集，active 为第 $k$ 步的节点。

图里没有损失节点时（例如只演示 softmax 的小部件），自动反向生成 0 步；这时给了 merge 或 override 会抛错。

自动步骤的默认标题为 ∂ℓ/∂节点名（合并的步骤用其中第一个非损失节点），按钮文字默认 ∂节点名，默认正文是该节点反向层名卡片的公式。override 按反向步骤的下标覆盖标题、正文或按钮文字。

反向时，如果某条边的上游梯度在结构上恒为零（例如 nll_loss 只取目标类，其余类别的边），这条边画成虚线，读者可以直接看出哪些路径上没有梯度。是否恒为零由 explain 的 zeroGrad(e) 给出，它只依赖图结构和 label 的当前值。

批量模式下 focus 是选中的样本下标，默认 0。setFocus 改变它，下标超出 visible 中节点的行数时抛错；scene3d 据此高亮这一行，正文模板用它代入这一行的数值。切换样本只改变高亮和正文，不改变计算图的数值。

页面没有创建 steps 时，allVisible(g) 给出默认状态：方向为前向，全部显示、全部高亮。

正文模板

步骤正文是作者写的 HTML 字符串，其中 $...$ 与 $$...$$ 是公式，双花括号 {{...}} 里的是数值模板。模板用双花括号，与 LaTeX 的单花括号区分，\mathbf{h}、W^{\top}_{k,t} 不是模板。作者写 {{z[t]}}，页面就显示当前值，并在输入变化时更新，正文里代入的数字始终与图上的状态一致。steps.text() 只替换模板，公式由 ui 通过 formula 渲染。steps 同时导出 compileTemplate(g, text): (focus: number) => string，把任意一段文字按同样的规则编译成求值函数。面板的说明文字（损失面板的 text、各面板的 note）在挂载时用它编译，模板写错时 mountPanels 直接抛错。

模板   := '{{' 表达式 (':' 格式)? '}}'
表达式 := 引用 (('+' | '-') 整数)?
引用   := 'b' | 名字 ('.grad')? ('[' 下标 (',' 下标)* ']')?
下标   := 整数 | 'b' | 名字 | 名字 '[' 'b' ']'
格式   := 整数 | 'token'

模板可以写在公式里，例如 $z_{ {{t+1}} } = {{z[t]}}$。模板紧贴 LaTeX 花括号时要留一个空格；出现 {{{ 或 }}} 时报错。

  • 解析前去掉模板内的空白，名字按图中的节点名做最长前缀匹配，因此名字可以含点：{{W.T.grad[0, t]}} 是节点 W.T 的梯度。label 的名字作为下标时取它的整数值，t[b] 取第 b 行。
  • b 是 steps.focus，可以单独使用，例如 样本 {{b+1}}。b 是保留名：图里有名为 b 的节点（例如偏置）而模板用到 b 时，创建 steps 时抛错，要求改名。原因是两种含义无法从模板里区分。
  • 下标从 0 开始。显示从 1 开始的序号时写 {{t+1}}。
  • 格式为整数时表示小数位数，例如 {{loss:3}}；{{t:token}} 输出 tokens[t]。
  • 标量节点可以省略下标；shape 为 $(1,n)$ 的节点只写一个下标时视为 [0, i]，$(n,1)$ 视为 [i, 0]；label 按整数输出。
  • 公式内的数用 formatNumber(v, { tex: true })，公式外用 U+2212 负号。
  • 不能解析的模板在创建 steps 时抛出带模板原文的错误。模板只能读取节点的值与梯度，不执行任意 JavaScript。

悬停卡片

悬停卡片分两种，内容都由 explain 根据运算定义生成。ui 和 scene3d 只负责显示，以后增加 2D 渲染时卡片可以直接复用。

层名卡片在悬停层名时出现。

  • 前向：标题为节点名；公式为 tex = 前向模板，例如 $\mathbf{z} = \mathbf{h}W^{\top}$；下面依次列出 shape、真实模型（给了 real 时，写作 Qwen3-8B：(1, 151936)）、当前值。当前值超过 8 个元素时只列前 8 个，后面加省略号。
  • 反向：标题为 ∂ℓ/∂节点名；公式是链式法则展开，对节点 $X$ 的每个消费者 $Y$ 写一项（只计结构上通向损失的运算，旁支和损失之后的节点不列，它们的项恒为 0），只有一个消费者时不写求和：
\begin{equation} \frac{\partial\ell}{\partial X} = \sum_{Y} \Big(\frac{\partial Y}{\partial X}\Big)^{\top} \frac{\partial\ell}{\partial Y} \label{eq:chain} \end{equation}

反向卡片的行依次为 shape、真实模型、Jacobian、当前梯度。Jacobian 每个消费者一行，写作 ∂Y/∂X：(...)，括号里是输出 shape 与输入 shape 各自去掉大小为 1 的维度后拼接，例如 $\partial\mathbf{z}/\partial\mathbf{h}$ 写作 (V, d)。作者在节点的 card 选项里给出的字段覆盖自动内容，没给的字段用自动内容。

连线卡片只在反向时悬停连线出现，分三行：这条边的局部导数、上游传来的梯度、两者相乘后沿这条边传回的量。节点有多条出边时，卡片说明各条边的贡献相加并给出合计，例如 $z_i$ 经 $\log p_i$ 与经 LSE 的两条边相加得到 $p_i - \delta_{it}$。

interface EdgeCard {

  local: { tex: string; value: number };

连线模式

每个运算从一个固定的小集合里选一种连线模式，scene3d 根据模式和布局模板决定线怎么画，卡片根据局部导数和公式模板生成文字，两者都不需要知道具体是哪个运算。新运算选定一种模式，就能得到全部讲解内容。

模式运算边
elementwiseadd、sub、mul、div、neg、exp、log、transpose每个输出元素连到每个张量参数的对应元素；广播的输入一对多，例如 LSE 连到每个 $\log p_i$。transpose 按交换后的下标对应。
reducesum、mean、max、logsumexp被归约的一组元素各连到一个输出元素
densesoftmax、log_softmax输出元素连到同一切片（dim 方向）里的全部输入元素
contractmatmul经过乘积格子：$A_{r,k}$ 连到格子 $(r,k,i)$，局部导数 $B_{k,i}$；$B_{k,i}$ 连到同一格子，局部导数 $A_{r,k}$；格子连到输出 $C_{r,i}$，局部导数 1。
selectgather、nll_loss只连被选中的元素；被 ignore_index 忽略的行没有边

乘积格子只存在于 explain，不是计算图的节点，数值为 $A_{r,k}B_{k,i}$。这样计算图与 torch 保持一致，讲解仍然可以画出「一行乘一列再累加」的过程。每条边有稳定的 id：同一个运算、同一位置的边在 label 变化前后 id 相同，select 模式的 id 用输出下标。

所有公式模板只使用 KaTeX 和 MathJax 都支持的命令：\frac、\partial、\mathbf、\top、\operatorname、\mathrm、\sum、\log、\exp、\Big、\left、\right、\cdot、\times、\to、\delta。

视觉原则

3D 只用于内容本身具有空间结构的地方，画面保持克制。

  • 坐标轴刻度固定。拖动滑块时只有柱子变化，坐标不重新缩放，读者可以比较前后两个状态。每个张量前向、反向各有一个固定刻度，默认在挂载时由初始值决定：初始值中的最大绝对值对应 1.6 个单位高度。之后刻度不随数值变化，作者也可以在布局模板的选项里直接指定刻度。柱子高度超过 2.0 个单位时截断，截断处留一道 0.07 个单位厚的缝。
  • 颜色只用一组：橙色（--pos）表示正，蓝色（--neg）表示负，前向数值和反向梯度共用。目标类用墨线框标出，不额外占用颜色。
  • 没有辉光、粒子和自动旋转。动效只有数值变化时柱子高度的过渡：时长 200 毫秒，缓出；prefers-reduced-motion 时直接跳到终值。
  • 未出现的节点只保留空的轮廓：柱子轮廓线的不透明度为 0.2，底板为 0.15，目标列的墨线框为 0.15；已出现的节点正常显示（轮廓线 0.9，底板 0.5），当前步骤的节点高亮。反向时已出现但不在当前步骤的张量，底板边框降到 0.25，让当前步骤的块更醒目。反向时上游梯度恒为零的边画成虚线。
  • 柱子的数值标签只在已出现并且处于当前步骤的张量上显示；总览步骤所有张量都处于当前步骤，数值标签全部显示，仍参与重叠检测。批量时数值标签和标量节点的标签只显示选中样本那一行。同一个张量的数值标签保留相同的小数位数：按这个张量当前绝对值最大的元素，用 formatNumber 的规则决定位数（$|v| \ge 100$ 保留 0 位，$|v| \ge 10$ 保留 1 位，$|v| \ge 1$ 保留 2 位，其余 3 位），这样同一层的数可以直接对齐比较。
  • 只在数值、相机或步骤变化以及过渡进行中时渲染，静止时不重绘。
  • 浏览器不支持 WebGL 时，画布位置显示一行提示，讲解和面板照常可用。

布局模板

张量在场景里的位置由布局模板决定。

模板摆法
stack把几层张量按计算顺序往上叠，高度表示计算的先后。
node放置标量节点，例如 $S$、LSE 和损失。只接受每行最多 1 个元素的节点（形状 ()、(1,)、(B, 1)），其他形状抛错并提示改用 stack。
board矩阵乘专用，按课本的摆法把三个矩阵排在同一块地面上：右侧的矩阵放在后方，左侧的矩阵放在左前方，结果放在右侧矩阵正前方，与它的列对齐。

以 $\mathbf{h}\,(1\times d)\cdot W^{\top}\,(d\times V)=\mathbf{z}\,(1\times V)$ 为例：$h_k$ 连到 $W^{\top}$ 第 $k$ 行的入口，沿这一行经过每个乘积格子；每一列从后往前累加乘积，落到 $z_i$。换成批量时 $\mathbf{h}$ 和 $\mathbf{z}$ 在 $W^{\top}$ 前方排成 $B$ 行，第 0 行在最前，后面的行依次往后，最后一行紧挨 $W^{\top}$，$W^{\top}$ 保持不动。

所有模板都接受位置、间距和缩放参数，例如 board(h, W.T, z, { at: [x, y, z], gap: 0.7 })。默认值不需要调整就能使用，每一项也都可以单独改。board 的 gap 是行距，默认 0.7 个单位；列距为 1.45 个单位；scale 同时缩放行距、列距和各块之间的距离，柱子底面尺寸不变。scales 按节点名指定柱子刻度，覆盖由初始值决定的默认刻度。

board(a, b, out) 的摆法（默认值取自 lm_head 页）：$b$ 为 $(d, V)$，元素 $(k, i)$ 放在 $x = (i - \tfrac{V-1}{2})\cdot 1.45$，$z = 2.9 - 1.3 - (d-1-k)\cdot\mathit{gap}$，第 0 行在最后方；$out$ 的第 $r$ 行放在 $z = 2.9 + 1.4\,(B-1-r)$，第 0 行在最前，最后一行紧挨 $b$，批量行的方向与 stack 一致；列与 $b$ 对齐；$a$ 的第 $r$ 行与 $out$ 同一 $z$，放在左前方 $x = x_0 - 4.3 + 0.95k$。三块各有一块 0.04 厚的浅色底板。$b$ 的行号标签 k=1…d 放在底板左边缘再往左 0.15 处，与各行对齐；$a$ 的列标签 k=1…d 放在地面上、最前一行柱子前方 0.7 处。类别对齐的张量的 token 标签去掉引号，前导空格显示为 ␣。柱子底面：$a$ 0.6×0.6，$b$ 0.58×0.4，$out$ 0.62×0.62。

stack 把节点按顺序往上放。每行元素数大于 1 的张量是「平面张量」，放在上一层上方 level（默认 5.2）处，列与上一层对齐；上一层也是平面张量时再往后（$z$ 减小）移 back（默认 0.7），让两层的标签和柱子在斜视角下沿对角线错开。softmax 页用 level: 3.0，单样本 back: 1.7、批量 back: 2.2，层高较小、后移较大，场景在画布中横向展开。批量时第 0 行放在 at 的 $z$ 处，后面的行依次往后（$z$ 减小）间隔 1.4 排开，样本 1 在最前面，与 board 的批量行方向一致。左侧有一条三个整齐刻度的纵轴，放在最左一列再往左 2.0 处、与底板后边缘同一深度，刻度标签在轴的左侧，这一层还没有出现时不画纵轴；放在后边缘、离板足够远，是为了不与板前方的类别标签（例如「1 · 目标」）相交。类别标签放在板前方 0.7 处；某一列的柱子为负、数值标签挂在柱子下方时，这一列的类别标签在屏幕上移到数值标签正下方，两者不重叠。批量时类别标签不标「· 目标」，各行的目标由墨线框标出。每行只有 1 个元素的节点是「标量节点」：由 reduce 或 dense 模式的运算从平面张量得到的（LSE、$S$）放在两层之间的侧面，$x$ 为列右端加 2.6，$z$ 比源张量靠后 back 的一半（默认 0.35），画成半径 0.55、高 0.3 的扁圆柱，批量时半径为 0.32，各行的圆柱在默认视角下互不重叠；由 select 模式得到的（$y$、nll_loss 的损失）放在源张量目标列正上方 2.6 处（柱子截断高度 2.0 再留 0.6，节点不会压在最高的柱子上），随目标列移动；其余标量继续往上 0.7，一列标量节点保持紧凑，标签由重叠检测挪开。select 节点和它上方的一列标量（例如 $y$、$\log y$ 和损失）把标签放在节点侧面、与节点中心同高，前向与反向相同，不压住上方的节点：标签离节点在屏幕上的轮廓 0.15 个单位（沿默认视角的屏幕水平方向量取，圆柱取半径，方块取它在这个方向上的半宽）；单样本放在右侧，批量放在左侧，因为各行的节点向右后方排开。侧面的 LSE、$S$ 和 node 模板放置的标量节点把标签放在节点上方。由 select 节点经逐元素运算得到、行数相同的标量（例如批量时的 $\log y_b$、$\ell_b$）每行跟随自己那一行的目标列；行数变少的标量（例如对批量取平均的损失）放在列的中间。损失节点画成 1.2×0.5×0.8 的扁方块，其他标量节点画成扁圆柱。形状超过二维的节点不能放进布局。

与 label 的类别维对应的张量（列数等于类别数，并且被 label 经 select 运算使用，或是这种张量的上游同列张量）称为「类别对齐」的张量：它们的底板上画出目标列的墨线框，列标签用 token 名，点击它们的柱子可以更换目标。

一个节点只放置一次。已经被前面的布局模板放置的节点出现在 stack 里时作为起点，不重复放置。例如 [board(h, W.T, z), stack(z, L, logp, loss)] 中，z 由 board 放在地面上，stack 从 z 往上叠放 LSE、$\log\mathbf{p}$ 和损失。

相机

相机采用正交投影，避免透视变形影响对高度的判断。取景根据所有元素与标签的包围盒在相机坐标下的投影自动计算，元素移动或缩放后不需要手动调整相机：几何体的投影四周留 12px，每个标签按它的像素尺寸和锚点计入，外沿离画布边缘也留 12px，在这个约束下取能放下全部内容的最大缩放，内容尽量填满画布。放在节点上方的节点标签按「翻到节点左侧」的位置计入，所以画布右侧不必为它们预留宽度；放在节点侧面的标签按实际位置计入。节点标签的宽度取前向与反向两种文字中较宽的一种，切换步骤时不需要重新取景。挂载、画布尺寸变化、字体加载完成与「复位视角」时重新取景。柱子按取景时的实际高度计入；读者拖动滑块让柱子变高时不重新取景，避免画面随数值跳动，柱子超出画布时按「复位视角」重新取景。读者只能在小范围内旋转和缩放，场景右上角的「复位视角」回到初始状态。下表是默认值；mountScene 的 camera 选项可以覆盖斜视方向（direction）、相对初始方位角的水平旋转范围（azimuth）和极角范围（polar）。softmax 页用它给出自己的数值：方向 $(0.62,\ 0.5,\ 1)$，水平 $-0.75$ 到 $+0.6$ 弧度，极角 $0.55$ 到 $1.5$ 弧度。

标签与交互

层名、数值、刻度、token 等标签用 HTML 覆盖在画布上，按投影位置放置，公式由 KaTeX 渲染。标签投影到屏幕后先处理越界：放在节点上方的节点标签右端超出画布（离右边缘不足 12px）时翻到节点左侧，右端对齐节点中心；左端越界时翻到右侧。放在节点侧面的标签不翻转，取景已为它们留出位置。然后做一次重叠检测：按优先级（块标题 5、节点标签 4、数值 3、类别 2、行号与刻度 1）依次放置；块标题和节点标签可以移动，与已放置的标签相交时按上、下、左、右的顺序以 4px 为步长尝试平移，最多 12 步，取第一个不相交、并且离画布边缘至少 12px 的位置，找不到时退回到画布安全区内离原位最近的位置；其余标签不移动，与已放置的标签相交或越出安全区时隐藏。标签的像素尺寸在文字或样式变化时测量一次并缓存，字体加载完成后重新测量；每帧只做投影和重叠检测。位置只在相机、布局或数值变化时重新计算。

元素之间的连线是竖直切线的三次贝塞尔曲线，切线长度取两端高度差的 0.45 倍、最少 0.5，起点向上、终点向下，不会在端点处回钩。

悬停柱子的提示显示元素名和当前值：前向时元素名后面给出该运算的元素级公式（只有当每个输入恰有一条连到这个元素的边时），反向时列出各条出边传回的量相加。连线卡片只在反向时出现，取屏幕空间距离 6px 以内最近的一条已出现的边。卡片优先放在指针右下 18px，越界时翻到另一侧。

  • 悬停柱子显示数值提示；悬停层名显示层名卡片。
  • 反向时悬停连线显示连线卡片，并加粗这条连线。
  • 点击 logits 或 $\log\mathbf{p}$ 的柱子，把它设为目标类，即更新对应的 label 节点；批量时同时选中这一行的样本。可点击的柱子在提示末尾写明：label 给了 tokens 时为「点击设为目标 token」，只给了 classes 时为「点击设为目标类」。提示里的 token 名与类别标签相同，不加引号，前导空格显示为 ␣。
  • 场景订阅 theme，主题切换时重新读取颜色。

编辑模式

自动取景和标签避让之后，作者仍然需要微调位置。mountScene(el, g, { edit: true }) 打开编辑模式，只在作者写页面时使用。编辑模式在画布右下角显示可以折叠的「编辑布局」面板。面板展开时，自动取景把面板左边缘到画布右边缘的宽度从可用宽度中扣除（最多扣到画布宽度的一半），场景放在面板左侧；面板折叠后取景恢复使用整个画布宽度。面板支持以下操作：

  • 拖动张量块：按住块的柱子、圆柱或底板，在水平面内移动。结果写进放置这个块的模板：board 的三个块一起移动，写成 board 的 at；node 模板写成它的 at；stack 里直接从 at 起放置的第一层写成 stack 的 at，其余各层写成 stack 的 offsets。坐标保留两位小数。
  • 调整间距：面板里每个 board 有 gap、scale 两个数值输入，每个 stack 有 level、back，步长 0.05，输入后场景立即重排。
  • 移动标签：拖动块名标签或标量节点的标签，结果写成 mountScene 的 labels，单位为像素，取整数。
  • 「设为默认视角」：把当前的相机方向（从观察目标指向相机，各分量保留两位小数）写成 camera.direction，视角回到这个方向下的自动取景。缩放不写入配置，取景始终自动计算。
  • 「复制配置」：在面板的文本框里显示 layout、camera、labels 三项的代码，同时尝试写进剪贴板；按钮旁显示「已复制」或「请从文本框复制」，2 秒后淡出（prefers-reduced-motion 时直接消失）。文本框不折行，可以横向滚动。代码是 mountScene 选项对象里的属性，替换页面里原来的这几项即可。节点写成 g.node('节点名')，g 是页面里图的变量名；camera、labels 没有内容时不输出。

每次拖动结束或数值变化后，视角回到默认方向并重新自动取景，所以编辑模式里看到的位置与把配置粘贴回页面后打开时一致。拖动过程中不重新取景，块跟随指针移动。

编辑模式写出的两个选项也可以手写：

  • stack 的 offsets：按节点名把这个 stack 放置的某一层整体平移 $[dx, dy, dz]$，包括柱子、底板、刻度轴和标签；后面以这一层为起点的层跟着平移，前面的层不动。例如 stack(z, L, logp, loss, { offsets: { 'log p': [1, 0, -0.5] } }) 移动 $\log\mathbf{p}$ 和它上方的损失，LSE 不动。
  • mountScene 的 labels：按节点名把块名标签（柱子块）或节点标签（标量节点，批量时每一行）从锚点处的原始位置平移 $[dx, dy]$ 像素，$x$ 向右、$y$ 向下。给出偏移的标签不再左右翻转，也不参与避让移动；其他标签照常避开它。自动取景按偏移后的位置计入这些标签。

位置的最终来源始终是页面里的配置代码。编辑模式不保存任何状态，不使用浏览器存储，所以不存在两份需要同步的配置。只有页面代码里写了 edit: true 时才出现编辑界面，没有快捷键或网址参数可以打开它，看图的人不能进入编辑模式，发布出去的页面布局是固定的。edit 省略或为 false 时不创建任何编辑相关的元素和事件监听。

面板与页面布局

挂载

每个带界面的模块只提供 mount(容器, ...) 形式的入口，只在页面给出的容器里渲染，铺满容器，并在容器尺寸变化时重排。模块不决定页面布局，页面可以把它们放在任何位置。每个 mount 返回带 dispose() 的句柄，用于释放监听和 WebGL 资源。scene3d 的 dispose() 还会主动释放 WebGL 上下文，页面反复挂载和释放场景时不会耗尽浏览器允许的上下文数量。

mountSteps(el: string | HTMLElement, steps: Steps): Mounted
mountPanels(el: string | HTMLElement, g: Graph, items: PanelItem[], options?: { steps?: Steps }): Mounted
interface Mounted { dispose(): void }

mountSteps 画出步骤条（前向、反向两组按钮）、左右按钮和讲解正文；键盘的左右方向键切换步骤。焦点在输入框或步骤条以外的按钮上，或按着 Alt、Ctrl、Meta 时不响应；焦点在步骤条自己的按钮上时照常切换。同一页有多个步骤条时，只有最近一次点击或聚焦落在其中的那个响应方向键，点击步骤条以外的地方不改变这一选择。

步骤按钮的左右内边距为 9px，桌面宽度下 lm_head 页的 11 个按钮在约 860px 宽的步骤卡片里排成一行。步骤卡片宽度不超过 560px 时按钮排成一行横向滚动，右端 24px 渐隐，提示还可以往右滚。讲解正文和面板里的独立公式块超出宽度时在公式块内横向滚动，不截断。

公式怎么渲染

第一版只用 KaTeX，但其他模块不直接调用 KaTeX，统一通过 formula 的接口渲染，KaTeX 是接口的一个适配器。接口按异步渲染设计：调用方先拿到一个占位元素，适配器渲染完成后填充。KaTeX 本身是同步的；以后加入渲染为异步的 MathJax 时，只需要新写一个适配器。

  • render 立即返回占位元素 <span class="vf-tex">。
  • renderText 把正文中的 $...$、$$...$$ 换成 render 的结果，其余部分按 HTML 插入。
  • KaTeX 适配器按（公式，是否 display）缓存渲染结果。渲染出错时不抛出，占位元素显示原始 TeX 并加 vf-tex-error 类。
  • KaTeX 的 CSS 由 formula 入口引入。
  • 公式模板只使用 KaTeX 和 MathJax 都支持的写法，命令列表见「连线模式」一节末尾。

打包与引用

库用 Vite 的库模式打包，输出 ES module 和类型声明。npm run build 构建两份产物，分别给两种引用方式使用，入口相同，入口之间共用的代码都拆成公共 chunk：

产物给谁用第三方库字体有限差分检查的默认值
dist/module/*.js用 npm 和构建工具（Vite、webpack 等）的项目，exports 的 import 指向它three.js、Solid、KaTeX、@fontsource 保留为 import，由构建工具解析import @fontsource 与 KaTeX 的 CSS 文件，字体由构建工具输出开发模式打开，生产构建关闭
dist/*.js不用构建工具的静态站，通过 jsDelivr 引用或复制 dist/打包进产物输出到 dist/fonts/，代码按自身地址请求关闭

两份产物的类型声明都是 dist/types/，exports 的 types 指向它，公开的类型声明不引用 three.js、Solid、KaTeX。

构建工具产物

构建工具产物不打包第三方库，所以 three.js、Solid、KaTeX 和三个 @fontsource 字体包列在 package.json 的 dependencies，安装 vizflow 时一起安装。页面自己也引用 three.js 时，构建工具把两边的 import 解析到同一份 three.js，页面里只有一个实例，不会出现 three.js 的「Multiple instances」警告；打包进产物时页面会有两份。

字体通过 import CSS 文件交付：theme 引入 @fontsource 的 CSS，formula 的 KaTeX 适配引入 katex/dist/katex.min.css，CSS 里的 url() 由构建工具处理，开发服务器和生产构建的字体都能正常加载。不用按 import.meta.url 计算字体地址的原因是：Vite 开发服务器会把依赖预打包到缓存目录，模块地址随之改变，按模块地址算出的字体路径就不存在了。

检查的默认值写成 process.env.NODE_ENV !== 'production'，因为 Vite 和 webpack 都会替换这个表达式。库模式构建时 Vite 保留 process.env.*，不在库自己的构建里替换，留给页面的构建工具。

源码里与产物有关的三个模块各有一个 .module.ts 版本：字体（theme/fonts）、KaTeX 样式（formula/katex-style）和检查默认值（autograd/check-default）。构建工具产物用 .module.ts 版本，直接引用的产物、开发服务器和测试用原版本。

直接引用的产物

静态站可以直接 import 这份产物，不需要 import map。three.js、Solid、KaTeX 打包进产物，three.js 只在引用 scene3d 时加载，KaTeX 只在引用 formula（包括间接引用）时加载。

字体文件输出到 dist/fonts/，包括 KaTeX 的字体和 @fontsource 的 Source Serif 4、Geist、Geist Mono，全部是 woff2。theme 与 formula 的代码以自身所在文件的地址为基准请求 fonts/ 下的文件，所以入口文件和 chunk 都放在 dist/ 根目录，复制产物时 fonts/ 要和它们保持在同一目录。

版本号遵循 semver，静态站固定引用某个版本。产物可以复制进静态站，也可以通过 jsDelivr 按版本号和文件路径引用。jsDelivr 按文件路径取文件，不经过 exports，所以 exports 指向构建工具产物不影响这种写法：

import { graph } from 'https://cdn.jsdelivr.net/npm/@yhnocoder/vizflow@0.1.0/dist/core.js';

sideEffects 与测试

注入样式的模块（theme 及其字体模块、ui、formula 的 KaTeX 样式模块、scene3d）和两份产物的 .js 文件在 sideEffects 中列出，否则构建会把只为注入样式而写的 import 删掉。

读取构建产物的测试确认：直接引用的产物里，core、explain、steps 入口及它们静态导入的 chunk 里不出现 three.js、Solid 和 KaTeX，ui 入口里不出现 three.js；构建工具产物里任何入口都不打包这三个库，它们只以 import 出现，CSS 引用的每个字体文件都存在；每个入口都有对应的 .d.ts。仓库里的 examples/vite-project/ 是一个独立的 Vite + TypeScript 项目，测试把它安装、构建，再用 vite preview 和 vite 开发服务器各打开一次，确认场景画出、没有控制台错误、字体请求全部返回 200、只有一个 three.js 实例，并且检查在开发服务器下打开、在生产构建里关闭。

仓库里的写作说明 docs/guide.md 写 API 用法、两个完整示例页面的代码和常见注意事项。作者和 Claude 在编写新页面之前先读它，生成的代码就基于同一套 API。
